# 스토리 넛지 상세 기획 — "카톡 한 통 · 20초 녹음 · 홈페이지가 자란다" (v1, 2026-09-04)

> 작성: 기술참모(코워크). 상태: **제안 — 회장님 수락 전까지 실행 없음.** 저장소에 넣지 않음.
> 회장님 원안: 회사마다 `onstori.com/abc/story` 페이지 하나 + 회사 명의 카톡에서 예약 메시지로 주 1회 "20초만 녹음해주세요" + 답장 "원치않음"이면 중단 + 나중에 자동화.
> 이 문서는 그 원안을 사실 확인으로 검증하고, 바꿔야 할 곳을 바꾸고, 페이지·문구·자동화 단계까지 실행 가능한 수준으로 갈아 놓은 것이다.

## 0. 결론 먼저 (5줄)

1. **사업성 있다.** 온스토리가 홈온과 다른 이유가 "스토리가 쌓이는 홈페이지"인데, 사장님이 스스로 올리는 비율은 어느 서비스든 낮다. 넛지(찔러주기)는 그 비율을 올리는 유일한 장치이고, 비용은 고객당 월 0~100원이다.
2. **수작업으로 시작하는 게 맞다.** 옛 계획의 헌법("유료 고객 5명 전 자동화 금지")과 정확히 맞는다. 코드로 만드는 건 **페이지 하나(`/abc/story`)뿐**이고, 발송은 회장님 손으로 한다.
3. **원안에서 세 군데는 바꿔야 한다.** ①카톡 예약 메시지에는 **반복 기능이 없다**(매주 새로 걸어야 함) ②**안드로이드 카톡 안 브라우저에서는 마이크가 안 된다**(2026-08 현재도 미해결) ③"원치않음" 답장 처리는 사람이 해야 하므로 명단 관리 규칙이 필요하다. 각각 해법이 있다(3장·5장).
4. **자동화는 "카톡 개인계정을 프로그램이 대신 보내는 방식"으로 가면 안 된다.** 카카오 운영정책 위반으로 계정 정지 위험. 자동화의 정도(正道)는 문자(솔라피 대량 예약) → 알림톡 API + 크론이다. 헤르메스·오픈클로 같은 에이전트는 "회장님 대신 명단·문구·엑셀 만드는 일"에 쓰면 좋고, "카톡 대신 눌러주는 일"에 쓰면 위험하다.
5. **핵심 지표는 응답률이다.** 현재 고객 2곳 + 지인 5곳으로 4주 실험 → 4주 안에 1회 이상 올린 사장님 비율 **40% 이상**이면 다음 단계(문자 대량 예약 + 컨시어지) 진행, 미만이면 문구·시각·주기부터 다시.

## 2. 사업성 — 왜 이걸 하는가, 얼마가 드는가

### 2-1. 이 기능이 돈이 되는 경로

```
넛지 → 사장님이 20초 말함 → 스토리 1편 게시 → (a) 홈페이지가 "살아있음" → 손님 신뢰 ↑ → 문의 ↑
                                             → (b) /abc/story/{id} 페이지 1장 추가 → 네이버·구글 롱테일 검색 유입 ↑
                                             → (c) 사장님이 "내 홈페이지에 뭔가 쌓인다"를 매주 체감 → 해지 ↓
```

- 홈온은 단일 페이지라 (b)가 구조적으로 불가능하다. 온스토리만 할 수 있는 무기다.
- (c)가 제일 크다. 구독형 사업의 이익은 해지율이 정한다. 월 해지율 5%→3%면 고객 생애가치가 1.7배가 된다(1/0.05=20개월 → 1/0.03=33개월).

### 2-2. 비용 (고객 1곳·월 기준)

| 항목 | 카톡 개인 1:1 | 문자(솔라피) | 카카오 채널 | 알림톡(자동화 후) |
|---|---|---|---|---|
| 발송 4회 | 0원 | 80원(SMS 20원) / LMS면 200원 | 60원 | 32원 |
| AI 다듬기 4회(글) | ≈5원 | ≈5원 | ≈5원 | ≈5원 |
| 음성 20초 듣기 4회 | ≈5원 | ≈5원 | ≈5원 | ≈5원 |
| 합계 | **≈10원** | **≈90~210원** | **≈70원** | **≈42원** |

월 49,000원(또는 12,900원) 요금 대비 0.02~0.4%. **돈은 변수가 아니다.** 변수는 회장님 시간과 사장님 응답률 둘뿐이다.

### 2-3. 회장님 시간 (수작업 단계)

| 고객 수 | 카톡 개인 예약(월 4개/곳) | 문자 대량 예약(엑셀 1장/주) | "원치않음"·답장 처리 |
|---|---|---|---|
| 5곳 | 월 10분 | — | 주 5분 |
| 20곳 | 월 40분 | 주 5분 | 주 10분 |
| 50곳 | 월 100분 (한계) | 주 5분 | 주 20분 → 컨시어지 페이지 필요 |
| 100곳+ | 불가 | 주 5분 | 자동화(알림톡+크론) |

## 3. 원안 대비 바꾸는 것 3가지 (그리고 왜)

### ① "매주 예약"은 없다 → 4주치를 한 번에 건다 + 20곳 넘으면 문자로
카톡 개인 예약 메시지는 1회성이다. 월초에 고객 1곳당 4개(화요일 4번)를 걸면 된다. 5~10곳까지는 이게 제일 따뜻하고 공짜다. 20곳이 넘으면 **솔라피 대량 예약 발송**(엑셀 업로드 · 이름·링크 변수 치환 · 발신번호는 회사폰 → 답장이 회사폰으로 옴)으로 옮긴다. 주 1회 5분이고, 링크가 기본 브라우저로 열려 녹음 문제도 없다.

### ② 카톡 링크 = 안드로이드 녹음 불가 → 페이지가 알아서 피한다
페이지가 카톡 인앱 브라우저(UA에 `KAKAOTALK`)를 감지하면, 안드로이드에선 녹음 버튼 자리에 **"🎤 녹음은 Chrome에서 열어야 돼요 → [Chrome으로 열기]"**(intent 링크, 1탭)를 보여주고, 그 아래 **"글로 쓸게요"·"사진만 올릴게요"**를 동등한 크기로 둔다. iOS 카톡은 그냥 된다. 문자로 온 사장님은 처음부터 문제 없다.
더 근본적인 우회 하나: **사장님이 카톡 채팅방에 음성메시지로 답해도 된다**(카톡 기본 기능). 회장님이 그 음성을 어드민 "대신 올리기"에 넣으면 AI가 초안을 만들고 사장님 승인 링크를 보낸다 — 이게 옛 계획의 "컨시어지 MVP"다. 5~20곳 구간에서 응답률을 가장 높이는 방법이고, 자동화 전에 어떤 말투·길이로 사장님이 말하는지 데이터가 쌓인다.

### ③ "원치않음"은 해방이 아니라 신호다 → 명단 + 월 1회 가벼운 접촉
"원치않음"을 보낸 사장님은 넛지를 끊는 게 맞다(법적으로도 즉시 반영해야 한다). 다만 그 사장님은 **해지 예비군**이다. 넛지 명단에서 빼되, 월 1회 "이번 달 홈페이지 방문 N명"(통계, P7) 같은 *받는 이득이 있는* 메시지 한 통은 남긴다. 명단은 구글 시트 한 장(상호·번호·링크·상태(정상/원치않음/휴면)·마지막 게시일·응답 횟수)으로 시작한다 — 이 시트가 나중에 `/admin/stories` 화면의 원형이 된다.

## 4. 메시지 문구 연구 — "귀찮지 않게"의 조건

### 4-1. 원안 문구의 진단
> "사장님 잘지내시죠? 항상 살아있는 이야기가 있는 홈페이지 유지를 위해서 주1회는 글을 올려주시는 것이 좋습니다 ^^ onstori.com/abc/story 이곳에 들어오셔서, 20초만 녹음해주세요. 사장님의 이야기만 하고 거짓말 안하고, 펙트만 정리 요약해서 일잘하는 비서 똑똑한 인공지능이 글 작성을 도와드립니다"

좋은 점: 20초라는 구체적 시간, 링크, "거짓말 안 하고 팩트만"이라는 약속(표시광고법 방어이자 신뢰). 고칠 점: ①"~하는 것이 좋습니다"는 **숙제를 내는 말투**다. 사장님은 숙제를 싫어한다. ②이유("살아있는 홈페이지 유지")가 온스토리의 이유지 사장님의 이유가 아니다. ③길다(LMS 요금·읽다 이탈). ④보낸 사람이 누군지 첫 줄에 없다.

### 4-2. 귀찮지 않은 넛지의 5원칙
1. **보낸 사람이 사람이다.** "온스토리 권병철입니다" — 시스템 문자가 아니라 아는 사람. 응답률의 절반은 여기서 난다.
2. **한 가지만 부탁한다.** "이번 주 한 일 하나만". 사진·글·녹음 중 아무거나.
3. **비용을 먼저 말한다.** "20초" / "사진 한 장".
4. **사장님의 이득 한 줄.** "이야기가 쌓일수록 네이버에서 더 잘 잡혀요" (사실) — 이득이 실제 숫자가 되면(P7: "지난주 방문 23명") 응답률이 뛴다.
5. **안 해도 된다는 걸 말한다.** 죄책감을 주지 않는다. "바쁘시면 다음 주에요." + 중단 방법 명시.

### 4-3. 문구 3안 (독자 제작, 홈온 문구 아님)

**A. 개인 카톡 1:1 (5~10곳, 회장님 명의)** — 90자
```
사장님, 온스토리 권병철입니다 🙂
이번 주 하신 일 하나만 남겨주세요 — 20초 녹음이면 충분해요.
👉 onstori.com/abc/story
말씀하신 그대로만 정리해서 홈페이지에 올려드려요. 지어내거나 부풀리지 않습니다.
바쁘시면 다음 주에 하셔도 돼요. 안 받고 싶으시면 "원치않음"이라고 답장 주세요.
```

**B. 문자 대량 예약 (20곳+, 변수 치환)** — SMS 90바이트 제한이라 두 줄
```
[온스토리] #{상호} 사장님, 이번 주 하신 일 하나 20초 녹음으로 남겨주세요 → onstori.com/#{slug}/story (중단: 원치않음 답장)
```

**C. 응답 다음 주 (강화 문구 — 올린 사장님에게만)**
```
사장님, 지난주 올리신 "성북구 욕실 타일 교체" 이야기가 홈페이지에 잘 올라갔어요 👍 (보기: onstori.com/abc/story)
이번 주도 하나 남겨주세요 — 20초면 됩니다.
```
C가 중요하다. **한 번 올린 사장님은 다음 주 응답률이 3배**쯤 된다(습관 형성). 올린 사람과 안 올린 사람의 문구를 나누는 것이 자동화 1순위 기능이다.

### 4-4. 시각·주기·업종
- 시각 안: **화요일 08:30**(현장 나가기 전, 지난주 기억이 남아 있음) 또는 **목요일 19:30**(퇴근 후, 오늘 찍은 사진이 폰에 있음). 5곳씩 A/B로 2주 돌려보고 정한다.
- 주기: 시공·카페는 주 1회. **3회 연속 무응답 → 격주 → 다시 3회 → 월 1회**, 응답하면 주 1회 복귀. 수작업 단계에선 구글 시트의 "응답 횟수" 열을 보고 회장님이 판단.
- 업종 라벨: 시공 "이번 주 현장 이야기", 카페·식당 "이번 주 가게 소식". 문구의 {라벨}만 바꾼다.

### 4-5. 법·정책 메모(참고, 법률 자문 아님)
- 서비스 이용 중인 고객에게 보내는 **이용 안내**는 광고성 정보(정보통신망법 50조)와 성격이 다르지만, 안전하게 ①가입 시 "스토리 알림 받기" 동의 항목 ②모든 메시지에 중단 방법 ③"원치않음" 즉시 반영 ④야간(21~08시) 발송 없음을 지킨다.
- 개인 카톡 계정으로 다수에게 같은 메시지를 보내는 건 정책상 "스팸 신고" 위험이 있다. 5~10곳까지만, 그것도 **이미 아는 사이(가입 시 대화한 사장님)**에게만.
- 녹음 파일은 사장님의 개인정보다. 첫 녹음 전 한 번 "녹음은 글 작성에만 쓰고 90일 후 지웁니다" 동의 체크, 개인정보처리방침에 항목 추가(P9 법무).

## 5. `onstori.com/abc/story` 페이지 기획

### 5-1. 한 페이지, 두 얼굴
같은 주소인데 **보는 사람에 따라 다르게** 보인다.

| 손님(로그인 없음) | 사장님(로그인 또는 작성 키) |
|---|---|
| 상호 · "이야기 N편 · 첫 이야기 2026.3" · 스토리 목록(날짜·제목·두 줄·사진) · 각 편은 `/abc/story/{id}` 개별 페이지(검색용) · 맨 아래 "견적 문의" 버튼(리드) | 맨 위에 **"이번 주 이야기 남기기" 카드**(아래 5-2) + 그 아래 손님과 같은 목록(내 눈으로 확인) + 각 편에 "숨기기" |

- 홈페이지 본문의 스토리 섹션은 최신 3편 + "전체 보기 → /abc/story". 사이트맵에 `/abc/story`·`/abc/story/{id}` 추가(체험 사이트는 제외 — 기존 규칙).

### 5-2. 사장님 카드 — 3탭 완결
```
① 입력   [🎤 20초 녹음]  큰 원형 버튼. 누르면 링이 20초 동안 차오름. 다시 누르면 멈춤(최대 60초).
         "글로 쓸게요"   같은 카드 안 텍스트 상자(두 줄이면 충분).
         "사진 추가"      최대 4장, 폰에서 바로. 사진만 보내도 됨.
         (안드로이드 카톡 인앱이면 🎤 자리에 "Chrome으로 열기")
② 확인   AI가 3~5초 뒤 초안: 제목 1줄 + 본문 2~4문장. 그 아래 회색으로 "사장님 말씀(원문)".
         [✅ 이대로 올리기]  [✏️ 조금 고칠게요]  [🗑 안 올릴게요]
③ 완료   "올라갔어요 🎉 3주 연속!" + [홈페이지에서 보기] [카톡으로 손님에게 알리기(공유)]
```
- 승인 없이 자동 게시하는 옵션은 **없다.** 사장님 이름으로 나가는 글이므로 승인 한 번은 안전장치다. 대신 ✅ 버튼을 화면에서 제일 크게.
- 글자 크기 18px 이상, 버튼 높이 56px 이상, 한 화면에 주요 동작 하나. 50~60대 사장님 폰 기준.
- 사장님 입력이 너무 짧으면(10자 미만·2초 미만) AI를 부르지 않고 "조금만 더 말씀해 주세요"로 되돌린다.

### 5-3. 사장님 인증 — 로그인 없이 여는 법
문자·카톡 링크를 눌렀는데 로그인 화면이 뜨면 거기서 끝난다. 두 가지 중 택일(참모 권고: **작성 키**):
- **작성 키(권고)**: 링크가 `onstori.com/abc/story?k=8자리`(회사별 비밀 키, 에디터에서 재발급 가능). 키가 맞으면 그 폰 브라우저에 30일 쿠키를 심어 이후엔 `onstori.com/abc/story`만 쳐도 사장님 모드. 키가 새면 남이 글을 올릴 수 있으나 ①사장님이 승인 화면에서 바로 보이고 ②"숨기기"로 즉시 내리고 ③키 재발급으로 끝. 하루 10편 제한.
- 카카오 로그인: 이미 있는 P4 로그인을 쓰되, 카톡 인앱 브라우저와 Chrome은 **쿠키가 따로**라 두 번 로그인하게 된다. 작성 키보다 이탈이 크다.

### 5-4. AI 다듬기 규칙 (표시광고법 방어)
- 원칙 한 줄: **사장님이 말한 것만, 순서만 정리, 아무것도 보태지 않는다.** 숫자·기간·경력·수상·후기·"최고/완벽/숙련" 금지. 지역은 동(洞)까지만.
- 원문(녹음 전사문)과 AI 결과를 **둘 다 저장**한다. "AI가 뭘 보탰나"를 언제든 대조할 수 있어야 한다.
- 겹층 프롬프트: 공통 규칙 → 업종(시공: 어디·무슨 작업·어떤 상태를 어떻게) → 상호·말투 → 이번 주 원문. 옛 음성 데모의 구조 그대로.

### 5-5. 홈페이지 연동 시 걸리는 문제와 답

| 문제 | 답 |
|---|---|
| 새 글이 홈페이지에 언제 뜨나 | `/abc`는 60초 캐시(ISR). 게시 API가 `revalidatePath("/abc")`·`("/abc/story")` 호출 → 즉시 |
| 녹음 파일은 어디에 | R2 **비공개** 버킷 `voice/{siteId}/{uuid}.m4a`, 90일 후 삭제. 공개 URL 없음 |
| 음성→글 | Gemini 3.5 flash에 음성 파일 그대로 입력(전사+초안 한 번에). 사투리·소음이면 전사문을 사장님이 고칠 수 있게 원문 표시 |
| 안드로이드 카톡 인앱 | 5-2의 "Chrome으로 열기" + 글/사진 대안. 문자 링크면 문제 없음 |
| iOS 녹음 형식 | `audio/mp4`(AAC). 안드로이드 Chrome은 `audio/webm`. 서버는 둘 다 받음 |
| 스토리 섹션 zod 스키마 | **변경 없음.** 페이지·API·테이블 2개(`story_drafts`, 넛지 명단은 시트→나중에 테이블) 추가만 |
| 체험(trial) 사이트 | noindex 유지. 사장님 모드는 동작(체험 중에 "쌓이는 맛"을 봐야 결제한다) |
| 남이 링크 열면 | 손님 화면만. 사장님 카드는 키/쿠키 있을 때만 |
| 스팸·남용 | 사이트당 하루 10편, 사진 4장·각 10MB, 녹음 60초 상한 |

## 6. 자동화 로드맵 — "회장님 손 → 프로그램 손"

| 단계 | 고객 수 | 발송 | 접수 | 코드 | 회장님 시간 |
|---|---|---|---|---|---|
| **A. 지금** | 0~10 | 회장님 개인 카톡 1:1, 월초 4주치 예약 | `/abc/story` 셀프 + 카톡 음성 답장은 회장님이 대신 올림(컨시어지) | 페이지 1개(`/[slug]/story` + 녹음/초안/게시 API) | 월 20분 + 주 10분 |
| **B. 10~50** | 10~50 | 솔라피 대량 예약(엑셀, 변수 치환, 화 08:30) | 셀프 + 컨시어지 | + 어드민 "대신 올리기"(음성 파일 넣고 승인 링크 발송) 1페이지 + 구글 시트→`story_nudges` 테이블 | 주 15분 |
| **C. 50+** | 50+ | 크론이 매주 자동 발송(알림톡 32원 / 문자 폴백), 응답자·무응답자 문구 자동 분기, 주기 자동 완화 | 셀프 | `docs/specs/story-engine.md`(제안본)의 S1 그대로 | 주 5분(보드만 봄) |

- **B→C 전환 조건**: 4주 응답률 40% 이상 **그리고** 회장님 주당 발송·응답 처리 시간이 30분을 넘을 때.
- 헤르메스·오픈클로 등 에이전트의 자리: A·B 단계에서 **"이번 주 발송 엑셀 만들기·시트 갱신·응답 요약"**을 시키면 좋다. 카톡 앱을 대신 조작하게 하면 안 된다(정책 위반·계정 정지, 그리고 그 순간 사장님 눈에는 스팸이 된다).
- 카카오 채널은 B 단계 선택지로만 둔다(친구 추가 장벽·공용 링크 필요·15원). 문자가 단순하고 링크가 바로 열린다.

## 7. 4주 실험 설계 (A 단계에서 검증할 것)

- 대상: 현재 고객 2곳(goodmoksu·whitedobae) + 지인 사장님 5곳(무료 체험 생성).
- 발송: 화 08:30 4곳 / 목 19:30 3곳(문구 A). 응답한 다음 주엔 문구 C.
- 기록(구글 시트): 발송일·열람(페이지 방문, `events` 'story_view'는 손님용이니 사장님 모드 진입은 별도 로그)·게시 여부·입력 방식(녹음/글/사진/카톡음성)·"원치않음".
- 판정: **4주 내 1회 이상 게시 ≥40%** → B 진행. 녹음 vs 글 비율로 S2(음성) 우선순위 결정. "원치않음" ≥30%면 문구·주기 재설계.

## 9. 회장님 결정 사항

1. A 단계 발송 채널: 개인 카톡(권고, 10곳까지) vs 처음부터 문자
2. 사장님 인증: 작성 키(권고) vs 카카오 로그인
3. 발송 시각 A/B: 화 08:30 vs 목 19:30
4. 문구 A안 확정 여부(4-3), 서명 "온스토리 권병철" 사용 여부
5. 컨시어지(카톡 음성 답장을 회장님이 대신 올림) 허용 여부 — 응답률은 오르지만 회장님 손이 간다
6. 시점: 위젯 뒤·R2-2 앞(권고) vs P5 뒤
