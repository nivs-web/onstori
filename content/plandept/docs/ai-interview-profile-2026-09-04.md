# 3분 AI 인터뷰 → 가게 두뇌(사이트 프로필) → 전 기능 연쇄

작성: 기술참모 · 2026-09-04 (밤) · 회장님 아이디어 검토
연결 문서: `global-ai-builder-benchmark-2026-09-04.md`, `autopost-feasibility-2026-09-04.md`

---

## 0. 결론 세 줄

1. **회장님 아이디어는 맞습니다. 다만 이유가 다릅니다.** "3분 대화로 홈페이지 완성"은 이미 시장에 흔합니다(Hocoos 8질문 3분, 재밋 한국, Wix 챗, Durable 3질문 30초). **속도로는 못 이깁니다.** 우리가 가져갈 것은 대화 자체가 아니라 **대화에서 나오는 정보**입니다.
2. **지금 온스토리는 가게에 대해 두 문장만 알고, 그마저도 버립니다.** `/new` 에서 받은 "상호명 + 하는 일 한 줄"로 사이트를 만든 뒤, 그 맥락은 어디에도 저장되지 않습니다. 그래서 나중에 스토리·인스타 캡션·블로그 초안·위젯 문구를 만들 때 AI가 **매번 백지에서 시작**합니다. 이게 "AI 티 난다"의 진짜 원인입니다.
3. **그러니 3분 인터뷰의 결과물은 홈페이지가 아니라 '가게 두뇌(사이트 프로필)'여야 합니다.** 홈페이지는 그 두뇌의 첫 번째 출력일 뿐이고, 같은 두뇌가 스토리·SNS·블로그·위젯·FAQ·AI 상담원까지 8군데를 먹여 살립니다. **그리고 이 두뇌가 dup-guard(중복 방지)의 핵심 부품이기도 합니다** — 가게마다 두뇌가 다르면 문장이 자동으로 갈라집니다.

## 1. 지금 온스토리는 이렇게 하고 있습니다 (저장소 확인, 2026-09-04)

`app/new/page.tsx` — **대화가 아니라 폼입니다. 필수 4개 + 선택 3개.**

| 항목 | 필수 | 쓰임 |
|---|---|---|
| 상호명 | O | 사이트 제목 |
| 하는 일 한 줄 | O | **업종 분류 + 카피 생성의 거의 유일한 입력** |
| 전화번호 | O | 문의 버튼 |
| 홈페이지 주소(slug) | O | URL |
| 분위기 4택 | — | 색 팔레트 |
| 주소 | 선택 | 오시는 길 |
| 시작한 이유 | 선택 | 첫 스토리 |

`lib/generate.ts` — 분류(사전 매칭 → 실패 시 LLM) → 카피 1회 생성 → 코드가 SiteDoc 조립. 사실 날조 금지 규칙이 프롬프트에 잘 박혀 있습니다("오랜 노하우로", "숙련된 전문가가" 같은 표현까지 금지).

**문제는 품질이 아니라 정보량입니다.** "주거 인테리어 리모델링을 해요" 한 줄로 만든 카피는 옆 가게 카피와 구별이 안 됩니다. 그리고 **생성이 끝나면 그 한 줄조차 프로필로 남지 않습니다**(`sites.inferred` 에는 분류 결과와 모델명만 저장).

> **즉 우리는 이미 폼이 충분히 짧습니다. 대화로 바꿔서 얻을 것은 "더 짧게"가 아니라 "더 깊게"입니다.**

## 2. 남들은 어떻게 하고 있나 (실측 조사)

| 서비스 | 방식 | 질문 수 | 시간 |
|---|---|---|---|
| **Durable** | 폼 | **3개** (업종·지역·사업명) | 30초 |
| **Butternut** | 폼 | 5개 | **20초** |
| **Hostinger** | 폼 | 3개 (사실상 1개) | 수초 |
| **Hocoos** | 폼 | **8개** — "Answer 8 Questions" 가 대표 카피 | 5분 |
| **Squarespace Blueprint** | 5단계 위저드 (제목·브랜드성격 7택 → 섹션 9택 → 페이지 6택 → 색 → 폰트) | 5단계 | 10분 미만 |
| **Wix AI Site Builder** | **진짜 챗** — 적응형 4~5문항, 답에 따라 다음 질문이 바뀜, **마지막에 요약해 보여주고 확인** | 4~5 | 수분 |
| **Wegic** | **자유 대화** — 고정 질문 없음, 음성 입력 지원 | 무제한 | 60초 초안 |
| **GoDaddy Airo** | 프롬프트 한 줄 → 채팅으로 다듬기 | 0 | — |
| **알리바바 万小智** | **다중턴 대화 → 5단계 추론 → 요구사항 문서(PRD) 출력 → "확인 후에 구축"** | 비공개 | 1분 방안 / 5분 구축 |
| **재밋 (한국)** | 대화형, "텍스트 한 줄로 3분" | 1 | 3분 |

### 여기서 나오는 판단 셋

1. **"3분·8질문"은 이미 점유된 카피입니다**(Hocoos). 한국에선 **재밋이 "3분 AI 웹사이트 빌더"로 선점** 중입니다. 같은 문구로 싸우면 집니다.
2. **초안 속도 경쟁은 무의미합니다.** GoDaddy Airo로 카페 사이트를 실제로 **완성**하기까지 한 리뷰어는 **프롬프트 33개, 4시간 45분**을 썼습니다. 20초 초안과 완성 사이의 간극이 진짜 문제입니다.
3. **가장 방어 가능한 패턴은 万小智입니다** — "'블라인드박스식 생성'과 결별", 즉 **먼저 이해한 내용을 문서로 보여주고 확인받은 뒤에 짓는다**. 이건 속도가 아니라 신뢰를 파는 방식이고, 우리가 그대로 가져올 수 있습니다.

## 3. 대화형이 폼보다 나은가 — 숫자

| 지표 | 폼 | 대화형 | 출처 |
|---|---|---|---|
| 폼 완료율 | 21.5% | **47.3%** | Typeform 2024 (260만 폼 분석) |
| **질문당 이탈률** | 18% | **3%** | SurveySparrow 2025 |
| **주관식 답변 길이** | 1배 | **2.5배 — AI가 되물으면 5배** | 〃 |
| 답변 품질 최상위 비율 | 13% | **65%** | 〃 |
| 멀티스텝 vs 한 화면 폼 | — | **완료율 +25.4%** | Formstack (65만+ 제출) |

관련 벤치마크: 온보딩이 **3~5단계면 완료율 60~80%**, 길거나 조기 페이월이 있으면 40% 미만. HubSpot은 필드 4개→3개로 줄여 전환 +50%.

> **우리에게 결정적인 줄은 "답변 길이 2.5배, 되물으면 5배"입니다.** 우리는 입력 품질이 곧 결과 품질인 사업입니다. 이건 UX 이득이 아니라 **제품 품질 이득**입니다.

## 4. 제안 — 3분 인터뷰의 결과물은 "가게 두뇌"

### 4-1. 흐름

```
[1] 필수 4개는 지금처럼 (상호·전화·주소·slug)        ← 30초, 폼 유지
       ↓
[2] AI 인터뷰 6문항 — 한 번에 하나씩, 말로 답해도 됨   ← 2분
       ↓  (AI가 답을 보고 2~3번만 되묻는다)
[3] "가게 카드" 확인 화면 — 이렇게 이해했습니다        ← 30초  ★万小智 패턴
       ↓  고칠 곳 탭해서 수정
[4] 홈페이지 생성 + 프로필 저장
```

### 4-2. 인터뷰 6문항 (한 화면에 하나씩)

| # | 질문 | 이 답이 나중에 어디 쓰이나 |
|---|---|---|
| 1 | **무슨 일을 하세요?** (지금의 '하는 일 한 줄') | 업종 분류·히어로·소개 |
| 2 | **주로 어떤 손님이 오세요?** | 카피 톤·타깃·FAQ·GEO |
| 3 | **다른 곳과 뭐가 다르다고 생각하세요?** | 히어로 문구·차별점 섹션·인스타 캡션 |
| 4 | **손님들이 자주 물어보는 게 뭐예요? 세 개만** | **FAQ 자동 생성 → AI 검색 인용 → 사이트 AI 상담원** |
| 5 | **안 하시는 일도 알려주세요** | ★ **AI 날조 방지 가드레일** — "이건 안 합니다"를 알아야 AI가 없는 서비스를 지어내지 않음 |
| 6 | **이 일 시작한 계기가 있으세요?** | 첫 스토리 + 브랜드 서사 |

**되묻기는 2번까지만.** 답이 너무 짧을 때만("한 문장만 더 들려주세요"), 한 턴에 질문 하나씩.

### 4-3. 이 대화에서 몰래 챙기는 것 — 말투

사장님이 실제로 쓴 문장을 그대로 저장합니다. 어미("~해요/~합니다"), 자주 쓰는 단어, 문장 길이. **이후 모든 AI 글이 이 말투를 흉내냅니다.** 이게 "AI 티" 제거의 핵심이고, 조사한 어떤 빌더도 안 하는 부분입니다.

### 4-4. 저장 구조 (schema.ts 무변경 — `sites.inferred` 안에 넣음)

```
sites.inferred.profile = {
  what, who, different, faqs[3], notDoing[], why,   // 6문항 답
  voice: { 어미, 자주쓰는말[], 평균문장길이, 원문샘플[] },
  banned: [],        // 쓰면 안 되는 표현 (사장님이 싫다고 한 말)
  updatedAt
}
```

> **⚠ `lib/schema.ts` 는 건드리지 않습니다.** 프로필은 사이트 문서(SiteDoc)가 아니라 사이트 메타(`sites.inferred`)에 들어가므로 **스키마 변경 없음 = Opus·ultracode 불필요**. 이건 중요한 설계 선택입니다.

## 5. 이 두뇌가 먹여 살리는 곳 8군데 — "맥락 기능"의 실체

회장님이 물으신 "홈페이지의 맥락 기능"이 바로 이겁니다.

| # | 기능 | 프로필이 없으면 | 프로필이 있으면 |
|---|---|---|---|
| 1 | **홈페이지 생성** | 두 문장으로 만든 평범한 카피 | 차별점·손님층이 들어간 카피 |
| 2 | **스토리 AI 다듬기** | 매번 백지, AI 말투 | 사장님 말투로 |
| 3 | **인스타·쓰레드 캡션** | 일반적인 해시태그 | 손님층·차별점 반영 |
| 4 | **네이버 블로그 초안** | **가게마다 문장이 비슷 → 유사문서 위험** | **가게마다 두뇌가 달라 문장이 갈라짐 → dup-guard 핵심 부품** |
| 5 | **위젯 문구** | "문의하기" | "무료 실측 문의" 같은 그 가게 말 |
| 6 | **FAQ 자동 생성** | 없음 | 4번 답 3개가 그대로 FAQ → **AI 브리핑 인용 구조** |
| 7 | **사이트 AI 상담원** | 불가능 | 프로필+스토리 기반 응답 (알리바바 万小智가 기본 탑재한 그 기능) |
| 8 | **견적 문의 답변 초안** | 없음 | Durable 의 Lead Agent 와 같은 것 |

**5번이 특히 좋습니다.** "안 하는 일"을 알면 AI 상담원이 "저희는 그건 안 합니다, 대신 이건 됩니다"라고 답할 수 있습니다. 이걸 모르면 AI가 없는 서비스를 지어내고, 손님이 헛걸음합니다. **날조 방지 장치를 사장님 입으로 만드는 것** — 조사한 어떤 서비스도 안 합니다.

## 6. AI와 대화하면서 블로그 글쓰기

### 6-1. 선례 (실존 확인)

| 서비스 | 방식 |
|---|---|
| **Storyworth** ($99/년) | 주 1회 이메일로 질문 1개 → **글로** 답 → 1년 52편 → 하드커버 책 |
| **Remento** ($99/년) | 주 1회 문자 → 링크 탭 → **음성으로 답변**(앱·로그인·타이핑 불필요) → **Speech-to-Story™** 로 산문 자동 변환 → 승인 후 인쇄. **각 페이지 QR로 원본 음성 재생** |
| **Elicito AI** | 주제 입력 → AI가 질문 목록 생성 → 고른 질문에 답 → **답에 따라 새 질문 분기** → 글이 실시간으로 조립되는 프리뷰 |
| **Ghostwriter 에이전트** | **한 턴에 질문 1개.** 열린 질문 → 좁히는 질문 → 확인 질문 3단 |

> **Remento 가 우리 스토리 넛지와 거의 같은 구조입니다.** 주 1회 문자 → 음성 답변 → AI가 산문으로. 다른 점은 그들은 책을 만들고 우리는 홈페이지·SNS를 만든다는 것뿐입니다. **이 모델이 실제로 팔린다는 증거**입니다.

### 6-2. 우리 스토리 넛지에 붙일 것 — 되묻기 2번

```
지금:  음성 30초 → AI가 3~5문장으로 정리 → 승인 → 게시   (1턴)

제안:  음성 30초
         ↓
       AI: "몇 평이었어요?"            ← 되묻기 1
         ↓ (음성 또는 탭)
       AI: "손님이 제일 좋아한 부분은요?"  ← 되묻기 2
         ↓
       완성 → 승인 → 게시
```

**되묻기 2번의 값어치:**

- 답변 길이 **5배**(조사 수치) → 300자 짧은 글 문제 해결
- **구체적 수치와 본인 경험이 자동으로 들어감** → 네이버가 요구하는 '솔직한 경험'·'독창성' 충족 → **저품질 방어**
- 가게마다 되묻는 내용이 달라짐 → **중복 문서 위험 감소**
- 비용: AI 호출 2회 추가 = **건당 3원 안 됨**

**규칙 4개:**
1. 한 번에 질문 하나 (Ghostwriter 패턴)
2. **최대 2번**, 그 이상 안 물음
3. **"그냥 이대로 올릴게요" 버튼 항상 노출** — 귀찮은 날 도망갈 구멍
4. 되묻는 질문은 업종별로 다르게 (인테리어=평수·기간·자재 / 미용=시술·소요시간 / 카페=신메뉴·재료)

## 7. ⚠ 반대 논거도 적습니다

**대화형이 항상 낫지는 않습니다.**

- **50~60대 사장님은 챗 UI 타이핑을 싫어할 수 있습니다.** 순수 채팅으로 만들면 오히려 이탈이 늘 수 있습니다. → **음성 답변 + 선택지 버튼을 반드시 병행**해야 합니다. 타이핑은 세 번째 선택지로.
- **대화는 "언제 끝나는지" 모르면 불안합니다.** → 진행 표시(3/6) 필수. 이게 없으면 대화형의 이점이 사라집니다.
- **필수 4개(상호·전화·slug·주소)는 폼이 낫습니다.** 전화번호를 대화로 물어볼 이유가 없습니다. **폼 + 인터뷰 혼합**이 정답입니다.
- 비용은 문제 아닙니다 — 인터뷰 10턴 약 20~50원, 1회성.

## 8. 음성 온보딩은 아직 빈 자리입니다

조사 결과: **"말로 답하면 홈페이지가 만들어지는" 전용 서비스는 확인되지 않았습니다.**

- Wegic — 채팅창에 음성 입력(받아쓰기)은 되지만 그뿐
- 재밋 — 생성 **후** 음성 편집 명령
- Remento — 음성 답변 → 산문 변환이 가장 성숙하지만 **책이지 홈페이지가 아님**

> **"말로 만드는 홈페이지"는 세계적으로 빈 자리이고, 우리는 이미 음성 파이프라인(스토리 넛지)을 기획해 뒀습니다.** 온보딩과 스토리가 같은 부품을 씁니다.

## 9. 순서 — Meta 심사 대기 기간에 이걸 만드십시오

이게 이번 검토에서 가장 실무적인 발견입니다.

```
오늘        Meta 앱 심사 신청  ────────────── 6~8주 대기 ──────────────┐
                                                                      │
그 사이에   ① 3분 인터뷰 + 가게 두뇌 (세션 2~3개)                      │
            ② 빈 섹션 정리 + 완성도 점수 (반나절)                      │
            ③ AI 검색 노출 GEO (반나절)                                │
            ④ 플로팅 위젯 (스키마 변경 → Opus)                         │
            ⑤ 스토리 넛지 N1~N4 + 되묻기 2번                          │
                                                                      ↓
심사 통과   ⑥ autopost (인스타·쓰레드 자동 게시) — 프로필이 준비된 상태에서 켬
```

**프로필(두뇌)이 autopost 보다 먼저여야 합니다.** 두뇌 없이 SNS 자동 게시를 켜면 평범한 글이 나가고, 그게 여러 계정에 퍼지면 dup-guard 가 막아야 할 바로 그 상황이 됩니다. 순서가 뒤집히면 안 됩니다.

그리고 **대기 기간이 놀고 있는 시간이 아니라 두뇌를 만드는 시간이 됩니다.** 일정이 딱 맞습니다.

## 10. 회장님 결정이 필요한 것

1. **인터뷰를 어디까지 대화로 할까요?** — 권고: 필수 4개는 폼 유지, 6문항만 대화 (혼합)
2. **음성 답변을 온보딩에도 넣을까요?** — 권고: 넣습니다. 빈 자리이고 부품을 재사용합니다
3. **"가게 카드 확인 화면"(만든 뒤가 아니라 만들기 전에 보여주기)을 넣을까요?** — 권고: 넣습니다. 万小智의 가장 방어 가능한 패턴
4. **스토리 넛지에 되묻기 2번을 넣을까요?** — 권고: 넣습니다. 저품질 방어에 직접 기여
