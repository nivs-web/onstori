01역할과 도구 — 무엇을 어디서 하나

코워크 세션을 2개로 나누는 것이 아니라, 클로드코드 터미널을 2개 여는 것입니다.

지금 하고 계신 방식이 맞습니다. 코워크(이 대화)는 기획·검토·프롬프트 작성을 맡고, 클로드코드(터미널)가 저장소에서 코드를 씁니다. 병렬 작업은 클로드코드 쪽에서 일어납니다 — 터미널 창 두 개, 각각 다른 폴더(worktree)에서 다른 브랜치를 작업하고, 끝나면 main에 합칩니다.

코워크는 하나면 됩니다. 클로드코드에서 나온 결과(빌드 로그, 화면 캡쳐, "이게 맞나요?")를 여기로 가져오시면 검토하고 다음 프롬프트를 드립니다. 이 세션이 그 기획의 단일 출처이고, 프로젝트 문서(claude/onstori-advisor-context.md)에 계속 누적됩니다.

도구하는 일하지 않는 일
코워크 (여기)기획 확정 · 스펙 작성 · 클로드코드 프롬프트 작성 · 결과 검토 · 결정 기록저장소 코드 직접 수정(가능은 하지만 클로드코드와 충돌)
클로드코드 터미널 1에디터 계열(세션 0 → A → C …) — 폴더 onstori(main) 또는 onstori-wt-editor다른 터미널이 소유한 파일 수정
클로드코드 터미널 2독립 작업(세션 B 미리보기, G1 견적 백엔드 …) — 폴더 onstori-wt-preview / onstori-wt-inquiry동시에 lib/schema.ts·마이그레이션 만지기
사장님(사람)브랜치 합치기 · 배포 확인 · 마이그레이션 push · 대시보드 설정 · 결정—

05견적 접수 설계 — 목표와 흐름

목표: 손님이 30초 안에 사진 3장과 전화번호를 남기고, 사장님 폰에 60초 안에 알림이 도착하고, 에디터에 "문의 3건"이 보인다.

그러면 온스토리는 처음으로 자기 상품의 성과(리드)를 측정하게 되고, 사장님은 무료 한 달 안에 "이 홈페이지에서 연락이 왔다"를 경험합니다. 홈온은 이 기능을 39,900원 BUSINESS에만 줍니다 — 온스토리는 기본입니다.

손님 쪽 흐름

히어로의 "견적 문의" 버튼 → #quote 섹션으로 스크롤 → 폼: 이름 · 연락처(필수) · 어떤 작업인지 한 줄(선택) · 현장 사진 최대 3장(폰이면 카메라 직행, 업로드 전 압축) · 개인정보 수집 동의 체크 → "견적 요청 보내기" → 성공 화면 "접수됐어요. 사장님이 곧 연락드려요" + 급하면 전화 버튼. 전화 버튼은 폼 옆에 그대로 둡니다 — 시공 손님의 절반은 여전히 전화를 선호합니다.

사장님 쪽 흐름

접수 즉시 문자(솔라피) + 이메일(Resend) — "니브인테리어에 견적 문의가 왔어요 · 김OO · 010-…· 사진 2장 · 보기 →" → 링크는 에디터 문의함 탭(로그인 필요) → 상세: 사진 크게, 내용, "전화하기" 버튼, 상태(새 문의 → 연락함 → 완료), 메모 한 줄. 문의함 탭에는 새 문의 수 배지. 알림 받을 번호·이메일은 설정 탭에서 바꿀 수 있고, 기본값은 견적 섹션의 전화번호와 로그인 이메일입니다.

온스토리 쪽(운영자) 흐름

어드민 사이트 목록에 "문의 수(30일)" 열 하나 추가. 어느 업종·어느 사이트에서 리드가 나는지 처음으로 보입니다. 이 숫자가 다음 리포트(Sprint B 대시보드)의 씨앗입니다.

06데이터 · API · 보안 · 알림 스펙

테이블 — inquiries (마이그레이션 1개)

create table inquiries (
  id            uuid primary key default gen_random_uuid(),
  site_id       uuid not null references sites(id) on delete cascade,
  kind          text not null default 'quote' check (kind in ('quote','reserve','consult','contact')),
  name          text not null check (char_length(name) between 1 and 40),
  phone         text not null check (phone ~ '^[0-9+\-]{9,20}$'),
  message       text check (char_length(message) <= 1000),
  photos        jsonb not null default '[]',        -- ["inquiries/<site_id>/<uuid>.webp", ...] 최대 3
  status        text not null default 'new' check (status in ('new','contacted','done','spam')),
  memo          text check (char_length(memo) <= 300),   -- 사장님 메모
  referrer_class text,                               -- direct|naver|google|instagram|kakao|other (Sprint B 통계와 공유)
  ip_hash       text,                                -- 일 단위 salt 해시. 원 IP 저장 안 함
  consent_at    timestamptz not null,                -- 개인정보 수집 동의 시각 (법적 근거)
  read_at       timestamptz,
  created_at    timestamptz not null default now()
);
create index on inquiries (site_id, created_at desc);
create index on inquiries (site_id, status);

alter table inquiries enable row level security;
-- 손님 insert 는 service-role API 에서만 (anon 직접 insert 정책 없음)
-- 사장님 select/update 는 owner_id 일치
create policy "owner reads own inquiries" on inquiries for select
  using (exists (select 1 from sites s where s.id = inquiries.site_id and s.owner_id = auth.uid()));
create policy "owner updates own inquiries" on inquiries for update
  using (exists (select 1 from sites s where s.id = inquiries.site_id and s.owner_id = auth.uid()));

-- 사진 버킷: 손님 현장 사진은 공개 버킷에 두지 않는다
insert into storage.buckets (id, name, public) values ('inquiry-photos','inquiry-photos', false);

-- site_progress.funnel 에 first_inquiry_at 키 추가 (jsonb 라 스키마 변경 없음, 코드에서 set)

설계서 09장의 inquiries 원안에 consent_at·ip_hash·memo·referrer_class를 더했습니다. 익명 사이트(owner_id null, anonId만)의 문의는 RLS로는 못 읽으므로 문의함 API가 loadOwnedSite(anonId 폴백 포함)로 판정하고 service-role로 읽습니다 — 기존 5개 게이트 API와 같은 방식입니다.
