# 이야기 이미지 — 생성하지 않고 뱅크에서 꺼내 쓰는 구현안

작성: 기술참모 · 2026-09-05 · 회장님 지시("글을 보고 이미지 생산은 하지 않고, 이미지뱅크 활용하자")
프로토타입: `story-engine-proto-v2-2026-09-05.html` 4장(이미지) — 눌러서 흐름 확인 가능

---

## 0. 세 줄 요약

1. **원가가 250원 → 67원으로 떨어집니다**(고객 1인 월, 주 2건 기준). 이미지 맞춤 생성 184원이 통째로 사라집니다. 49,000원 대비 0.5% → **0.14%**.
2. **이미 있는 것을 그대로 씁니다.** `image_bank` 테이블과 `pickImage()` 매칭 함수가 이미 돌아가고 있습니다(승인 638장). **`role`에 `'story'` 하나만 추가하면 됩니다.**
3. **뱅크를 짓는 비용은 한 번에 약 1,024원**(256장 × Flux Schnell 4원)입니다. 3개월에 40만 원 쓸 일이 없습니다 — 구글 API는 선불이 아니라 종량제이고, 우리에게 필요한 건 10만 장이 아니라 256장입니다.

## 1. 회장님 질문에 대한 답 두 가지

### 1-1. 나노바나나가 왜 10월 2일에 끝나는가

구글 **공식 지원 종료 목록**(ai.google.dev/gemini-api/docs/deprecations)에 이렇게 올라와 있습니다.

| 모델 | 종료일 | 후속 |
|---|---|---|
| `gemini-2.5-flash-image` (나노바나나) | **2026-10-02** | `gemini-3.1-flash-image-preview` |
| `imagen-4.0-generate-001` / `ultra` / `fast` | **2026-08-17** | `gemini-3.1-flash-image` |
| `gemini-2.0-flash-preview-image-generation` | 2025-11-14 | `gemini-2.5-flash-image` |

**다만 같은 문서가 이 날짜를 «은퇴할 수 있는 가장 이른 날(earliest possible dates)»이라고 명시**합니다. 그날 갑자기 멈춘다는 뜻이 아니라, 그 뒤로는 언제든 끊길 수 있으니 옮기라는 안내입니다.

⚠ **동시에 중요한 정정** — 제가 지난번 표에 넣은 **Imagen 4 Fast(27원)는 이미 8월 17일에 정리됐습니다.** 지금 쓸 수 있는 선택지는 사실상 둘입니다.

- **Flux Schnell (Replicate)** — 장당 **4원**
- **나노바나나 2 Lite + 배치** — 장당 **23원**

뱅크는 일 년에 네 번, 한 번에 천 원어치라 어느 쪽이든 상관없습니다.

### 1-2. "3개월간 40만원 정도 쓰는 거 아니었어?"

**그럴 일이 없습니다.** 두 가지가 겹쳐서 생긴 오해로 보입니다.

- **구글 API는 선불 충전이 아니라 쓴 만큼 내는 종량제**입니다. 40만 원을 미리 넣어둘 필요가 없습니다.
- 40만 원어치면 Flux Schnell 기준 **10만 장**입니다. 우리에게 필요한 건 **256장**입니다.

| | 3개월 비용 |
|---|---|
| 이야기마다 AI로 새로 뽑기 (고객 100명) | **55,200원** |
| **배경 뱅크 방식** | **약 1,000원** |

## 2. 이미 있는 것 — 손댈 필요가 없는 부분

`lib/bank.ts`(2026-09-05 확인)에 이미 들어 있는 것들입니다.

- **테이블** `image_bank`: `id, url, tags[], industry, mood, role, quality_ok, quality_score, used_count, deleted`
- **`pickImage(industry, mood, role, {text})`** — 승인 이미지 중에서
  - 태그가 본문과 겹치는 개수로 점수(`tagScore`)
  - `quality_score` 내림차순 → `used_count` 오름차순
  - 적중 그룹 안에서 랜덤(사이트 판박이 방지)
  - `bump_bank_used` RPC로 사용 카운트 증가(실패해도 진행)
  - 뱅크가 비면 `placeholderFor(industry)` 폴백
- **`pickImages(..., n, {widenMood})`** — 여러 장, 점수 tier별 셔플, 모자라면 같은 업종 다른 무드에서 보충
- **`heroStock()`** — 어드민 재고 표시
- **재고 부족 경고** — `hero_stock_low` 로그

**이 설계가 이미 우리가 필요한 것의 90%입니다.** 이야기 이미지는 여기에 얹기만 하면 됩니다.

## 3. 바꿀 것 — 최소 변경

### 3-1. `role`에 `'story'` 추가

```
role: "hero" | "gallery" | "about" | "process" | "story"
```

DB에 `role` check 제약이 있으면 마이그레이션 한 줄. 없으면 값만 추가하면 됩니다. **`lib/schema.ts`는 건드리지 않습니다** — `image_bank`는 SiteDoc 스키마가 아니라 별도 테이블입니다. **즉 Opus·ultracode 불필요.**

### 3-2. 태그 체계 — 이야기용

기존 태그(업종·소재)에 더해 이야기 배경용 태그를 붙입니다. 배경은 **장면이 아니라 질감·색면**이므로 태그도 추상적입니다.

| 축 | 값 예시 |
|---|---|
| 재료·질감 | 나무 · 콘크리트 · 타일 · 금속 · 페인트 · 벽지 · 천 · 유리 |
| 작업 | 철거 · 마감 · 도색 · 배선 · 조립 · 청소 · 시술 · 조리 |
| 공간 | 거실 · 주방 · 욕실 · 매장 · 작업대 · 현장 |
| 도구 | 공구 · 붓 · 줄자 · 장비 |
| 정서 | 아침 · 마무리 · 시작 · 손 · 기다림 |
| 톤 | 따뜻한 · 차분한 · 밝은 · 어두운 |

### 3-3. `pickStoryImage()` 신설

```
pickStoryImage(siteId, industry, mood, imageTags[], recentUrls[])
  → 뱅크에서 role='story', quality_ok, industry 일치(또는 공용)
  → tagScore(tags, imageTags.join(" "))로 점수
  → recentUrls(그 사이트가 최근 12편에 쓴 것) 제외
  → 적중 그룹에서 랜덤 → bump_bank_used
  → 없으면 industry 무시하고 공용 배경에서 (톤만 맞춰서)
```

`recentUrls`는 `story_entries`에서 그 사이트의 최근 12건 `imageUrl`을 읽으면 됩니다. hero처럼 전역 "사용 중" 개념은 필요 없습니다 — 이야기는 흘러가는 콘텐츠라 다른 가게와 배경이 겹쳐도 치명적이지 않고, 어차피 **얹는 글자가 다릅니다.**

## 4. 핵심 — "고르는 데는 돈이 안 든다"

글을 읽고 어떤 배경이 어울릴지 판단하려면 AI를 한 번 더 불러야 할 것 같지만, **그럴 필요가 없습니다.**

이미 이야기 하나당 **글 4종(홈페이지·인스타·쓰레드·블로그)을 만드는 호출이 한 번** 있습니다. 그 응답 JSON에 필드 하나만 더 요구하면 됩니다.

```
{
  "homepage": {...}, "instagram": {...}, "threads": "...", "blog": "...",
  "imageTags": ["철거", "거실", "벽", "리모델링"],   ← 추가
  "cardLine": "벽 하나 텄더니\n딴 집 같다고 하셨습니다"  ← 추가
}
```

**추가 호출 0회, 추가 비용 0원.** 출력 토큰이 20~30개 늘어나는 정도라 계산에 잡히지도 않습니다.

`cardLine`은 카드에 얹을 한 줄입니다. 제목을 그대로 쓰면 길어서 안 예쁘므로 별도로 받습니다.

---

## 5. 배경 한 장으로 여러 장 만들기 — 뱅크가 작아도 되는 이유

이게 이 설계의 핵심입니다. **뱅크는 «완성된 이미지»가 아니라 «배경 소재»입니다.**

```
배경 1장  +  이야기 한 줄  +  크롭 3종  =  매번 다른 결과물
```

| 자리 | 비율 | 용도 |
|---|---|---|
| 1:1 (1080×1080) | 정사각 | 인스타 피드 · 홈페이지 이야기 카드 |
| 4:5 (1080×1350) | 세로 | 인스타 피드(더 크게 보임) |
| 9:16 (1080×1920) | 세로 긴 | 릴스·쇼츠 표지 · 인스타 스토리 |

**구현: `@vercel/og`(Satori 기반 `ImageResponse`)** — Next.js에 이미 딸려 있는 방식이고, 한글 폰트 파일을 fetch해서 넣으면 됩니다. `app/api/story-card/route.tsx` 하나로 세 비율을 다 뽑습니다. **서버 함수 실행시간 말고는 비용이 0원**입니다.

> 대안으로 `sharp` + SVG 합성도 되지만, 한글 폰트 처리와 줄바꿈 계산이 `@vercel/og` 쪽이 훨씬 간단합니다.

**결과적으로 뱅크가 겹쳐도 티가 나지 않습니다.** 가게마다 이야기가 다르니 얹는 글자가 다르고, 글자가 다르면 다른 이미지로 보입니다.

## 6. 우선순위 — 사장님 사진이 언제나 1순위

```
1순위  사장님이 이 이야기에 올린 사진        → 그대로 사용, 뱅크 안 씀
2순위  그 사이트의 예전 이야기 사진 재활용    → "지난 작업" 표기 필요, 기본은 끔
3순위  뱅크 배경 + 이야기 한 줄 카드          → 위 5장
4순위  업종 플레이스홀더                      → 뱅크가 비었을 때만
```

**뱅크는 «사진을 못 찍은 날의 안전망»입니다.** 그리고 이야기가 쌓일수록 사장님 사진도 쌓여서 **시간이 갈수록 뱅크를 덜 쓰게 됩니다.**

⚠ 다만 **인스타는 이미지가 없으면 게시 자체가 불가능**하므로, 영상이 없고 사진도 없는 날엔 3순위가 반드시 작동해야 합니다.

---

## 7. ⚠ 지켜야 할 선 — 뱅크에 «장면 사진»을 넣지 않습니다

AI가 만든 이미지를 실제 시공 사진처럼 쓰면 **표시광고법 문제**이고, 손님이 알아보는 순간 신뢰가 무너집니다.

**해결은 규칙이 아니라 소재 자체를 바꾸는 것입니다.** 뱅크에 «공사 끝난 예쁜 거실» 같은 장면을 아예 넣지 않고, **글자를 얹을 추상적인 배경만** 넣습니다.

| 넣는 것 | 넣지 않는 것 |
|---|---|
| 나뭇결·콘크리트·타일 질감 클로즈업 | 완성된 거실·주방 전경 |
| 색면·그라디언트 | 사람이 작업하는 장면 |
| 공구 실루엣·흐린 배경 | 시공 전후 비교 컷 |
| 창밖 빛·먼지 낀 공기 | 특정 매장 인테리어 |

이러면 애초에 **«저 집이 내 작업물»이라는 오해가 생길 여지가 없습니다.** 그래도 화면 구석에 «AI로 만든 배경»을 작게 적어 둡니다.

**그리고 이 규칙이 뱅크 크기를 줄여줍니다.** 장면 사진이면 인테리어용과 미용실용이 완전히 달라야 하지만, **질감과 색면은 톤만 맞으면 업종을 가리지 않습니다.** 그래서 48업종 × 100장이 아니라 **8묶음 × 32장**으로 끝납니다.

## 8. 뱅크 짓기 — 실제 절차

### 8-1. 규모

| 축 | 값 | 수 |
|---|---|---|
| 업종 묶음 | 인테리어·시공 / 수리·설비 / 미용·뷰티 / 카페·음식 / 전문·상담 / 건강·운동 / 교육·공방 / 공용 | 8 |
| 톤 | 따뜻한 · 차분한 · 밝은 · 어두운 | 4 |
| 각 칸 | | 8장 |
| **합계** | | **256장** |

**비용: 256 × 4원 = 약 1,024원.** 분기마다 256장씩 보충해도 연 4,096원입니다.

### 8-2. 생성 프롬프트 뼈대

```
한국 소상공인 홈페이지의 이야기 카드 배경 이미지.
- 소재: {나뭇결 / 콘크리트 / 타일 / 금속 / 페인트 자국 / 벽지 / 천}
- 톤: {따뜻한 / 차분한 / 밝은 / 어두운}
- 구도: 텍스트를 얹을 여백이 왼쪽 아래에 크게 비어 있을 것
- 절대 넣지 말 것: 사람, 얼굴, 글자, 로고, 완성된 실내 전경, 특정 브랜드
- 스타일: 사진 같은 질감. 일러스트·3D 렌더링 아님
- 비율: 1:1, 1024px
```

**«텍스트를 얹을 여백»** 지시가 중요합니다. 이게 없으면 글자가 배경에 묻힙니다.

### 8-3. 검수

회장님이 보시고 **넣을 것만 골라 `quality_ok = true`**로 올립니다. 기존 뱅크와 같은 방식입니다. 256장 중 절반만 통과해도 128장이고, 그걸로도 충분합니다(글자·크롭·톤 변주가 곱해지므로).

## 9. 어드민 — 재고 화면

기존 `heroStock()` 옆에 `storyStock()`을 하나 더 만듭니다.

```
(업종 묶음, 톤)별  승인 수 / 최근 30일 사용 수 / 사용률
사용률 70% 넘는 칸에 경고 → 그 칸만 보충 생성
```

`hero_stock_low`와 같은 패턴의 로그를 남기면 회장님 문자로 알림이 갑니다.

## 12. 회장님 결정이 필요한 것

1. **뱅크 생성 모델** — Flux Schnell(4원, 256장에 1,024원) vs 나노바나나 2 Lite 배치(23원, 5,888원)
2. **뱅크 규모** — 256장으로 시작 vs 처음부터 넉넉히(2,880장 · 11,520원)
3. **«AI로 만든 배경» 표기를 넣을지** — 참모 권고: 넣습니다. 작게라도.
4. 사장님 사진이 없는 날 **예전 사진 재활용을 허용할지** — 참모 권고: 기본은 끕니다("지난 작업" 표기가 없으면 오해 소지).
