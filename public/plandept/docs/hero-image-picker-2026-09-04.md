# 히어로 사진 — 별점 선별 · 추천 3장 · 직접 등록(크롭) (기획, 2026-09-04)

> 작성: 전략기획실(코워크). 온팀장(클로드코드)이 읽고 구현한다.
> 관련: `lib/bank.ts`(pickImage), `app/admin/bank/ui.tsx`(검수 화면), `app/[slug]/edit/ui.tsx`(히어로 카드), `lib/image-usage.ts`(사용 중 판정).
> 한 줄 결론: **별점은 오늘이라도 된다(반나절, 위험 0). 편집 화면의 추천 3장·AI 추천·직접 등록은 미리보기(5번) 바로 뒤 한 세션.**

## 0. 아이디어 요약 (사장님 원안)

이미지뱅크에 관리자가 1~5점 별점을 매긴다. 점수 높은 히어로가 먼저 뽑힌다. 첫 편집 화면에서 "히어로 사진 바꾸기"를 누르면 별점 상위 후보 3장이 보이고, "AI 추천" 버튼은 항상 있으며, "직접 등록하기"는 비율에 맞게 잘라서 올린다.

## 1. 현재 코드가 이미 가진 것 (사실 확인)

- `image_bank.quality_score`(0~100)가 있고, 어드민 검수 카드에 **90/70/50/30점 드롭다운**이 이미 있다(`admin/bank/ui.tsx` 119행).
- `pickImage()`는 이미 `quality_score desc → used_count asc`로 정렬해 뽑는다. 히어로는 다른 사이트가 쓰는 사진을 제외하고(`heroUrls`), 태그 적중 그룹 또는 상위 5장에서 랜덤.
- 에디터 히어로 카드에는 "내 사진으로 교체(+15점 항목)" 업로드 버튼만 있다. 뱅크에서 고르는 UI는 없다.
- 히어로 스키마 `Hero.image`는 URL 문자열 하나 — **스키마 변경 없이** 전부 가능하다.

→ 원안의 절반(점수→우선 선택)은 이미 구현돼 있고 **점수를 안 매겼을 뿐**이다(638장 전량 50점 기본값). 나머지 절반이 "고객이 고르는 화면"이다.

## 2. 별점 (H1 — 어드민만, 반나절)

- 드롭다운을 **★1~5**로 교체. 저장값은 기존 `quality_score`에 매핑(1→20, 2→40, 3→60, 4→80, 5→100). 마이그레이션 없음.
- 어드민 뱅크 목록에 필터 `role=hero` + 정렬 "점수 낮은 순/미채점 우선" + 키보드 1~5로 채점(한 장에 1초). 히어로 100여 장을 사장님이 직접 10분에 끝낼 수 있게.
- `pickImage` 변경 한 줄: 히어로는 **★4 이상만 후보**, 부족하면 ★3까지 확장(재고 경고 `hero_stock_low` 기존 로직 유지). 갤러리 등은 지금처럼 점수 가중치만.
- 효과: 새 사이트 생성 품질이 **즉시** 올라간다. 편집 화면이 없어도 이득이 있으므로 먼저 한다.
- 지금 진행 중인 병합·db push 사이에 끼워도 안전하다(어드민 파일 2곳, 스키마·마이그레이션 무관).

## 3. 편집 화면 — 히어로 사진 바꾸기 (H2 — 한 세션)

### 3-1. 화면

히어로 카드의 사진 아래 버튼 하나 **"사진 바꾸기"** → 바텀시트(폰) / 패널(PC) 하나에 세 줄:

```
┌ 사진 바꾸기 ─────────────────────────────┐
│ 추천 3장                    [다른 추천 보기 ↻] │
│  [■ 후보1] [■ 후보2] [■ 후보3]   ← 탭하면 즉시 교체(미리보기 반영)        │
│ ✨ 내 소개글에 맞춰 AI가 다시 고르기          ← 항상 있음                  │
│ 📷 내 사진 올리기 (자동으로 비율 맞춤)         ← 파일 선택 → 크롭 → 업로드  │
└──────────────────────────────────────────┘
```

- **추천 3장**: `POST /api/bank/suggest {slug, exclude:[현재 URL, 이미 보여준 URL…]}` → 같은 업종·무드·`role=hero`·★4 이상·다른 사이트 미사용 중에서 **상위 9장 안에서 3장**(사이트마다 판박이 방지). "다른 추천 보기"는 exclude를 늘려 다음 3장. 후보 소진이면 ★3까지 확장, 그래도 없으면 "직접 올리기"만 안내.
- **AI 추천(항상 노출)**: 생성이 아니라 **선택**이다. 상호·헤드라인·소개글 앞 200자를 `pickImage(opts.text)`의 태그 점수에 태워 3장을 다시 고른다. 비용 0원, 1초. 문구는 "AI가 골랐어요 · 이유: '욕실·타일' 태그 일치"처럼 이유 한 줄을 붙인다(신뢰).
  - "AI로 새로 만들기"(gemini-3-pro-image, 장당 $0.134·15초)는 **이 화면에 넣지 않는다.** 뱅크 638장이 있는 동안 생성은 비용·대기·검수 문제만 만든다. P6 브랜드키트/유료 옵션에서 하루 1회 제한으로 검토.
- **내 사진 올리기**: 파일 선택 → 크롭 화면(핀치 줌·드래그, 고정 비율) → canvas로 잘라 1600px WebP → 기존 `/api/site/upload` → `patchSection(i, {image})`. 비율은 히어로 렌더러의 실제 표시 비율을 따른다 — 현재 렌더러가 `object-cover`로 임의 비율을 받는다면 **PC 16:9 기준으로 자르고 폰은 가운데를 보여주는 현행 유지**가 가장 단순하다. 크롭 라이브러리는 `react-easy-crop`(MIT, 작음, 모바일 핀치 지원) 채택 — 직접 만들면 폰 터치 처리에서 하루가 나간다.
- 교체 즉시 미리보기(5번 스프린트의 postMessage)로 보인다. 저장은 기존 자동저장/저장 버튼 흐름.
- 파일 위치: `app/[slug]/edit/hero-picker.tsx` **별도 파일**(ui.tsx에 쌓지 않는다 — 스프린트 플랜 5장). data-tour 앵커는 `config/tours.ts`에 `hero-picker`를 먼저 등록.

### 3-2. 첫 편집 화면과의 연결

- 생성 직후 에디터 첫 진입 투어(`editorIntro`)의 **1번째 스텝을 "첫 화면 사진 바꾸기"**로 둔다. 사장님이 처음 3초에 하는 행동이 "내 가게 사진처럼 보이게 바꾸기"여야 소유감이 생긴다.
- 완성도 규칙(`completeness.ts`)의 "내 사진으로 교체 +15점"은 **직접 업로드일 때만** 준다(뱅크 안에서 바꾸는 건 점수 0). 규칙표 변경 없음 — 판정은 URL이 `sites/` 키인지로.

### 3-3. API

| 라우트 | 입력 | 동작 |
|---|---|---|
| `POST /api/bank/suggest` | `{slug, anonId?, exclude:string[], mode:'top'|'ai'}` | `loadOwnedSite` 게이트 → `mode=top`: 업종·무드·hero·★4↑·미사용 상위 9장에서 3장 / `mode=ai`: 사이트 문구로 tagScore 재정렬 상위 3장 + 적중 태그 반환 → `{items:[{url, id, reason?}]}`. rate limit 분당 20 |

- 히어로 교체 시 `used_count`는 발행 시점에 `bump_bank_used`(기존 RPC)로 올린다 — 후보를 보여준 것만으로 올리지 않는다.
