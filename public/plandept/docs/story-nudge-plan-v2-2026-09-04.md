## 1. 채널 — 카톡 (A단계 운영 절차)

### 1-1. 발송 방법 (0~20곳)
- 회장님 명의 카톡(회사 번호 계정)에서 **1:1 채팅방**에 예약 메시지. 카톡 예약은 반복이 없으므로 **월초에 4주치(화요일 4번, 12:00)**를 건다. 20곳 × 4개 = 80개, 약 40분/월. 20곳 넘으면 B단계(알림톡, 아래).
- 회장님이 폰에서만 관리 가능(PC 카톡에서 예약 수정 불가 — v1 사실확인).
- 명단은 운영자 화면 "고객관리"(4장)에서 본다. 시트는 쓰지 않는다 — 어차피 운영자 화면이 필요하므로 처음부터 거기에.

### 1-2. 메시지 v2 (독자 제작)
```
사장님, 온스토리 권병철입니다 🙂
이번 주 하신 일 하나만 남겨주세요. 20초 녹음이면 충분해요.
👉 onstori.com/abc/story

말씀하신 내용만 그대로 정리해서 홈페이지에 올려드려요. 지어내거나 부풀리지 않습니다.
※ 녹음은 카톡 밖(Chrome·Safari)에서 돼요. 카톡 안에서는 글·사진으로 남겨주세요. 이 채팅에 음성메시지를 보내셔도 글이 되지는 않아요.
바쁘시면 다음 주에 하셔도 됩니다. 안 받고 싶으시면 "원치않음"이라고 답장 주세요.
```

### 1-3. B단계(20곳+): 알림톡
- 사업자등록 → 카카오 비즈니스 채널 → 알림톡 템플릿 심사(정보성, 1~2주) → `lib/notify.ts`에 채널 추가 → 크론이 화 12:00 자동 발송. 사장님 쪽엔 "onstori 채널" 발신으로 바뀌는 것 외에 달라지는 게 없다. 회장님 손은 0이 된다.

## 2. 인증 — 카카오 로그인 기술 검토

### 2-1. 카톡 안에서 카카오 로그인이 왜 1탭인가
카톡 메시지의 링크를 누르면 **카톡 인앱 브라우저**가 열린다. 거기서 "카카오로 계속하기"를 누르면 카카오 인증 화면이 뜨는데, 카톡 앱 안이라 **이미 로그인된 계정으로 "동의하고 계속" 한 번**이면 끝난다. 아이디·비밀번호 입력이 없다. 그리고 그 브라우저의 쿠키(세션)는 남으므로 **다음 주부터는 로그인 화면 자체가 안 뜬다.**
- 온스토리는 이미 카카오 OIDC 직결(`/auth/kakao` → `/auth/callback`)이 있다. `/abc/story`에서 로그인이 필요하면 `?next=/abc/story`로 보내서 돌아오게만 하면 된다.
- 세션은 `@supabase/ssr` 쿠키 + 리프레시 토큰이라 며칠~몇 주 지나도 유지된다(사장님이 로그아웃하지 않는 한).
- **"Chrome으로 열기"를 눌러 녹음하러 나가면 쿠키가 다른 브라우저라 한 번 더 로그인**한다. 이것도 카카오 앱 인증이라 1~2탭. 이후 Chrome에서도 유지.

### 2-2. 링크를 가로채도 안전한가
안전하다. `/abc/story`의 사장님 모드는 **로그인한 사용자의 uid가 `sites.owner_id`와 같을 때만** 열린다(P4에서 만든 `loadOwnedSite` 게이트 그대로). 링크는 공개 주소일 뿐이고, 남이 열면 손님 화면만 본다. 그래서 v1의 "작성 키"는 **폐기**한다 — 회장님 판단이 맞다.

### 2-3. 이메일 가입자는 어떻게 하나 (3안)
현재 로그인은 카카오 + 이메일 OTP 둘 다 있다. 카카오 로그인이 안 되는 사장님(카카오 앱 인증 실패, 법인폰 등)이 이메일로 가입했다면:

| 안 | 내용 | 장단 |
|---|---|---|
| A. 그대로 둔다(권고) | `/abc/story` 로그인 화면에 **카카오 버튼 크게 + "이메일로 로그인" 작은 링크**. 이메일 사장님은 6자리 코드 입력 | 개발 0. 이메일 사장님은 처음 한 번 코드 입력, 이후 세션 유지 |
| B. 운영자가 소유자 변경 | 사장님이 나중에 카카오로 로그인하면 새 계정이 생긴다 → 운영자 "고객관리 → 소유자 변경"으로 사이트를 그 계정에 옮김 | 관리 화면 버튼 1개. 회장님 손이 한 번 간다 |
| C. 계정 연결(linkIdentity) | Supabase가 제공하는 계정 연결 기능 | **막혀 있다** — Supabase의 카카오 프로바이더는 이메일 동의를 강제해 KOE205로 실패한 그 경로다(DECISIONS 2026-09-01). 자동 연결도 카카오가 이메일을 안 주므로 불가 |

권고: **A를 기본으로, B를 운영자 화면에 넣어 둔다.** "이메일 로그인 차단"은 하지 않는다 — 막아서 얻는 보안이 없고(2-2), 잃는 건 기존 가입자다. 다만 **신규 가입 화면에서는 카카오를 먼저 보여주고** 이메일은 접힌 링크로 둬서 자연스럽게 카카오 비율을 높인다.

### 2-4. 주인 없는(익명) 사이트
가입 없이 만든 사이트(`owner_id null`)는 넛지 대상이 아니다. `/abc/story`에서 사장님 모드를 열려면 카카오 로그인 → 기존 claim 흐름으로 소유권을 가진 뒤 진입. 고객관리 화면에 "소유자 없음" 표시.

## 3. 입력 · AI — "10초 말해도 그 사장님 글이 되게"

### 3-1. 입력 3종과 제한
| 입력 | 되는 곳 | 제한 |
|---|---|---|
| 🎤 녹음 | iOS 카톡 안 · iOS Safari · 안드로이드 Chrome. **안드로이드 카톡 안 ✗**(페이지가 감지해 "Chrome으로 열기" + 명시 문구) | 최소 2초, 20초 권장, **60초 상한** |
| ✏️ 글 | 어디서나 | 10자 이상, 1,000자 이하 |
| 📷 사진 | 어디서나 | **1글 20장 상한**(운영자 설정), 장당 폰에서 1,600px·WebP로 줄여 올림(≈250KB), 첫 화면 노출 8장 + "사진 더보기" |

- 카톡 채팅으로 온 음성메시지는 처리하지 않는다(명시). 사장님이 문의하면 "페이지에서 녹음해 주세요"로 안내.

### 3-2. AI가 맥락을 아는 방법 (겹층 프롬프트 + 사이트 프로필)
질문의 핵심: 인테리어·싱크대·목공·카페가 다 다른데 20초로 그 사장님 글이 되나. **된다. 방법은 "AI에게 매번 그 사장님의 홈페이지를 읽혀 주는 것"이다.**

```
[0 공통 규칙]   말한 것만 정리. 사실·숫자·경력·수상·후기·품질 자랑 추가 금지. 과장 형용사 금지. 지역은 동까지. 출력 JSON {title, body}
[1 업종 지시문] config/industries 의 storyPrompt (운영자 설정에서 덮어쓰기 가능)
                 시공: 어디 → 무슨 작업 → 어떤 상태였고 어떻게 했나 → 마무리
                 카페·베이커리: 무엇을 만들었나/바뀐 것 → 언제부터 → 손님에게 어떻게 보이나
                 가구·목공: 어떤 가구 → 재료·치수(말한 것만) → 어디에 놓였나
[2 사이트 프로필] 상호·업종·지역·소개문 요지·서비스 목록·말투 표본(사이트 카피 2문단) — 사이트 발행 시 1회 요약해 캐시(sites.inferred.storyProfile). 매번 사이트 전체를 넣지 않아 토큰 절약
[3 최근 이야기 5편] 제목+본문 — 말투 유지, 같은 현장 이어쓰기("지난주 정릉동 현장 마무리"), 중복 표현 회피
[4 사진]         사진이 있으면 함께 입력. 규칙: 사진에 **보이는 것만** 명사로 언급 가능("회색 줄눈"), 평가·추정 금지("깔끔하게", "고급")
[5 이번 입력]    녹음 전사문 또는 글. 길이 설정(3-3)과 재수정 지시(3-4)
```
- 모델: Gemini 3.5 flash. 음성은 파일을 그대로 입력(전사+초안 한 번에). 토큰 약 4~6K/건 ≈ **1원 미만**.
- **2차 검수 호출**(자동 검토의 핵심): 초안이 나오면 같은 모델에게 "원문·사진에 없는 사실이 초안에 있는가? 있으면 그 문장을 지목" → 있으면 지우고 검토함(4-3)에 기록. 건당 0.5원 추가.
- 만족도 안전판: 초안 화면에 항상 **"내가 쓸게요"** — 사장님 원문을 맞춤법만 고쳐 그대로 게시. 회장님 말대로 그것도 나쁘지 않다. 오히려 이 비율이 높은 사이트는 프롬프트를 손볼 신호다(4-3 규칙 ⑥).

### 3-3. 분량 기본값 (운영자 설정으로 조절)
| 설정 | 짧게 | **보통(기본)** | 길게 |
|---|---|---|---|
| 본문 | 2~3문장 · ≤150자 | **3~5문장 · 150~300자** | 5~8문장 · 300~500자 |
| 제목 | ≤18자 | **≤22자** | ≤26자 |
| 근거 | 폰 카드에 2줄 미리보기, 개별 페이지에서 전체 | 검색엔진이 "글"로 인식하는 최소 분량 ≈ 150자, 사장님이 승인 화면에서 한눈에 읽는 상한 ≈ 300자 | 사장님이 "더 길게" 요구할 때 |
- 사이트별 덮어쓰기 가능(고객관리 → 사이트 → 스토리 설정). 회장님이 고객 이야기 듣고 "더 길게"를 원하면 전체 기본값 또는 그 사이트만 바꾼다.

### 3-4. 수정 흐름 (AI 1회, 그다음은 직접)
```
초안 표시 → [✅ 이대로 올리기] [🔁 AI에게 한 번 더 부탁 (1/1)] [✏️ 내가 고칠게요] [🗑 안 올릴게요]
   🔁 → 한 줄 지시 선택: "더 짧게 / 더 자세히 / 더 부드럽게 / 이 부분 빼줘(직접 입력)" → 새 초안 → 버튼에서 🔁 사라짐
   ✏️ → 제목·본문 직접 편집 → 올리기
게시 후 → 목록의 내 글 카드 "글 고치기" → 제목·본문·사진 편집·숨기기 (AI 없음)
```
- 게시 후 수정은 **새 API**(`PATCH /api/site/story` — 제목·본문·사진·visible)가 필요하다. 지금은 insert만 있다.

## 4. 운영자(회장님) 메뉴

### 4-1. 설정 — `/admin/settings/story`

### 4-2. 고객관리 — `/admin/customers`
- 표: 상호 · slug · 업종 · 소유자(**카카오/이메일/없음** 표시) · 연락처 · 상태(체험/유료/만료) · 가입일 · **마지막 이야기(N일 전)** · 최근 4주 게시 수 · 넛지 상태(정상/원치않음/휴면) · 검토 미해결 수
- 기본 정렬 "마지막 이야기 오래된 순". 필터: 원치않음 / 4주 무응답 / 검토 대기 / 이메일 가입자.
- 상세: 위 정보 + 스토리 목록 + [소유자 변경](2-3 B안) + [넛지 일시중지/재개] + [스토리 설정 덮어쓰기] + 메모 + [전화하기] + "대신 올리기"(4-4).
- 기존 `/admin/sites`를 확장하거나 새 화면. 데이터는 `sites`·`auth.users`(provider)·`story_entries`·`review_queue`.

### 4-3. 검토함 — `/admin/review` (자동 검토 → 회장님 메시지 → 개별 연락)
자동 검토가 아래 규칙에 걸리면 `review_queue`에 한 줄 만들고, **회장님 폰에 문자 1통**("[온스토리 검토] abc 인테리어 · 사실 추가 의심 · onstori.com/admin/review") + 운영자 화면 배지. 회장님은 검토함에서 글을 보고 [문제 없음] [글 수정] [숨김] [전화하기] 중 하나로 닫는다.

| # | 규칙 | 언제 | 심각도 |
|---|---|---|---|
| ① | 2차 검수 AI가 "원문에 없는 사실" 지목 | 초안 생성 직후(자동 삭제 후 기록) | 높음 |
| ② | 금지 표현이 게시문에 남음(정규식) | 게시 직전 | 높음 |
| ③ | 의료·법률 위험어(전후·완치·효과·부작용 없음·최저가·1위·공식) | 게시 직전 | 높음 |
| ④ | 전화번호·URL·이메일 나열(스팸·타 업체 홍보) | 게시 직전 | 중간 |
| ⑤ | 본문 30자 미만 또는 사진만 | 게시 직후 | 낮음 |
| ⑥ | 같은 사이트에서 "안 올릴게요"·"내가 쓸게요" 3회 연속 | 주간 집계 | 중간(프롬프트 개선 신호) |
| ⑦ | 4주 무응답 / "원치않음" 접수 | 주간 집계 | 낮음(해지 예비군) |
| ⑧ | 하루 게시 상한 도달·사진 상한 반복 초과 시도 | 즉시 | 중간 |
- 문자는 하루 1회 묶음(높음은 즉시). 알림은 기존 `lib/notify.ts`로 회장님 번호에 보낸다.

### 4-4. 테스트 도구 — `/admin/story-lab`
- **AI 시험**: 사이트 고르고 → 글 붙여넣기(또는 음성 파일) → 초안·2차 검수 결과·사용 프롬프트를 나란히 표시. 설정값을 바꿔가며 즉시 비교. 게시 안 함.
- **대신 올리기**: 사이트 고르고 → 글·사진 → 게시(운영자 게시 표시 `posted_by:'admin'`). 사장님이 전화로 불러준 내용을 올릴 때, 그리고 시연·QA용. 회장님 결정 4에 따라 카톡 음성 컨시어지는 하지 않지만, 이 버튼은 QA를 위해 남긴다.
- **넛지 미리보기**: 사이트 고르면 이번 주 보낼 문구(응답/무응답 분기 반영)가 만들어져 복사 버튼 — A단계에서 회장님이 카톡에 붙여넣는 데 쓴다.

## 5. 데이터 · API 변경 목록 (수락 후 온팀장용)

테이블(마이그레이션 2개):
- `story_drafts` — v1과 같음 + `revise_count int default 0`, `mode text ('ai'|'self')`, `check_result jsonb`(2차 검수)
- `app_settings(key text pk, value jsonb, updated_at)` · `review_queue(id, site_id, story_entry_id?, draft_id?, rule text, severity, detail jsonb, status open/closed, created_at, closed_at, closed_by)`
- `story_entries`에 `updated_at`, `posted_by text default 'owner'` 두 열 추가(ALTER)

API:
- 사장님: `POST /api/story/voice`(녹음→초안) · `POST /api/story/draft`(글→초안) · `POST /api/story/revise`(1회) · `POST /api/story/decide`(게시/직접/폐기 → `story_entries` insert + revalidate) · **`PATCH /api/site/story`**(게시 후 수정·숨김, 신규)
- 운영자: `GET/POST /api/admin/settings` · `GET /api/admin/customers` · `POST /api/admin/customers/transfer-owner` · `GET/POST /api/admin/review` · `POST /api/admin/story-lab`
- 페이지: `/[slug]/story`, `/[slug]/story/[id]`, `/admin/settings/story`, `/admin/customers`, `/admin/review`, `/admin/story-lab`
- 변경 없음: `lib/schema.ts`(섹션 zod), 로그인 방식(이메일 유지), 스토리 섹션 렌더러(라벨만 config)

## 6. 서버 부하 · 비용 (사진 20장 기준 재계산)
- 사진 20장 × 250KB = 5MB/글. 주 1글이면 고객당 **연 260MB**(최대치). R2 저장 $0.015/GB-월 → 고객당 월 4원. 전송량은 R2 무료. 100곳이 전부 매주 20장씩 올려도 연 26GB.
- 업로드는 폰에서 줄여 보내므로 Vercel 함수 시간은 장당 1초 미만. 하루 게시 상한 10 × 20장 = 200장/사이트가 물리적 최대.
- AI: 초안 + 2차 검수 + 재수정 1회 = 건당 약 2원. 음성 60초 포함해도 3원.
- 결론: "서버 폭주"는 사진 수가 아니라 **한 사람이 반복 업로드하는 남용**에서 온다 → 사이트당 일일 상한·rate limit이 진짜 안전장치. 20장 상한은 독자 경험용이지 서버용이 아니다.

## 7. 리스크 · 아직 못 정한 것
- **안드로이드 카톡 안 녹음 불가**는 우리가 못 고친다(카카오 이슈). 명시 + Chrome 유도 + 글/사진 대안으로 간다. iOS 사장님과 Chrome 사장님이 먼저 녹음 데이터를 만든다.
- 카카오 로그인 후 `next` 리다이렉트: 현재 `/auth/callback`이 `next`를 받는지 확인 필요(온팀장 세션 1에서 확인).
- 2차 검수 AI도 놓칠 수 있다. 회장님 검토함이 마지막 방어선이라는 전제를 유지한다.
- 사진에서 얼굴·차량번호 등 개인정보: v1 범위 밖. P9 법무에서 "사진 올릴 때 타인 얼굴 주의" 안내 문구.

## 9. 회장님 확인 요청
1. 결정 4 해석: "카톡 안에서 녹음 안 됨"과 "카톡 음성메시지는 글이 안 됨" **둘 다** 명시하는 것으로 이해했다. 맞나?
2. 이메일 로그인: **막지 않고 뒤로 숨기기**(2-3 A안 + 운영자 소유자 변경 B안) 수락 여부
3. 사진 기본 노출 8장 + 상한 20장 수락 여부
4. 분량 기본 "보통(3~5문장·150~300자)" 수락 여부
5. 검토 알림 채널: 회장님 폰 **문자**(즉시) + 운영자 화면 배지 — 카톡 알림은 알림톡 개통 후
