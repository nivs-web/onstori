### ⚠ 목표를 왜 낮췄나 — 못 지킬 숫자를 걸어두지 않는다

처음 목표는 LCP 1.8초 · First Load JS 170KB 였다. **둘 다 지금 구조에서 도달할 수 없다.**

- **First Load JS 170KB**: 상호작용이 거의 없는 `/terms` 가 이미 **174KB** 다.
  Next 16 + React 런타임 자체이고 우리 코드가 아니다. 첫 페이지 179KB 중 우리 몫은 **5KB**.
  → 목표를 **179KB(현재값)** 로 낮춘다. 여기서 더 올라가면 우리가 뭔가 늘린 것이다.
- **LCP 1.8초**: 남은 무게는 한글 웹폰트 451KB 와 손님 사진이다.
  폰트는 한글 커버리지의 실제 값이라 **더 줄이지 않기로 확정**(2026-09-07).
  사진은 next/image·AVIF·sizes·lazy 가 전부 걸려 있다.
  → 목표를 **5.0초** 로 낮춘다.

**남은 개선 수단은 하나뿐이다: 위저드 250KB 의 단계별 코드 분할**(우리 몫 76KB).
그 밖의 수단은 §5-1 에 적어 뒀다.

## 1. 사진

- **히어로만** `next/image` + `priority` + `fetchPriority="high"`. **lazy 금지.**
  히어로는 LCP 요소다 — 늦게 부르면 그만큼 점수가 그대로 늦어진다.
- 히어로에 `.reveal`(fade-up)을 붙이지 않는다 — 투명하게 시작하면 LCP 가 늦게 찍힌다 (MOTION.md).
- **나머지 사진은 전부 lazy** + `width`/`height` 또는 `aspect-ratio` 고정.
  비율이 없으면 사진이 들어오는 순간 아래 내용이 밀린다(CLS).
- AVIF 우선, WebP 대체. `sizes` 로 폰에는 폰 크기만 내려보낸다 —
  `sizes` 를 안 주면 1920px 원본이 390px 화면으로 내려간다.
- 사진 카드는 4:3 고정(`.photo`).

## 2. 자바스크립트

- **지도 · 챗봇 · PayModal · 토스 SDK 는 `next/dynamic`** 으로 첫 화면 번들에서 분리한다.
  넷 다 "손님이 특정 행동을 해야" 쓰이는 것들이라 첫 화면에 있을 이유가 없다.
- 외부 스크립트는 `next/script` 의 `afterInteractive` 또는 `lazyOnload`.

## 3. 캐시

- **`[slug]` 는 ISR `revalidate 60`.** 손님 사이트는 매 요청마다 DB 를 볼 필요가 없다.
  발행 시 `revalidatePath` 로 즉시 갱신한다 — 이 둘은 **한 쌍이다.**
  revalidatePath 가 없으면 사장님이 발행하고도 최대 60초 동안 옛 화면을 본다.
- **R2 이미지 `Cache-Control: public, max-age=31536000, immutable`** (`lib/storage.ts`).
  키가 UUID 라 같은 주소의 내용이 바뀌지 않는다 — 다시 물어볼 이유가 없다.
  ⚠ 서명 PUT URL 에는 넣지 않는다. 서명에 포함돼 브라우저가 같은 헤더를 보내야만 성공한다.

## 4. 글꼴

- **Pretendard Variable 자체 호스팅** (`app/fonts.css`, `public/fonts/pretendard/`).
  `unicode-range` 로 92조각이라 브라우저는 실제 쓰는 3~6조각(100KB 안팎)만 받는다.
  `ascent-override: 92%` — 라틴 메트릭 그대로면 한글 행간이 뜬다.
- ★ **글꼴은 Pretendard 하나다. 명조(Noto Serif KR)는 2026-09-07 폐기했다** (CLAUDE.md 규칙 11).
  제목은 서체가 아니라 **굵기(700/600)와 자간**으로 낸다.
  **`Noto Serif` 참조가 코드에 다시 생기면 안 된다** — 2026-09-07 실측 확인: 코드 참조 0건.
  ⚠ 아래는 명조를 쓰던 시절의 기록이다. **되살리라는 뜻이 아니라, 되살릴 때 무엇을
  다시 밟게 되는지 남겨 둔 것이다.**
  - 폰트를 `globals.css` 의 `@import` 로 부르지 않는다 — CSS → 구글 CSS → 폰트 파일로
    이어지는 **렌더 차단 사슬**이라 LCP 를 그대로 늦춘다. (그래서 `next/font/google` 로 옮겼었다.)
  - 한글 세리프는 글리프가 커서 `preload` 하면 히어로 사진과 대역폭을 다툰다.
  - v5 시작 대비 **빌드 폰트 산출물 6.4MB → 64KB.** 명조를 뺀 것이 그 대부분이다.

## 5. CLS (화면이 튀지 않게)

- 상단 프로모 띠 · D-day 띠는 **높이를 CSS 로 고정**한다. 조건부로 나타나면 아래가 통째로 밀린다.
- 모든 사진에 비율 고정.
- 폰트는 `display: swap` — 글자가 안 보이는 구간을 만들지 않는다.

## 5-1. First Load JS — 왜 170KB 를 못 넘는지 (2026-09-07 실측)

gzip 전송량 기준:

| 페이지 | First Load JS | 비고 |
|---|---|---|
| `/terms` | **174KB** | 상호작용이 거의 없는 페이지 — **이게 바닥이다** |
| `/` 첫 페이지 | **179KB** | 바닥 + 5KB (헤더·질문위젯·포트폴리오탭·폰프레임) |
| `/barun` 손님 사이트 | **180KB** | 바닥 + 6KB |
| `/new` 위저드 | **250KB** | 바닥 + 76KB (5단계 폼·로고 생성·플레이스 검색) |

**174KB 는 Next 16 + React 런타임 자체다.** 우리 코드가 아니다.
그래서 **목표 170KB 는 지금 구조에서 도달할 수 없다** — 우리 코드를 0 으로 만들어도 174KB 다.

남은 수단(효과 순):
1. 첫 페이지의 클라이언트 부품 4개를 서버 컴포넌트로 — 최대 **5KB**. 노력 대비 효과가 없다.
2. 위저드 250KB → 단계별 코드 분할. **76KB 중 상당 부분**을 뒤로 미룰 수 있다. 효과가 제일 크다.
3. Next 버전을 올려 런타임이 줄기를 기다린다 — 우리가 할 수 있는 게 없다.

⚠ Lighthouse 는 같은 페이지를 **231KB** 로 잡는다. 스크립트 요청의 전송량 합계라
헤더·비압축 응답이 섞인다. 위 표는 `Accept-Encoding: gzip` 으로 실제 받은 바이트다.
**둘 중 실제 손님이 받는 값은 위 표다.**

## 5-2. ★ 손님 사이트 섹션은 «서버 컴포넌트»다 — 이 경계를 함부로 넘지 마라 (2026-09-10 회장님)

> **손님 사이트 섹션은 서버 컴포넌트다. 클라이언트 기능을 넣으면 그 사이트만이 아니라
> 섹션을 쓰는 모든 사이트가 무거워질 수 있다. V-2 릴 화면은 이 경계를 먼저 정하고 시작한다.**

### 왜 이게 중요한가

`components/sections/index.tsx` 에는 **`"use client"` 가 없다.** 그래서 섹션 렌더러 코드는
손님 브라우저로 **아예 가지 않는다** — 서버에서 HTML 로 그려져 나갈 뿐이다.
덕분에 2026-09-10 에 영상 섹션을 넣으면서도 **영상 없는 사이트의 전송량이 0바이트**였다.

⚠ **이 성질은 쉽게 깨진다.** 아래를 하나라도 넣으면 그 파일이 클라이언트 번들로 끌려 들어가고,
  그 순간 **영상이 없는 사이트까지** 그 JS 를 받는다:

| 넣으면 깨지는 것 | 왜 |
|---|---|
| 자동재생·음소거 자동재생 | 재생 제어에 JS 가 필요하다. 게다가 **손님이 사이트에 들어오자마자 사장님 목소리가 나면 그 자리에서 나간다**(2026-09-10 회장님) |
| 직접 만든 재생 버튼·진행 막대 | `<video controls>` 는 브라우저가 공짜로 준다. 직접 만들면 JS 다 |
| 가로 밀기·세로 스와이프(릴 화면) | 손가락 제스처는 JS 없이 안 된다 — **V-2 의 핵심 과제가 정확히 이것이다** |
| `useState`·`useEffect`·`onClick` 어느 하나라도 | 그 파일 전체가 클라이언트가 된다 |

### V-2 릴 화면을 시작하기 전에 정할 것

릴 화면은 JS 가 **반드시** 필요하다. 그러니 시작 전에 이것부터 정한다:

1. **어디까지 서버 컴포넌트로 두나** — 영상 한 편을 그냥 보여주는 자리는 지금처럼 서버로 둔다
2. **어디부터 클라이언트인가** — 릴 화면은 `components/sections/index.tsx` 를 건드리지 말고
   **별도 파일**(`"use client"`)로 떼어내고, 그 파일은 **릴을 쓰는 사이트에서만** 불린다
   (`next/dynamic` 으로 늦게 불러오는 것까지 포함해 정한다)
3. **재는 법** — 릴이 없는 사이트의 JS 가 1바이트도 안 늘었는지 전후로 잰다

⚠ 이 셋을 정하지 않고 index.tsx 안에서 시작하면, **릴을 안 쓰는 사장님 사이트까지** 무거워진다.
  되돌리기 어려운 종류의 실수다.
