### 1~3. 감사 제출 — **찍을 수 있는 상태**가 됐다

| # | 무엇 | 결과 |

| 1 | 데모(심사) 사이트 | **`sample-interior`** — 영상 12편 보유, 홈페이지에 한 편 **발행 완료**(실측) |
| 2 | 게이트 | **`review` + 허용 목록 [sample-interior]** · `auditPassed` 는 **꺼진 채** |
| 3 | 스크린샷 4종 | 경로 전부 확인 — 아래 |

**왜 `sample-interior` 인가**
- 진짜 사장님 사이트가 아니다 (`owner_id`·`anon_id` 둘 다 null → **운영자만 편집**)
- **인스타 심사 때 쓰던 그 사이트**라 심사관이 볼 화면이 이미 손질돼 있다(인스타 연결 active)
- 전화번호도 이미 `010-0000-0000` 으로 안전하다

**허용 목록이 실제로 듣는다 (실측)**

| 사이트 | 유튜브 |
|---|---|
| `sample-interior` | ✅ ok · 비공개로 올라간다는 안내 포함 |
| `barun`(진짜 사장님) | ❌ 「준비 중」 |
| `interior2`(진짜 사장님) | ❌ 「준비 중」 |

**찍기 전 확인한 것**
- 구글 동의 주소가 나오고 **로그인 화면까지 열린다** — `redirect_uri_mismatch`·`invalid_client` 없음
- `redirect_uri = https://onstori.com/api/sns/callback/youtube` · `scope = youtube.upload`
- `/privacy` 에 **YouTube API Services 문단** 있음
- ★ 심사관 화면에 뜰 **조사 오류**를 고쳤다 — 「유튜브 쇼츠**을** 먼저 연결」 → 「쇼츠**를**」

### 4. 신청서 6번 「Demo Account」 — ★ **이미 만들어져 있었다**

회장님 확인: 심사관 로그인은 어제 만들었고 Vercel 에 열쇠도 넣었다. 찾아서 확인했다.

| 항목 | 결과 |
|---|---|
| 주소 | **`onstori.com/login/review`** |
| 살아 있나 | ✅ **HTTP 200** — 열쇠(`REVIEW_ID`·`REVIEW_PASSWORD`)가 운영에 들어 있다 |
| 안전장치 | 열쇠가 없으면 **404**(없는 길) · 그 아이디 하나만 · 10분 5회·24시간 30회 제한 · 시간일정 비교 |

⚠ **그런데 막히는 것이 하나 더 있었다** — 그 계정이 **가진 사이트가 하나도 없다.**
저장소의 모든 사이트가 익명·운영자 소유라, 심사관이 로그인해도 **빈 화면**을 본다.
심사는 「이 앱이 정말 그 일을 하는가」를 보는 것이라 빈 화면은 곧 반려다.

★ 그래서 로그인 끝에 **심사용 사이트를 그 계정에 붙이는 걸음**을 넣었다. 조건을 좁게 걸었다:
  ① `REVIEW_SITE` 가 **있어야** 한다(없으면 아무 일도 안 한다)
  ② 그 사이트의 주인이 **아직 없을 때만** 붙인다 — 남의 사이트를 빼앗지 않는다
  ③ 붙이기에 실패해도 **로그인은 안 막는다**

### ⚠⚠ 회장님이 Vercel 에 **한 줄 더** 넣으셔야 합니다

```
REVIEW_SITE = sample-interior
```

넣고 Redeploy 하면, 심사관이 `/login/review` 로 들어오는 순간
그 사이트가 그 계정 것이 되고 — 편집화면·연결·올리기를 전부 해 볼 수 있습니다.
