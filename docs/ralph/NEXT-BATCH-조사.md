## 1. 위저드에서 사진을 몇 장까지 받는가

**받지 않는다 (0장).** 위저드의 파일 입력은 **로고 1장뿐**이다.
- `app/new/wizard.tsx:398` — `type="file"` 이 파일 전체에 **딱 하나**, 로고용이다.
- 사이트 사진은 위저드가 아니라 **에디터**에서 섹션마다 한 장씩 올린다
  (`app/[slug]/edit/ui.tsx:573` → `/api/site/upload`).

**15장 상한을 걸려면 고칠 곳 3군데:**
| 무엇 | 파일 | 지금 |
|---|---|---|
| 위저드에 사진 단계 추가 | `app/new/wizard.tsx` | 단계 자체가 없다 |
| 업로드 API 를 여러 장으로 | `app/api/site/upload/route.ts` | 한 번에 `file` 1개만 받는다 |
| 상한 상수 | (신설) `config/` | 견적 폼은 `MAX_PHOTOS=3`(`components/sections/quote-form.tsx:19`), 스키마는 갤러리 30장·이야기 10장(`lib/schema.ts:49,168`) |

⚠ 상한이 지금 **세 곳에 흩어져 있다**(3 / 30 / 10). 15장을 새로 걸면 네 번째가 된다.
→ `config/` 에 한 곳으로 모으는 것을 같이 하는 게 낫다.

**예상 시간: 4~6시간** (위저드 단계 1개 + 다중 업로드 + 진행률 표시 + 상한 단일화)

## 2. 업로드된 이미지를 Gemini 로 분석하는 코드가 있는가

**없다.** 이미지를 **만드는** 코드만 있고 **읽는** 코드는 없다.
- `lib/vertex.ts:211` — 응답에서 이미지를 **꺼내는** 쪽(`inlineData`)만 있다.
- 보내는 쪽은 `parts: [{ text }]` 뿐이다(`scripts/bank-generate.ts:95`).

**붙이는 자리는 이미 있다.** `vertexGenerate()` 가 `contents` 를 그대로 넘기므로
`parts` 에 `{ inlineData: { mimeType, data: base64 } }` 를 얹기만 하면 된다.
새 함수는 필요 없고 `lib/vertex.ts` 에 얇은 래퍼 하나면 충분하다.

붙일 위치 후보: `/api/site/upload` 가 사진을 받은 직후(WebP 변환 뒤 그 buffer 를 그대로 쓴다).
쓸 곳: 사진 자동 분류(현관/거실/주방…), 대체텍스트 자동 생성, 부적절 사진 걸러내기.

⚠ 사진 15장이면 호출도 15번이다. 비용·시간을 먼저 재야 한다.

**예상 시간: 3~4시간** (래퍼 + 분류 프롬프트 + 실측 1회)

## 3. 영상 업로드가 지금 가능한가 · 릴에도 쓸 수 있는가

**가능하다. 이미 돌고 있다.**
- `/rec` 이 브라우저 `MediaRecorder` 로 찍고(`app/rec/[slug]/rec-client.tsx:113`)
- `/api/story/upload-url` 이 R2 서명 URL 을 내주면 브라우저가 **R2 로 직접** 올린다.
  (Vercel 함수 본문 한도 4.5MB 를 피하려고 이렇게 했다)
- 저장 위치: **`private` 버킷** `stories/{slug}/{uuid}.webm`
- DB: `story_entries.video_key` · `media_status`(none→uploaded→processing→ready→failed)

**릴에 쓸 수 있나 — 경로는 그대로 쓸 수 있지만 한 가지가 막힌다.**
지금 영상은 **비공개 버킷**이다. 손님 사이트에 걸려면
① 공개 버킷으로 옮기거나 ② 서명 URL 을 매번 발급해야 한다.
`storage.put("media", …)` 로 공개 버킷에 넣는 길은 이미 있다(`lib/storage.ts`).
`video_out_key`(가공 결과) 컬럼도 이미 있고 **아직 아무도 안 쓴다.**

**예상 시간: 2~3시간** (공개 경로 + 손님 사이트 릴 섹션 렌더러 + 스키마 4곳 동시 수정)

## 4. 세로 영상을 웹용으로 변환할 수단이 있는가

**저장소에는 없다. 이 PC 에는 있다.**
- `package.json` 에 ffmpeg 계열 의존성 **0개**. 있는 건 `sharp`(이미지 전용)뿐.
- 이 작업 PC 에는 ffmpeg 9.0 이 깔려 있다(winget). **서버에는 없다.**
- 자막 워커(STEP 4)는 아직 **미착수** — `media_status` 를 `processing`→`ready` 로
  넘기는 코드가 없다. 지금은 `uploaded` 에서 멈춘다.

**즉, 720×1280 H.264 변환도 표지 프레임 추출도 지금은 못 한다.**

수단 3가지:
| 방법 | 장점 | 단점 |
|---|---|---|
| Vercel 함수에서 ffmpeg-wasm | 서버 추가 없음 | 60초 영상엔 너무 느리다(함수 시간 한도) |
| 별도 워커(내 PC·작은 서버)에서 ffmpeg | 빠르고 확실 | 사람이 켜 둬야 한다 |
| 외부 변환 서비스 | 손 안 댐 | 월 비용 · 업체 선택 필요 |

⚠ **이건 결정이 필요한 항목이다.** 셋 중 무엇으로 갈지 정해야 견적을 낼 수 있다.

**예상 시간: 방법이 정해진 뒤 6~10시간** (워커 + 상태 전이 + 실패 재시도)
