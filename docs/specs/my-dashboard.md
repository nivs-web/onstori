작성 2026-09-07 · **구현 전 · 회장님 승인 대기** · 코드 변경 0

## 0. 실측 결과

### 0-1. `/my` 는 지금 무엇을 보여주는가

**이미 있다.** 빈 화면이 아니다. 코드 경로:

| 파일 | 하는 일 |
|---|---|
| `app/my/page.tsx` (117줄) | 서버 컴포넌트. 세션 확인 → `sites` 를 `owner_id` 로 조회 → 목록 |
| `app/my/ui.tsx` (91줄) | 로그아웃 버튼 · 구독 해지 버튼 |

지금 화면에 있는 것:
- 헤더(온스토리 로고 + 로그아웃)
- "내 홈페이지" 제목 + "○○님으로 로그인했어요"
- 사이트가 없으면 → 안내 + **[홈페이지 만들기 — 무료]** 큰 버튼 (이미 있다)
- 사이트가 있으면 → 한 줄짜리 카드 목록. 카드 안: **상호 · onstori.com/slug · 무료 D-n / 정회원 / 정지됨**
- 버튼: **[사이트 보기] [수정하기]**
- 정회원이면 **[구독 해지]** (전자상거래법 제21조의2 — 없애면 안 되는 버튼이다)

⚠ 프로덕션에서 화면 캡처는 못 했다. 회장님 크롬에는 **운영자 쿠키만** 있고 고객 계정 세션이 없어
`/my` 가 `/login?next=%2Fmy` 로 튕긴다. 위 내용은 코드를 읽어 확인했다.

### 0-2. 로그인 후 자기 홈페이지를 고치러 가는 경로 — 몇 단계인가

**주소창에 `/edit` 를 직접 칠 필요는 없다.** 이미 길이 있다.

| 출발 | 단계 |
|---|---|
| 헤더 "마이페이지"(로그인 상태) | `/my` → **[수정하기]** = **2번 누름** |
| 헤더 "로그인"(비로그인) | `/login?next=/my` → 로그인 → `/my` → [수정하기] = 로그인 + **2번 누름** |
| **주소창에 `onstori.com/login` 을 직접 침** | 로그인 → **첫 페이지(랜딩)로 떨어진다** ← ⚠ 여기가 구멍 |

구멍의 정체는 `app/login/ui.tsx:8` 의 `safeNext()` 다. `next` 파라미터가 없으면 `/` 로 보낸다.
헤더를 눌러 들어오면 `next=/my` 가 붙어 괜찮지만, **주소를 직접 치거나 옛 북마크로 들어오면 랜딩에 떨어져
사장님이 자기 홈페이지를 어디서 고치는지 알 길이 없다.** 고칠 곳은 한 줄이다 — 기본값을 `/my` 로.

### 0-3. 한 계정 = 사이트 1개 구조인가

**아니다. 지금 코드에는 계정당 사이트 개수 제한이 전혀 없다.**

- `app/api/generate/route.ts` 가 확인하는 것은 두 가지뿐이다: **IP 기준** 시간·일일 한도(`GENERATE_LIMITS`)와 **전사 월간** 생성 상한(`MONTHLY_SITE_CAP`).
- `owner_id` 는 **기록만** 하고(80행), "이 사람이 이미 사이트를 갖고 있나"는 **묻지 않는다.**
- `app/my/page.tsx:33-38` 도 `.eq("owner_id", user.id)` 로 **전부** 가져와 `sites.map()` 으로 **전부** 그린다. 개수 제한이 없다.

즉 회장님이 말씀하신 "최대 1개" 는 **아직 규칙이 아니라 의도**다. 만들어야 하는 것이지 이미 있는 게 아니다.

### 0-4. 결제 — 있는 것과 없는 것

⚠ **회장님 지시문의 전제 하나가 실제와 다릅니다.**
"카드 관리·정기결제는 **빌링키가 없어** 지금 못 만든다" 고 쓰셨는데, **빌링키 코드와 표는 이미 다 있습니다.**
막고 있는 것은 빌링키가 아니라 **Vercel 환경변수 `TOSS_*` 가 안 들어가 있는 것**입니다(토스 가맹 전).

| 항목 | 있나 | 근거 |
|---|---|---|
| 빌링키 발급(카드 저장) | **있다** | `app/api/billing/subscribe/route.ts` → `lib/toss.ts` `issueBillingKey()` |
| 빌링키 저장 | **있다** | `billing` 표 — `billing_key` · `card_company` · `card_last4` · `next_charge_at` · `fail_count` (마이그레이션 `20260906120000`, 적용 완료) |
| 정기결제(매달 자동 청구) | **있다** | `charge()` + `billing_due_idx` + `app/api/cron/expire` |
| 결제 원장 | **있다** | `payments` 표 (전자상거래법 5년 보존 고려해 사이트 삭제와 분리) |
| 구독 해지 | **있다** | `/api/billing/cancel` + `/my` 의 [구독 해지] |
| **고객이 결제 내역을 보는 화면** | **없다** | `payments` 를 읽는 곳은 `/admin/dashboard`·`/admin/members` **둘뿐**이다 |
| **고객이 카드를 바꾸는 화면** | **없다** | 발급은 되는데 교체 흐름이 없다 |
| 실제 결제 동작 | **안 된다** | `TOSS_CLIENT_KEY` 없음 → `/api/billing/checkout` 이 `ready:false` → 모달이 "결제 준비 중" 안내만 |

**따라서 [결제 문의] 로 둘 필요가 없습니다.** 버튼은 처음부터 [결제] 로 만들고,
`ready:false` 인 동안에만 "결제 준비 중" 안내가 뜨게 하면 됩니다 — 그 분기는 `components/site/pay-modal.tsx` 에 **이미 구현돼 있습니다.**
`TOSS_*` 를 Vercel 에 넣는 날 화면은 **한 줄도 안 고치고** 진짜 결제로 바뀝니다.

### 0-5. v5 토큰 부채

`app/my/page.tsx`·`ui.tsx` 는 [C] 루프 때 변환되지 않았다. 지금도 옛 토큰을 쓴다:
`--paper` · `--ink` · `--muted` · `--accent` · `--forest` · `--terra` · `--green` · `--line`.
규칙 11 은 `--text-strong`/`--text`/`--text-soft` 의미 토큰만 쓰게 돼 있다.
특히 `--muted` 는 `--text` 로 재지정돼 있어 지금 당장 깨져 보이진 않지만, **이 화면은 v5 검사(contrast.js)를 한 번도 통과한 적이 없다.**

| 버튼 | 가는 곳 | 모양 |
|---|---|---|
| **수정하기** | `/{slug}/edit` | **주 버튼(초록 면).** 뷰포트당 1개 규칙에 맞게 이것 하나만 초록 |
| 보러가기 | `/{slug}` (새 창) | 보조 — 연회색 **면**(테두리 아님, 규칙 11) |
| **결제** | 결제 모달(`pay-modal`) | 보조. ★ **[결제 문의] 가 아니다**(2026-09-07 회장님 확정) |

★ **[결제] 로 만드는 이유** — 빌링키·정기결제·원장이 이미 다 있고(0-4), 막는 건 Vercel 의 `TOSS_*` 뿐이다.
`components/site/pay-modal.tsx` 는 서버가 `ready:false` 를 주면 **"결제 준비 중" 안내**를 대신 띄우는
분기를 이미 갖고 있다. 그래서 지금 [결제] 로 만들어 두면 —

- 오늘: 눌러도 "결제 준비 중입니다. …수동으로 정회원 처리해 드립니다" 안내가 뜬다. 손해가 없다.
- `TOSS_*` 를 넣는 날: **화면을 한 줄도 안 고치고** 같은 버튼이 진짜 카드 등록창을 연다.

[결제 문의] 로 만들면 그날 버튼 이름·연결·안내를 전부 다시 손봐야 한다. 일을 두 번 하게 된다.

정회원이면 [결제] 자리는 **[결제 관리]** 로 바뀌고, 그 안에 `card_company`·`card_last4`(끝 4자리) 표시 + [구독 해지].
빌링키 자체는 절대 화면에 내보내지 않는다(`billing` 표 주석).

**P5 이후 무엇으로 바뀌는가:** `TOSS_*` 가 Vercel 에 들어가면 **화면은 그대로**이고 `checkout` 이 `ready:true` 를 주기 시작해
같은 [결제] 버튼이 진짜 카드 등록창을 연다. 그 뒤에 더할 것은 두 개뿐이다 —
① **결제 내역**(`payments` 를 고객 자기 것만 읽는 API + 카드 안 접이식 목록) ② **카드 교체**(빌링키 재발급 후 `billing` upsert).

### 1-5. 사이트는 1개만 — 회장님 지시(2026-09-07) 반영

지금은 제한이 없다(0-3). 두 곳을 막는다.

1. **만들 때** — `app/api/generate/route.ts` 에서 로그인 상태면 `owner_id = user.id` 인 사이트가
   이미 있는지 먼저 본다. 있으면 만들지 않고 409 를 준다. 화면은 안내 + **[내 홈페이지로]** 버튼(`/my`).
   문구(회장님 지정, 그대로 쓴다):
   > **한 계정에 홈페이지 하나입니다. 두 개가 필요하시면 계정을 하나 더 만들어 주세요.**

   ⚠ **비로그인(익명) 생성은 막지 않는다.** 지금 온보딩은 로그인 없이 만들고 나중에 귀속(claim)하는
   구조다. 여기서 막으면 신규 가입이 통째로 끊긴다.
   ⚠ 귀속(claim) 시점에도 같은 검사를 넣어야 한다. 안 그러면 "익명으로 만든 뒤 로그인" 으로 우회된다.

2. **보여줄 때** — `/my` 는 카드를 **1장만** 그린다(`updated_at` 최신 1개).

### 1-5-1. ★ 지금 2개 이상 가진 계정 조회 결과 — **0개다. 정리할 것이 없다**

2026-09-07 프로덕션 DB 실조회:

```
전체 사이트 8곳 · 소유 계정 0개
  owner_id 가 비어 있는(익명) 사이트 8곳:
```

8곳 **전부 `owner_id` 가 `null`** 이다 — 우리가 운영자로 만든 전시·시험용 사이트라 주인이 없다.
따라서 **1계정 1사이트 규칙을 지금 넣어도 기존 회원 중 걸리는 사람이 한 명도 없다.** 지금이 넣기 가장 좋은 때다.

**정리 방법 제안(실행하지 않음 — 회장님 결정 사항):**
- **아무것도 하지 않는다(권장).** 걸리는 계정이 없으므로 정리 자체가 불필요하다.
- 굳이 한다면, 이 8곳은 회장님 운영자 계정에 귀속시켜 `/my` 에서도 보이게 할 수 있다.
  다만 그러면 **회장님 계정이 곧바로 1계정 1사이트 규칙을 어기는 유일한 계정**이 된다.
  운영자 계정은 규칙에서 빼는 예외를 두거나(코드가 복잡해진다), 지금처럼 주인 없이 두는 편이 낫다.
- ⚠ 어느 쪽이든 **사이트를 지우는 선택지는 없다**(규칙 10, herotest 보존 지시).

## 2. 두 건 합계 — 10.7h

순서는 **어드민 껍데기 → `/my`** 를 권한다. 껍데기에서 만드는 `min-w-0`·서랍·현재 위치 표시가
`/my` 에서 다시 쓰이지는 않지만, 어드민 쪽이 지금 **막다른 길 4개**로 실제 운영에 더 걸리기 때문이다.
