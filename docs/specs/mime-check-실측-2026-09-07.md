## 2. ★ 카톡 인앱에서 「영상 + 소리」도 되는가 — **시험 버튼을 추가했다. 확인 대기**

### 왜 ①로는 알 수 없나

①(검사 시작)은 **캔버스를 녹화**한다. 그래서 권한 창이 안 뜨고 **마이크는 아예 건드리지 않는다.**
카톡 인앱에서 ①이 mp4 로 나왔다는 것이 「마이크도 된다」는 뜻이 **아니다.**
회장님 지적대로 예전에 카톡 인앱 WebView 가 마이크를 막은 전례가 있다.

### 추가한 것 — `public/mime-check.html` §③ 「소리 포함 녹화 시험」

`getUserMedia({ audio: true, video: true })` 로 **진짜 마이크 권한을 요청**하고 2초 녹화한다.
세 가지를 따로 본다:

| 보는 것 | 판정 |
|---|---|
| ⓐ 권한이 떨어지는가 | 실패하면 오류 이름을 그대로 보여준다. **`NotAllowedError` 면 브라우저가 막은 것** |
| ⓑ 오디오 트랙이 실제로 붙는가 | `getAudioTracks().length` · 마이크 이름 |
| ⓒ 그 상태로도 mp4 가 나오는가 | 파일 머리 `ftyp` 확인 |

⚠ 트랙이 1개 있어도 **2초에 8KB 미만이면 「너무 작다」로 경고**한다 —
트랙만 붙고 실제로는 안 담기는 경우가 있어서다.

**회장님: 카톡으로 다시 들어가 ③ 버튼을 눌러 주십시오.** 결과를 그대로 보내 주시면 판단하겠습니다.

## 3. 구형 안드로이드 폴백 — **분기가 코드에 없다. V-1 목록에 넣는다**

`app/rec/` 전체를 훑었다. **`capture` 를 쓰는 곳이 하나도 없다.**

지금 코드(`rec-client.tsx:67`)는 이렇게만 돼 있다:

```js
const c = ["video/mp4;codecs=avc1", "video/webm;codecs=vp9,opus", ..., "video/mp4"];
for (const m of c) if (MediaRecorder.isTypeSupported(m)) return m;
```

즉 **mp4 가 안 되면 조용히 webm 으로 내려간다.** 폰 기본 카메라로 넘어가지 않는다.
webm 으로 찍히면 아이폰 손님에게 검은 화면이 된다 — 지금은 그걸 변환 워커가 받아야 한다는 뜻이다.

### V-1 에서 만들 것 (아직 안 만들었다)

| # | 무엇 |
|---|---|
| 1 | `pickMime()` 이 **mp4 계열을 하나도 못 찾으면** MediaRecorder 경로를 포기하고 `<input type="file" accept="video/*" capture="user">` 로 전환 |
| 2 | 그 경로에서는 실시간 안내를 띄울 수 없다 → **촬영 가이드 12문장을 「촬영 전 카드」로** 먼저 보여준다 (회장님 지시) |
| 3 | `MediaRecorder` 자체가 없는 브라우저도 같은 갈래로 보낸다 |
| 4 | 어느 경로로 찍었는지 서버 로그에 남긴다 — 안 남기면 나중에 재현이 안 된다 |

⚠ 이 폴백으로 들어온 파일은 **아이폰이면 `.mov`(HEVC 일 수 있다)** 가 나온다.
그때는 변환이 필요하다 — §4 의 예외가 바로 이것이다.

## 4. 변환 워커가 필요한가 — **한 줄 판단**

> **브라우저 녹화 경로는 안드로이드·아이폰 모두 mp4 이므로 변환 워커가 필요 없다. 자막 워커만 남는다.**
> **단, 폰 기본 카메라 폴백(§3)으로 들어오는 아이폰 `.mov`/HEVC 는 예외라 그 한 갈래만 변환이 남는다.**

### ✅ 확정 (2026-09-09) — **변환 워커는 만들지 않는다**

아이폰 사파리 실측(§2-1)으로 조건 1이 해소됐다. 조건 2(폰 기본 카메라 .mov)는
**변환이 아니라 «그 갈래를 안 보여주는 것»으로 푼다.** 자막 워커는 별개이며 계획대로 간다.

### V-1 설계에 그대로 넣을 것 — 회장님 지시 5줄 (2026-09-09)

| # | 무엇 | 왜 |
|---|---|---|
| 1 | **아이폰에서는 「폰 카메라로 찍기」 대체 경로를 보여주지 않는다.** 브라우저 녹화만 | 아이폰 카메라는 .mov 를 내놓는다. 그 하나 때문에 워커를 만들 이유가 없다 |
| 2 | 안드로이드는 브라우저 녹화 우선, 실패하면 폰 카메라 | 안드로이드는 폰 카메라도 mp4 다 |
| 3 | 아주 오래된 아이폰이라 브라우저 녹화가 안 될 때만 「사파리로 열어 주세요」 안내 | 막다른 길을 만들지 않는다 |
| 4 | **업로드받을 때 형식을 확인해 mp4 가 아니면 「다시 찍어 주세요」로 되돌린다** | 조용히 받아서 나중에 재생이 안 되는 것이 최악이다 |
| 5 | MediaRecorder mimeType 은 `video/mp4;codecs=avc1` 로 지정한다 | `h264` 로 쓰면 `isTypeSupported` 가 false 를 낸다 — 확인된 함정 |

## 5. 카톡으로 녹화 링크 보내기 — 조사만 (⚠ **발송비 0원이 아니다**)

지금은 `app/api/story/send-link` 가 **솔라피 문자(SMS/LMS)** 를 쓴다.

### ★ 먼저 바로잡을 것 — 알림톡도 건당 과금이다

회장님께서 「발송비 0원」이라 하셨는데 그건 사실과 다르다.
**알림톡은 건당 과금**이고, 다만 **문자보다 싸다.**

| | 대략 단가 | 성격 |
|---|---|---|
| SMS(단문) | 8~20원대 | 지금 쓰는 것 |
| **알림톡** | **6~9원대** | 정보성만 · 템플릿 심사 필요 |
| 친구톡 | 알림톡보다 비쌈 | 광고성 가능 · **채널 친구만** |

즉 **「0원」이 아니라 「문자보다 30~50% 싸다」** 가 맞다. 그래도 바꿀 이유는 된다.

### 조건 (다 갖춰야 보낼 수 있다)

1. **카카오톡 채널 개설** + 사업자등록증으로 **비즈니스 채널 인증**
2. **발신프로필 등록** (솔라피가 대행한다 — 지금 쓰는 솔라피 그대로 쓸 수 있다. 새 업체 불필요)
3. **템플릿 사전 심사** — 문구를 미리 등록해 승인받아야 한다. 보통 영업일 1~3일.
   변수는 `#{이름}` 꼴로만. **승인된 문구 밖으로 한 글자도 못 나간다**
4. 내용이 **정보성**이어야 한다. 「사장님이 요청하신 녹화 링크」는 정보성이라 **적합하다**

### 제약 (이게 결정적이다)

- **수신자가 카카오톡 사용자여야 한다.** 아니면 발송 실패다
- 그래서 실무에서는 **실패 시 문자 대체발송(LMS)** 을 반드시 켠다
  → **솔라피 문자는 없앨 수 없고, 백업으로 계속 남는다**
- 채널 차단·탈퇴한 사람에게는 안 간다
- 광고성 문구를 섞으면 반려된다 (「지금 결제하시면」 같은 말 금지)

### 판단

**바꿀 값은 있다** — 단가가 싸고, 카톡은 링크 클릭률이 문자보다 확실히 높다.
**다만 「문자를 없애는 것」이 아니라 「카톡 먼저, 실패하면 문자」 2단 구조가 된다.**
`send-link` 라우트에 그 갈래를 하나 더 두는 일이고, 채널 인증·템플릿 승인이 선행돼야 한다.

⚠ **지금 바꾸지 않았다** (회장님 지시). 착수하려면 채널 개설·인증이 먼저다 — 그건 회장님 몫이다.

## ★ 2026-09-07 추가 실측 — 카톡 인앱에서 **소리 포함 녹화 성공**

회장님이 **안드로이드 + 카카오톡 인앱 브라우저**에서 링크를 눌러 §③ 시험을 돌리셨다.

> **「✅ 소리 포함 녹화됩니다」**

### 이게 왜 큰 관문이었나

카톡 인앱 WebView 가 예전에 마이크를 막은 전례가 있었다. 막혔다면
**두 번째 영상부터(소리가 들어가는 영상) 카톡으로 받은 링크에서는 녹화가 불가능**했다.
사장님 대부분이 카톡으로 링크를 받는다는 것을 생각하면 제품의 목줄이었다.

**그 관문을 넘었다.** 이제 안드로이드 쪽은 형식(mp4)·소리 둘 다 확인됐다.

| 경로 | 형식 | 소리 |
|---|---|---|
| 카카오톡 인앱 | ✅ mp4 | ✅ **된다** |
| 크롬 | ✅ mp4 | (인앱이 되면 크롬은 당연히 된다) |
| 네이버 | ✅ mp4 | 〃 |
| 폰 기본 카메라 | ✅ `video/mp4.mp42` | 해당 없음 |

⏸ **아이폰 사파리는 오늘 밤 확인 예정.** 그 결과가 나오면 §4 판단이 확정된다.
