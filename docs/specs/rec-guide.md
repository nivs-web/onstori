작성 2026-09-06 (기술참모) · 파일 **1개**(`app/rec/[slug]/rec-client.tsx`) · 스키마 변경 없음 · DB 변경 없음

## 0. 왜 작은가

회장님 지시는 "**기존 `/rec/` 라우트에 문구·가이드를 추가**"다. 새 화면도, 새 라우트도, 새 컴포넌트 파일도 만들지 않는다.
`rec-client.tsx`(19,058 B) **한 파일 안에서** 끝난다. A/B·E·F 와 겹치는 부분이 없어 **언제든 끼워 넣을 수 있는 작업**이다.

## 1. 지금 `/rec` 이 어떻게 생겼나 (사실)

`app/rec/[slug]/rec-client.tsx` — `Screen` 9단계:

```
greet → ask → mode → setup → count → rec → review → sending → done   (+ error)
```

| 화면 | 줄 | 지금 내용 |
|---|---|---|
| `greet` | 155~171 | "안녕하세요, {상호명} 사장님" · "오늘 질문 하나에 60초만…" · 칩 3개(글쓰기 금지·이 링크가 로그인·앱 설치 없음) · 카톡 인앱 경고 · **[시작하기]** 버튼(170) |
| `ask` | 174~187 | 질문 4장(`QuestionShuffle`) + 직접 입력 |
| `mode` | 190~206 | 질문 표시 + **영상으로 / 음성만** 선택 + [카메라·마이크 켜기] |
| `setup` | 209~ | 카메라 미리보기 3:4 |
| `rec` | — | `MAX_SEC = 60` 자동 정지 |

접근은 문자 링크뿐이다 — `app/[slug]/edit/story-link.tsx` 의 [녹화 링크 문자로 받기] → `/api/story/send-link` → 솔라피.
링크 서명(`?k=`)이 곧 로그인이라 `/rec` 은 로그인 화면이 없다(`app/rec/[slug]/page.tsx:17`).

**참고 구조:** 레멘토(web.remento.co)는 녹화 전에 "이렇게 찍으면 됩니다" 한 화면을 따로 둔다.
Blaze(app.blaze.ai)는 각 연결 모달 안에 노란 "지침" 박스를 접어 두고 그 안에 단계 안내를 넣는다(회장님이 보내신 캡처 5장).
**우리는 화면을 늘리지 않고**(9화면을 10화면으로 만들면 60초 약속이 무거워진다) **접었다 펴는 안내 박스**로 간다 — 구조만 참고, 화면·문구는 온스토리 것(규칙 9 ③).

## 2. 넣을 것 ① — 촬영 안내 문구

회장님이 주신 원문을 **뜻은 그대로, 읽기 쉽게** 5줄로 나눴다.

```tsx
/** 촬영 안내 — 회장님 문구(2026-09-06). 화면 3곳이 이 하나를 쓴다. */
const SHOOT_TIPS: [string, string][] = [
  ["얼굴이 안 나와도 됩니다",
   "목소리만으로도 충분합니다. 처음엔 목 아래만 나오게 찍으셔도 돼요."],
  ["매장이라면, 60초 동안 매장을 걸으세요",
   "“오늘 매장을 보여드릴게요”처럼 편하게 말씀하시면 됩니다."],
  ["상품이 있다면, 상품을 보여주세요",
   "60초 동안 상품을 비추면서 “이 상품은 OOO입니다”라고 짧게 말씀해 주세요."],
  ["얼굴이 부담되시면 손만",
   "손에 제품을 들고 손과 제품만 나오게 찍으셔도 좋습니다."],
  ["카메라는 나 말고 매장 쪽으로",
   "카메라를 매장 쪽으로 두고 편하게 말씀하세요. 그게 가장 자연스럽습니다."],
];
```

⚠ 문구를 **JSX 안에 흩어 놓지 않는다.** 3곳에서 쓰므로 사본이 생기면 곧 말이 갈라진다
(A 스펙에서 "텅 빈 상가"가 4곳에 복사돼 있던 것과 같은 실수).

### 안내 박스 컴포넌트 (같은 파일 안, `RecClient` 밖)

```tsx
/** 촬영 안내 — JS 없이 접었다 펴기. globals.css 의 details.faq 규칙을 그대로 쓴다. */
function ShootGuide({ compact = false }: { compact?: boolean }) {
  return (
    <details className="faq mt-5 rounded-2xl bg-white/10 px-4 py-3 text-left">
      <summary className="flex items-center justify-between gap-3 text-[13.5px] font-bold">
        어떻게 찍나요? · 30초면 읽어요
        <span className="chev shrink-0 text-[18px] font-light" aria-hidden>＋</span>
      </summary>
      <ul className="mt-3 space-y-2.5">
        {(compact ? SHOOT_TIPS.slice(0, 3) : SHOOT_TIPS).map(([t, d]) => (
          <li key={t}>
            <p className="text-[13.5px] font-bold">{t}</p>
            <p className="mt-0.5 text-[13px] leading-relaxed opacity-75">{d}</p>
          </li>
        ))}
      </ul>
    </details>
  );
}
```

⚠ `details.faq` 의 `＋` 회전 애니메이션은 `app/globals.css:85~88` 에 이미 있다. **CSS 를 새로 쓰지 않는다.**
⚠ `/rec` 은 짙은 초록 바탕(`--forest`)에 크림 글자다. 카드 배경은 `bg-white/10` — 이 화면의 다른 카드들과 같은 값이다
   (`rec-client.tsx:167`, `:178`). **하드코딩 흰색·검정을 쓰지 않는다.**

## 4. 어디에 붙이나 — 3곳

| # | 화면 | 위치 | 형태 |
|---|---|---|---|
| 1 | `greet` | `[60초 영상 촬영하기]` 버튼 **바로 아래**(170줄 다음) | `<ShootGuide />` (5줄 전부) |
| 2 | `mode` | 영상/음성 카드 아래, `[카메라·마이크 켜기]` **위**(203줄 근처) | `<ShootGuide compact />` (앞 3줄) |
| 3 | `setup` | 카메라 미리보기 아래 한 줄 | 접는 박스 말고 **한 문장** (아래) |

```tsx
<p className="mt-3 text-center text-[12.5px] opacity-70">
  카메라를 매장 쪽으로 돌려도 됩니다. 얼굴이 안 나와도 괜찮아요.
</p>
```

## 5. 같이 고칠 문구 하나 — 회장님 방침과 어긋난다

`rec-client.tsx:199` 현재:

```tsx
[["video", "영상으로", "얼굴이 나옵니다. 가장 반응이 좋아요."],
 ["audio", "음성만",  "얼굴 없이 목소리만. 사진과 자막으로 영상을 만듭니다."]]
```

"영상으로 = **얼굴이 나옵니다**" 는 회장님이 이번에 확정하신 "**얼굴이 안 나와도 된다**"와 정면으로 어긋난다.
얼굴이 부담스러운 사장님이 이 줄을 보고 [음성만]으로 도망간다.

→

```tsx
[["video", "영상으로", "매장·상품·손만 찍어도 됩니다. 얼굴은 선택이에요."],
 ["audio", "음성만",  "목소리만 남깁니다. 사진과 자막으로 영상을 만들어 드려요."]]
```

## 6. 하지 않는 것

- **새 화면·새 라우트·새 파일 금지.** 9화면 그대로.
- `MAX_SEC`(60) · 업로드 경로(`/api/story/upload-url` → R2) · 링크 서명(`lib/story-link.ts`) 손대지 않는다.
- `app/[slug]/edit/story-link.tsx` 의 버튼 문구는 **이번엔 두지 않는다** — 거긴 "링크를 문자로 받는" 버튼이지 "촬영하는" 버튼이 아니라 이름이 맞다.
- `config/questions.ts`(질문 100개) 손대지 않는다.
- `data-tour` 앵커 추가 금지(규칙 3). `/rec` 은 애초에 앵커가 없다.
