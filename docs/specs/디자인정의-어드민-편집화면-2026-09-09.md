# 디자인 정의 — 어드민 · 사장님 편집화면 (2026-09-09)

> S2 착수 전 정의. 대표님 지시: 「온스토리 홈은 속도가 생명. 어드민·사장님 편집화면은
> 디자인을 만들어야 한다. 다크/화이트 선택 가능. `design-v6-admin.html` 참고. 로고는 다크에서 흰색.」

---

## 1. 원칙 — 화면 셋의 성격이 다르다

| 화면 | 성격 | 1순위 | 디자인 투자 |
|---|---|---|---|
| **onstori.com 홈** | 손님을 데려오는 얼굴 | **속도** | 지금 그대로. 손대지 않는다 |
| **/admin 운영자 콘솔** | 우리가 하루 종일 쓰는 작업대 | 정보 밀도·오래 봐도 안 피로 | 다시 칠한다 |
| **/{상호}/edit 사장님 편집** | 사장님이 처음 만지는 도구 | **덜 무섭게·자기 홈페이지가 잘 보이게** | 다시 짠다 |

★ **홈은 S1 에서 이미 「0바이트」로 끝났다.** 기본 설정이면 아무것도 더 보내지 않는다.
이 문서는 나머지 둘 이야기다. 둘은 손님이 보는 화면이 아니라 **속도보다 쓰기 편함이 먼저다.**

⚠ 그래도 지켜야 할 선: 편집화면이 무거워지면 사장님이 「느린 서비스」로 기억한다.
사장님 편집화면도 **첫 화면 기준값을 재고 시작한다**(지금 값은 S2 첫 작업으로 측정).

## 2. 사장님 편집화면 — 「디자인 1」 안으로 간다

대표님이 주신 시안 둘 중 **디자인 1(모던 & 심플)** 을 권한다.

| | 디자인 1 (상단 가로 메뉴) | 디자인 2 (왼쪽 짙은 세로 메뉴) |
|---|---|---|
| 메뉴 | 화면 맨 위 한 줄 | 왼쪽에 짙은 기둥(약 240px) |
| 미리보기에 줄 수 있는 폭 | **넓다** | 240px 좁다 |
| 첫인상 | 웹사이트 편집기 | 관리자 프로그램 |
| 다크모드 | 쉽다 | **어렵다** — 이미 어두운 기둥이 다크에서 배경과 뭉개진다 |

**추천 이유(쉬운 말로):**
사장님이 이 화면에서 제일 오래 보는 건 **자기 홈페이지 미리보기**입니다. 왼쪽에 짙은 기둥을
세우면 그만큼 미리보기가 좁아집니다. 그리고 짙은 기둥은 「전산실 프로그램」 같은 인상을 주는데,
우리 손님은 컴퓨터를 어려워하는 사장님입니다. 메뉴를 위에 한 줄로 눕히면 화면이 넓어지고
덜 위압적입니다. 어두운 화면을 만들 때도, 이미 어두운 기둥은 배경과 구분이 사라져 손이 더 갑니다.

### 화면 구조 (3단)

```
┌──────────────────────────────────────────────────────────────┐
│ [로고]  홈페이지 디자인 콘텐츠 사진 영상 연결 설정   [미리보기 ▭▯] [저장] [사이트 반영] │
├──────────┬──────────────────────────┬────────────────────────┤
│ 준비도    │  섹션 편집 폼             │  미리보기               │
│ 45% ▓▓░░  │  (제목·설명·이미지·버튼)   │  [PC][모바일]           │
│          │                          │                        │
│ 섹션 목록 │  ─────────────────       │  ┌──────────┐  ┌───┐   │
│ · 히어로  │  디자인 설정              │  │ PC 화면   │  │폰 │   │
│ · 분위기  │  분위기 / 색 / 글씨체     │  │          │  │   │   │
│ · 연결버튼│                          │  └──────────┘  └───┘   │
└──────────┴──────────────────────────┴────────────────────────┘
```

| 자리 | 무엇 | 규칙 |
|---|---|---|
| 상단바 | 로고 · 메뉴 7개 · 미리보기 전환 · [저장] · [사이트 반영] | 높이 `--bar-h`(56px) · 아래 `--border` 1px |
| 현재 메뉴 표시 | 글자 아래 **초록 밑줄 2px** | 색 `--brand-solid` |
| [사이트 반영] | **초록 채운 버튼** | 화면당 초록 버튼은 **이것 하나뿐**(규칙 11) |
| [저장] | 연회색 면 버튼 | 테두리 버튼이 아니다(규칙 11) |
| 왼쪽 | 준비도 막대 + 섹션 목록 | 고른 항목은 연초록 면 `--brand-tint` |
| 가운데 | 편집 폼 + 디자인 설정 | 카드 = 흰 면 · `--r-lg` · `--border` 1px · 그림자 없음 |
| 오른쪽 | 미리보기 | **폭을 제일 많이 준다.** 지금 `preview-pane.tsx` 재사용 |

### ⚠ 시안과 새 시스템이 어긋나는 곳 셋 — 시안을 따르지 않는다

시안은 분위기 카드 40장을 정하기 **전에** 그린 그림이다. 그대로 만들면 안 된다.

| 시안 | 새 시스템 | 어떻게 |
|---|---|---|
| 분위기 칩 4개 (깔끔한·따뜻한·프리미엄·활기찬) | **분위기 카드 40장** | 칩이 아니라 **그림 카드 격자**. 밝은 20 / 어두운 20 탭 |
| 색 동그라미 4개 + `+` | **색 20개 + 직접 입력** | 동그라미 20개 한 줄 + `#RRGGBB` 칸 |
| 폰트 드롭다운 | **글씨체 5개** | 그대로 두되 5개. ⚠ 용량(+405KB)은 절대 안 보인다 — 무거운 것에만 「글자가 조금 늦게 뜰 수 있어요」 |

★ 시안의 「분위기·색·폰트」 자리는 그대로 쓰되 **안에 들어가는 것만 바꾼다.**
자리 배치는 시안이 맞다.

## 3. 운영자 콘솔(/admin) — 지금 뼈대 유지 + 다시 칠하기

★ **여기는 세로 사이드바를 그대로 둔다.** 사장님 화면과 반대 결론인 이유:
운영자 화면은 **8개 화면 사이를 계속 오간다.** 2026-09-07 에 사이드바를 만든 이유가
「4곳이 뒤로가기조차 없는 막다른 길이었다」였다. 우리는 매일 쓰는 사람이고, 사장님은 처음 온 사람이다.

| 무엇 | 지금 | 바꿀 것 |
|---|---|---|
| 왼쪽 위 | 「ONSTORI」 **글자** + 운영자 콘솔 | **로고 이미지**로 교체. 다크에서는 흰 로고 |
| 다크모드 | 개인 브라우저 설정(localStorage) · 색 하드코딩 8덩어리 | **`data-mode` 로 흡수** — 서버가 심는다 |
| 첫 렌더 깜빡임 | 잠깐 밝게 보였다 어두워진다 | **사라진다**(서버가 처음부터 어둡게 준다) |
| 면·글자·선 색 | `#131C19` 같은 하드코딩 | `--canvas` `--surface` `--border` `--text` 토큰 |

## 4. 밝은/어두운 — 규칙

| 항목 | 밝은 | 어두운 |
|---|---|---|
| 바탕 | `--canvas` #F2F6F4 | `--canvas` #101815 |
| 카드 면 | `--surface` #FFFFFF | `--surface` #18211E |
| 선 | `--border` #E5EBE9 | `--border` #2A3531 |
| 본문 글자 | `--text` #50665E | `--text` #E5EBE9 |
| 초록 버튼 | `--brand-solid` = 7단계(진한 초록) · 흰 글자 | `--brand-solid` = **3단계(밝은 초록)** · 어두운 글자 |

★ **어두운 모드에서 버튼이 뒤집힌다.** 어두운 바탕에 진한 초록을 놓으면 안 보이기 때문이다.
이건 v6 시안의 설계이고 200조합 대비 검사를 이미 통과했다.

**누가 고르나:**
- 운영자 콘솔·사장님 편집화면의 밝은/어두운은 **대표님이 어드민에서 정한다**(대상별 설정).
- 사장님이 자기 **홈페이지**를 어둡게 하는 것은 별개다(분위기 카드).

⚠ 지금 어드민 다크 토글은 **개인 설정**이라 성격이 다르다. 흡수하면 「내가 어둡게 봤는데
다른 사람 화면도 어두워진다」가 된다. → **§7 결정 1번**

## 5. 로고 — 다크에서 흰색

### 확인된 사실
- 지금 다크용 파일은 `onstori-logo-cream-160.png` 인데 **순백이 아니라 크림색**(누런 흰색)이다.
  손님 사이트 어두운 띠에서 쓰려고 만든 것이라 지금은 그게 맞다.
- 어드민 사이드바에는 **로고 이미지 자체가 없다.** 글자로만 「ONSTORI」라고 적혀 있다.

### 정의

| 자리 | 밝은 | 어두운 |
|---|---|---|
| 어드민 왼쪽 위 | 초록 로고 (`onstori-logo-160.png`) | **순백 로고 (새로 만든다)** |
| 사장님 편집화면 상단바 | 초록 로고 | 순백 로고 |
| 손님 사이트 어두운 띠 | — | 크림 로고 (지금 그대로. 건드리지 않는다) |

★ **순백 파일을 새로 만든다.** 원본 로고의 모양(투명도)만 남기고 색을 순백으로 채우면 된다.
크림을 흰색 대신 쓰지 않는다 — 어두운 회녹색 위에서 크림은 **누렇게 뜬다.**

⚠ 파일 이름은 `onstori-logo-white-160.png`. 크림 파일을 덮어쓰지 않는다(손님 사이트가 쓰고 있다).

## 6. 안 건드리는 것

- **onstori.com 홈 화면** — S1 에서 0바이트로 끝났다. 이번 단계에서 손대지 않는다.
- **손님 사이트(`/{상호}`)** — S4 다.
- **미리보기 창 «안»** — 사장님이 고른 테마로 보인다. 편집 도구의 테마를 따라가지 않는다.
  손글씨 테마를 고른 사장님의 편집 화면 글자까지 손글씨가 되면 못 쓴다.

## 7. 결정이 필요한 것 넷 (각각 추천 포함)

### 1. 어드민 어두운 모드를 «개인 설정»에서 «전체 설정»으로 바꾼다
지금은 운영자가 자기 브라우저에서만 어둡게 본다. 새 것은 대표님이 정하면 모두에게 적용된다.
**추천: 전체 설정으로 바꾼다.**
> 왜: 지금 방식은 화면이 처음에 하얗게 떴다가 어두워지는 깜빡임이 있습니다. 서버가 처음부터
> 어둡게 내려주면 그게 사라집니다. 그리고 어드민을 쓰는 사람은 지금 대표님뿐이라
> 개인별로 나눌 실익이 없습니다. 나중에 직원이 늘면 그때 개인 설정을 다시 얹으면 됩니다.

### 2. 사장님 편집화면을 «디자인 1»로 다시 짠다
**추천: 그렇게 한다.** (이유는 §2)
> 다만 지금 편집화면은 974줄이고 탭 구조가 다릅니다(내용·이야기·문의함).
> 시안의 메뉴 7개(홈페이지·디자인·콘텐츠·사진·영상·연결·설정)로 가려면 **화면을 새로 짜는 일**입니다.
> S2 에서 껍데기(상단바·3단 배치)만 먼저 만들고, 안쪽 기능은 지금 것을 옮겨 담기를 권합니다.
> 한 번에 다 바꾸면 문의함·이야기 기능이 조용히 사라질 위험이 있습니다.

### 3. 순백 로고 파일을 새로 만든다
**추천: 만든다.** 원본의 모양만 남기고 흰색으로 채운다. 파일 하나 추가, 위험 없음.

### 4. 사장님 편집화면 메뉴 이름
시안은 「홈페이지 · 디자인 · 콘텐츠 · 사진 · 영상 · 연결 · 설정」이다.
**추천: 그대로 쓰되 「콘텐츠」만 「이야기」로 바꾼다.**
> 왜: 「콘텐츠」는 사장님이 잘 안 쓰는 말입니다. 우리 서비스의 핵심이 사장님 이야기이고
> 이미 「사업이야기」라는 이름을 쓰고 있으니, 말을 맞추는 편이 헷갈리지 않습니다.
