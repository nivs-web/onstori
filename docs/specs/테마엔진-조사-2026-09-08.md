## 2. `data-style` / `data-mode` / `data-font` 를 어디에 씌우나

### 확인된 사실

**`<html>` 을 그리는 파일은 `app/layout.tsx` 하나뿐이다.** 네 화면이 루트 레이아웃을 공유한다.
그리고 App Router 의 레이아웃은 **자기가 어느 경로인지 알 수 없다**(pathname 을 받지 못한다).

### 가능한 길 셋

| 안 | 방법 | 판정 |
|---|---|---|
| A | 미들웨어로 pathname 헤더 주입 | ✕ CLAUDE.md 「미들웨어 없음」. 엣지 호출 비용도 붙는다 |
| B | 라우트 그룹으로 루트 레이아웃 4개 | ✕ 전면 재배치. 그룹 간 이동마다 전체 새로고침 |
| C | **루트 = site, 나머지는 래퍼로 덮기** | ○ **추천** |

### C안 — 추가 파일 0, 미들웨어 0

```
app/layout.tsx            <html data-style/mode + --brand-*>   ← site 설정 (기본값)
└ app/admin/layout.tsx      <div data-style/mode …>            ← admin 설정이 덮는다
└ app/[slug]/edit/…         <div data-style/mode …>            ← editor 설정이 덮는다
└ app/[slug]/page.tsx       <div data-style/mode/font …>       ← shop (이미 vars 주입 중)
```

- CSS 선택자를 `:root[data-style="x"]` → **`[data-style="x"]`** 로 바꾸면 래퍼에서도 먹는다
- `app/[slug]/page.tsx:75` 는 **이미 `--s-bg` 등을 `<div style={vars}>` 로 주입**하고 있다. 그 자리에 얹는다
- `app/admin/layout.tsx` 에는 **이미 `.admin-shell` 래퍼**가 있다
- ⚠ 래퍼가 `min-height` 와 `background: var(--canvas)` 를 가져야 한다. 안 그러면 `<body>` 바깥 여백만 옛 색으로 남는다

### 화면별 손댈 파일

| 대상 | 파일 | 비고 |
|---|---|---|
| site | `app/layout.tsx` | 루트. 본사 8곳(`/` `/faq` `/reviews` `/blog` `/how-it-works` `/our-story` `/terms` `/privacy`)이 자동 적용. `/compare` `/login` `/new` `/my` 도 딸려온다 |
| admin | `app/admin/layout.tsx` | `.admin-shell` 에 속성 추가 |
| editor | `app/[slug]/edit/ui.tsx` | 편집 UI 껍데기. **미리보기 창 안쪽은 제외**(지시 [7]) |
| shop | `app/[slug]/page.tsx:75` · `app/[slug]/preview/preview-client.tsx:52` | 두 곳이 같은 vars 를 만든다 — 공용 함수로 먼저 뽑아야 한다 |

## 3. 저장 위치 판단

### 확인된 사실

- **`app_settings` 같은 표는 없다.** 마이그레이션 18개 전수 확인
- 운영자 설정의 유일한 전례는 `admin_notes(id text pk, body text, updated_at)` — 한 줄 = 한 메모
- `admin_notes` API 는 `IDS = {main, todo, done}` **화이트리스트로 잠겨** 있다
- 손님 사이트 테마는 이미 있다 — `lib/schema.ts:10` `Theme { palette, accent?, font }`
  - **`font: z.enum(["pretendard"])` 슬롯이 이미 있다.** 늘리기만 하면 된다

### 판단

| 무엇 | 어디에 | 이유 |
|---|---|---|
| site/admin/editor 설정 3벌 | **새 표 `app_settings(key text pk, value jsonb, updated_at)`** | `admin_notes` 는 의미가 '메모'이고 body 가 text 다. 거기 얹으면 메모 API 가 디자인을 다루게 된다. jsonb 면 zod 로 검증하고 바로 읽는다. RLS 켜고 정책 0 → 서비스롤만 (`admin_notes` 와 같은 방식) |
| 분위기 카드 40장 | **새 표 `theme_cards`** | 순서(`sort`)·켜기끄기(`enabled`)·위저드노출(`in_wizard`)·**복구 가능한 삭제**(`deleted` `deleted_at` `deleted_reason` — 불변 규칙 10)·미리보기 키가 행마다 필요하다. jsonb 배열 한 줄이면 한 장 고치는 데 40장을 통째로 덮어써 동시 편집이 서로를 지운다 |
| 소상공인 사이트 테마 | **`Theme` 확장** (site doc 안) | 이미 사이트별로 저장되는 자리다. **추가 쿼리 0** |

### `Theme` 확장안

```ts
Theme = {
  palette, accent?, font,                              // 지금
  card?:  string,                                      // 분위기 카드 id
  logo?: { variant, text, color?, symbol? },           // 로고 4안
}
font: z.enum(["pretendard","serif-title","hand-title","round-title","soft-all"])
```

⚠ **새 필드는 반드시 `.optional()`.** `lib/schema.ts:158~161` 에 「필수로 만들면 기존 발행
사이트가 전부 죽는다」는 경고가 이미 박혀 있다. `.default()` 도 쓰지 않는다.
⚠ Theme 을 고치면 규칙 2 정신대로 **schema + 렌더러 + 에디터 폼 + docs/SCHEMA.md** 를 한 커밋에서.

**마이그레이션 2개가 필요하다. 파일만 만들고 「db push 필요」라고 알린다.**

## 4. ISR·정적 생성과 충돌하는가

### 확인된 사실

| 경로 | 렌더 방식 |
|---|---|
| `app/page.tsx` | `revalidate = 60` (ISR) |
| `app/[slug]/page.tsx` | `revalidate = 60` + `generateStaticParams()` (SSG+ISR) |
| `app/admin/*` 6곳 | `force-dynamic` |

**기준값 실측 (2026-09-08, onstori.com 프로덕션)**

| 항목 | 값 |
|---|---|
| TTFB (예열) | **0.058초 · 0.062초** (첫 요청 0.317초) |
| 첫 페이지 HTML (br) | **20,343 bytes** |
| globals CSS (br) | **26,217 bytes** |

### 결론 — 충돌하지 않는다. 단 조건 셋

1. **루트 레이아웃에서 `cookies()` · `headers()` 를 부르지 마라.** 부르는 순간 `/` 와 `/{slug}` 가
   전부 동적으로 떨어지고 TTFB 0.06초를 잃는다. ← 이것 하나가 유일한 진짜 위험이다
2. DB 읽기 자체는 정적 렌더를 깨지 않는다. 빌드/재생성 시점에 구워지고 60초 안에 반영된다
3. 설정 읽기는 `React.cache()` + `unstable_cache(tag)` 로 감싼다. [적용하기] 때 `revalidateTag` →
   60초를 기다리지 않고 즉시 반영된다

- 손님 사이트는 테마가 이미 site doc 안이라 **추가 쿼리 0**
- 어드민은 원래 `force-dynamic` 이라 무관

### 전송량 예상

스타일 5벌 토큰을 CSS 에 **다 싣지 않고** 고른 한 벌만 인라인 → 회장님 계산(613 bytes)과 같다.
스타일을 15개로 늘려도 인라인 크기는 그대로다.
★ 다만 **globals.css 에 5벌을 다 넣으면 26KB 가 32KB 로 늘어난다** — 그 길로 가지 않는 것이 [2]-1 의 요지다.

## 5. 카드 미리보기 그림 40장 — 제안

### 확인된 사실

`lib/site-shot.ts` 는 `puppeteer-core` + **로컬 크롬**이다. `findBrowser()` 가 못 찾으면
`{ok:false, reason:"no-browser"}` 로 조용히 넘어간다. **Vercel 에는 크롬이 없다.**
지금 포트폴리오 스크린샷도 회장님 컴퓨터에서 찍고 있다.

### 제안 — 2단계

| 단계 | 방법 | 비용 | 판정 |
|---|---|---|---|
| **1단계** | **CSS 미니 미리보기** — 카드 안에 제목·버튼·글 몇 줄을 그 조합의 토큰으로 그린다 | **0 bytes · R2 0** | ★ **추천** |
| 2단계 | `site-shot.ts` 재사용. `sample-interior` 를 40조합으로 렌더 → 340×220 webp → R2 | 40 × 약 18KB ≈ **0.7MB** | 1단계가 부족할 때만 |

**1단계를 먼저 하자는 이유:** 카드는 조합이지 사이트가 아니다. 스크린샷은 「진짜 남의 사이트」를
보여줄 때만 값어치가 있다(포트폴리오가 그렇다). 분위기 카드는 색·모서리·굵기·간격만 보이면 되고,
그건 CSS 로 그리는 편이 **항상 최신이고, 40장을 다시 찍을 일이 없고, lazy 로딩도 필요 없다.**
스타일을 15개로 늘릴 때 80장을 다시 찍는 일도 사라진다.

## 6. 위저드 로고 — 이미 4안이 있다

### 확인된 사실

`app/new/wizard.tsx:40` 의 `wordmarks()` 가 **이미 4안을 만들고 있다.**

| 지금 (wizard.tsx) | v6 (paintLogo) |
|---|---|
| 세리프 / 굵은 고딕 / 모노그램 / 배지 | 굵은 워드마크 / 가는 워드마크 / 심볼+워드마크 / 엠블럼 |
| 512×512 **정사각 · 배경색 있음** | **가변폭 · 배경 투명** |
| 업로드해 저장하는 **로고 파일**(`/api/site/logo`) | 화면에서 그리는 **헤더 락업** |

→ 「적용돼 있지 않다」는 말씀은 맞다. 다만 **빈 자리가 아니라 다른 4안이 들어 있다.**
**교체인지 추가인지 결정이 필요하다.** 교체하면 `/api/site/logo` 로 올라가는 값의 성격이 바뀐다
(정사각 파비콘·카톡 썸네일용 vs 헤더용 가로 락업). 둘 다 필요할 수도 있다.

### 옮길 때 고칠 곳

`paintLogo()` 는 `getComputedStyle()` 로 `--brand-solid` `--brand-ink` `--ls-h1` `--w-title` 을 읽는다.
서버에서 그리려면 **그 값들을 인자로 받게** 바꿔야 한다. 순수 함수로 뽑으면 위저드·에디터·미리보기가 같이 쓴다.
⚠ 지시대로 **AI 로 로고 이미지를 만들지 않는다.**

1. ★ **CLAUDE.md 규칙 11 과 정면으로 부딪힌다.**

   > 「글꼴은 Pretendard 하나다. 명조(Noto Serif KR)는 2026-09-07 폐기했다.
   > `Noto Serif` 참조가 코드에 다시 생기면 안 된다.」

   **폐기한 이유(onstori.com 속도)와는 어긋나지 않는다** — shop 에만 들어가고 onstori.com 은 그대로다.
   그러나 규칙 문장 그대로는 위반이다. **규칙 11 을 「onstori.com 세 화면은 Pretendard 고정,
   손님 사이트는 서체 선택 가능」으로 고쳐 주셔야** 다음 세션이 이걸 되돌리지 않는다.

   손님 사이트 4종도 자체 호스팅할지, CDN 을 허용할지. (Noto Serif KR 은 405KB 다.)

3. **서체 5개인가 6개인가.** 지시 [6]③ 은 5개, 시안은 6개(**`serif-all` 명조 전체**가 더 있다).
