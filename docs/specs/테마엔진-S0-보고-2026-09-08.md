## 2. 로고 — **AI 가 아니다.** 결정 4의 전제 확인

### 판정

**위저드 자동 로고 4안에 AI 이미지 생성이 없다.** 폐기할 경로가 없다.

`app/new/wizard.tsx:40~54` 의 `wordmarks()` 는 순수 템플릿 문자열로 SVG 4개를 조립한다.
함수 안에 `fetch`·`await`·`import` 가 **하나도 없고**, 미리보기도 `data:image/svg+xml` 로 그려
서버를 거치지 않는다(`:56`, `:417`). 색은 고정 8색 팔레트에서 온 hex 를 그대로 `fill` 에 넣는다.

- 코드가 스스로 그렇게 선언한다 — `:39` 주석 「자동 로고 4안 — 상호명 워드마크 SVG. AI 그림 로고는 후순위」
- 이미 결정으로 기록돼 있다 — `docs/DECISIONS.md:76` 「워드마크 로고는 **폰트 조판 SVG** · 한글 렌더 정확성과 건당 원가 ~0원」
- `/api/site/logo` 는 SVG 를 **변환 없이** R2 에 올린다(`route.ts:33`). `sharp` 는 사장님이 올린 PNG/JPG 에만 걸린다(`:42`)
- 로고 경로가 import 하는 것은 여섯 개뿐이다(`:1~6`) — vertex·gemini·imagen 문자열이 파일 55줄 어디에도 없다
- 기획서는 오히려 AI 이미지에 「글자·숫자·로고·상표」를 **금지 항목**으로 못 박아 뒀다

## 3. R2 자체 호스팅 서체 — 절차와 용량

### 지금 Pretendard 가 어떻게 돼 있나 (실측)

`app/fonts.css` 한 파일에 `@font-face` **92개**, 파일은 `public/fonts/pretendard/PretendardVariable.subset.{0..91}.woff2`
**92개 · 2,957,724 B (2.82 MiB)**. 커버 코드포인트 13,154개(한글 음절 11,172 전량 포함).

★ **저장소 문서 3곳이 틀렸다.** `app/fonts.css:8` · `docs/LICENSES.md:7` · `docs/PERFORMANCE.md:61` 이
「3~6조각 100KB 안팎」이라고 적어 뒀는데, unicode-range 를 실제 한글 텍스트에 대입하니
**한 페이지가 14~18조각 365~468 KB** 를 받는다(`PERFORMANCE.md:22` 의 실측 451KB 와 일치).
이 잘못된 숫자로 계산하면 4배 이상 과소 추정한다 — **문서부터 고쳐야 한다.**

### 4종 실측 용량

구글이 서빙하는 조각의 `Content-Length` 를 전부 합산해 잰 값이다(추정 아님).

| 서체 | 쓰임 | 조각 | 총량 |
|---|---|---|---|
| Noto Serif KR | 명조 제목 | 124 | **6,249,684 B (5.96 MiB)** |
| Nanum Pen Script | 손글씨 제목 | 93 | **1,727,488 B (1.65 MiB)** |
| Gowun Dodum | 부드러운 전체 | 95 | **1,334,716 B (1.27 MiB)** |
| Jua | 둥근 제목 | 87 | **874,176 B (0.83 MiB)** |
| **합계 (안 A — 구글 조각 그대로)** | | **399개** | **10,183,916 B (9.71 MiB)** |
| 합계 (안 B — Pretendard 92범위로 다시 자르기) | | 368개 | 8,260,348 B (7.88 MiB) |

**R2 무료 10GB 의 0.10%.** 저장 비용은 사실상 0이다.

### ★ 페이지당 실제 전송량 — soft-all 이 제일 가볍다

| 서체 | 페이지당 | 지금 대비 |
|---|---|---|
| 기본(Pretendard) = 지금 | 365 ~ 468 KB | — |
| 손글씨 제목 | 457 ~ 560 KB | **+92 KB** |
| 둥근 제목 | 465 ~ 568 KB | **+101 KB** |
| 명조 제목 | 492 ~ 595 KB | **+127 KB** |
| **부드러운 전체** | **200 ~ 259 KB** | ★ **−164 ~ −208 KB (줄어든다)** |

「부드러운 전체」는 Gowun Dodum 이 본문까지 담당해 **Pretendard 조각을 아예 안 받는다.**
1차 조사는 이걸 「제일 무겁다」고 잘못 봤고 검증에서 뒤집혔다 — **LCP 위험이 아니라 개선 후보다.**

### ⚠ 절차 — 순서를 지켜야 한다

1. **CORS 부터 연다.** ★ 이걸 안 하면 그냥 안 된다.
   폰트는 CSS 명세상 **항상 CORS anonymous** 로 받는다. 지금 R2 에 CORS 규칙이 없고(저장소 grep 0건),
   실측으로 프리플라이트가 막히는 것을 확인했다. 이대로 올리면 **4종 전부 조용히 폴백 고딕으로 그려진다.**
   화면이 깨져 보이지 않아 알아채기도 어렵다. 「이미지가 잘 나온다」는 근거가 못 된다 — `<img>` 는 CORS 검사를 안 받는다.
   · `AllowedOrigins` 는 **`["*"]`** 여야 한다. 도메인 목록으로 좁히면 나중에 손님 커스텀 도메인이 붙는 순간 그 사이트만 글꼴이 죽는다.
2. **캐시 TTL 을 함께 고친다.** `put()` 이 `immutable` 을 붙이지만 그 헤더가 손님 브라우저까지 오지 않는다 —
   `img.onstori.com` 의 실효 캐시가 **4시간**이다. 그대로 두면 재방문자가 4시간마다 수백 KB 를 다시 받는다.
3. **조각을 받아 R2 에 올린다.** `storage.put("media", key, buf, "font/woff2")` → `storage.publicUrl(key)`.
   ⚠ 스크립트 첫 줄에 `storageMode() === "r2"` 가드를 넣는다. R2 env 가 없으면 존재하지 않는 버킷으로 조용히 폴백하다 실패한다.
4. **손글씨는 이름을 바꾼다.** Nanum Pen Script 만 OFL **예약 이름**(Reserved Font Name)이 걸려 있다.
   서브셋은 OFL 상 Modified Version 이므로 family 명을 바꿔야 한다(예: `Onstori Pen`).
   바꾸면 `config/design.ts` 의 `titleFamily` 도 같이 고친다. 나머지 3종은 SIL OFL 1.1 로 재배포 가능하다.
5. **CSS 는 고른 1종만 인라인한다.** `@font-face` 원문이 1종당 55KB 다. 4종을 한 CSS 에 다 넣으면
   220KB 짜리 렌더 차단 CSS 가 생긴다 — Pretendard 를 CDN 에서 떼어낸 이유를 그대로 되살리는 셈이다.

## 5. ⚠ S1 착수 전 결정 — 규칙 11 과의 잔여 충돌 5건

규칙 11 의 글꼴 조항은 고쳤다(`1b7e397`). 그런데 **v6 스타일 값이 규칙 11 의 다른 조항과 부딪힌다.**
전부 시안 값을 직접 열어 대조한 것이다.

| # | 규칙 문장 | v6 실제 값 | 판단 |
|---|---|---|---|
| 1 | `CLAUDE.md` 「굵기는 400·500·600·700 넷뿐」 | **bold `--w-title:800`** | 800 을 허용할지, bold 를 700 으로 낮출지 |
| 2 | 「제목 행간을 1.2 아래로 내리지 않는다」(한글은 행간이 필요하다) | **bold `--lh-display:1.14`** | 한글 때문에 박은 규칙이다. 낮추면 제목이 붙어 보인다 |
| 3 | ★ 「**본문 17px · 행간 1.68**」 | **quiet `--t-body:1rem`(16px)** · 행간이 1.62/1.68/1.78/1.85/1.95 **다섯 갈래** | 스타일을 고르면 본문 크기가 바뀐다 — 규칙이 명시적으로 「그대로 둔다」고 못 박은 조항이다 |
| 4 | 「토큰은 `globals.css` 의 `:root`」 | 스타일 토큰을 TS 값으로 두고 서버가 인라인 | 방식이 바뀐다 — 규칙 문장을 함께 고쳐야 한다 |
| 5 | 「주 버튼(**초록** 면)」 · 「고객 사이트는 `--s-bg` 등으로 인라인 주입」 | 20색 + `--brand-*` | 20색으로 가면 둘 다 사실이 아니게 된다 |

**제 권고:** 3번이 가장 무겁다. 본문 크기·행간은 읽기 쉬움의 바닥이라 스타일마다 흔들면 안 된다고 봅니다.
**`--t-body` 와 `--lh-body` 를 스타일 축에서 빼고 `:root` 고정으로 두는 것**을 제안합니다.
1·2도 같은 이유로 bold 를 700 / 1.2 로 눌러 맞추는 편이 낫다고 봅니다.
4·5는 사실 기술을 규칙 문장에 반영만 하면 되는 일입니다.

### 그리고 제 앞선 보고의 오류 하나

`docs/specs/테마엔진-조사-2026-09-08.md` §1(가)에서 `--t-h3` 를 「값이 같다」로 분류했는데 **틀렸다.**

| | 지금 | v6 basic |
|---|---|---|
| `--t-h3` | `clamp(1.125rem, 1.05rem + 0.3vw, 1.25rem)` (18→**20px**) | `1.125rem` 고정 (**18px**) |

PC 에서 h3 가 20px → 18px 로 줄어든다. S1 합격 기준이 이 표에 걸려 있으므로 정정한다.
**S1 에서는 basic 의 `--t-h3` 에 지금 clamp 값을 쓴다.**
그 밖에 v6 basic 에 **없는** 토큰도 있다 — `--t-lead` `--t-micro` `--ls-lead` `--ls-small` `--lh-lead` 등.
이것들은 스타일 축이 아니라 `:root` 에 그대로 남긴다.
