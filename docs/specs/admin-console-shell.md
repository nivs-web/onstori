# 어드민 콘솔 껍데기 — 설계안

작성 2026-09-07 · **구현 전 · 회장님 승인 대기** · 코드 변경 0
실측은 회장님 크롬(운영자 로그인 상태)에서 프로덕션 onstori.com 을 직접 열어 했다. ADMIN_KEY 는 다루지 않았다(규칙 6).
390px 은 크롬 창이 그 폭까지 줄지 않아(윈도우 최소 폭 1536) **같은 출처 iframe 390×844** 로 진짜 뷰포트를 만들어 쟀다.

## 0. 실측 결과

### 0-1. `/admin` 에 들어가면 무엇이 뜨는가

**대시보드가 아니다.** 링크 카드 13장이 깔린 **목차 페이지**가 뜬다(`app/admin/page.tsx`).
대시보드는 그 카드 중 하나(`/admin/dashboard`)일 뿐이다.

### 0-2. 왼쪽 고정 메뉴

**없다.** `app/admin/` 에 `layout.tsx` 자체가 없다. 화면마다 `isAdmin()` 을 각자 부르고 각자 그린다.
그래서 화면 간 이동은 이렇게 하고 있다:

| 방법 | 실제 |
|---|---|
| ← 운영자 콘솔 링크 | **8곳 중 4곳에만 있다** (bank · showcase · sites · subdomains) |
| 없는 4곳 | `/admin` · `/admin/dashboard` · `/admin/members` · `/admin/pages` — **막다른 길**이다. 브라우저 뒤로가기를 쓰거나 주소를 직접 쳐야 한다 |
| 화면↔화면 직접 이동 | 아예 없다. 회원 목록 → 사이트 관리로 가려면 반드시 `/admin` 을 거친다(2탭) |

### 0-3. 지금 있는 어드민 화면 전부

`page.tsx` 가 실제로 있는 것은 **8개**다. `/admin` 목차에는 13장이 깔려 있어 5장은 갈 곳이 없다.

| 주소 | 이름 | 상태 |
|---|---|---|
| `/admin` | 운영자 콘솔(목차) | 있음 |
| `/admin/dashboard` | 대시보드 | 있음 |
| `/admin/members` | 회원 목록 | 있음 |
| `/admin/bank` | 이미지뱅크 관리 | 있음 |
| `/admin/showcase` | 랜딩 포트폴리오 관리 | 있음 |
| `/admin/pages` | 홈페이지 관리(섹션 토글) | 있음 |
| `/admin/sites` | 사이트 관리 | 있음 |

| — | 기획1·2·3 (`/mainplan`·`/plandept`·`/onstoriplandept`) | 어드민 밖 별도 라우트 |
| — | 신청 접수함 · 무비 주문 관리 | 목차 카드만 있고 라우트 없음 |

### 0-5. ★ 회원 목록 표가 폰에서 어떤가 — `table-scroll` 이 **작동하지 않는다**

붙이긴 붙였는데 효과가 없다. 이유를 끝까지 팠다.

```
body   (display:flex, flex-direction:column, overflow-x:hidden)  보이는 폭 380px
└ main.mx-auto.max-w-7xl.px-6   min-width: auto  ← ★ 범인      계산된 폭 1280px
  └ div.table-scroll  overflow-x:auto            보이는 폭 1230px  내용 1250px
    └ table                                       1250px, 열 12개
```

`main` 은 `body` 의 **flex 아이템**이다. flex 아이템의 `min-width` 기본값은 `auto` — 즉
**내용의 최소 폭 아래로 줄어들지 않는다.** 표가 1250px 이니 `main` 이 1280px 로 부풀고,
그 안의 `.table-scroll` 은 이미 넉넉한 상자 안에 있으니 스크롤할 게 20px 밖에 없다.
결과적으로 **표가 아니라 페이지 전체가 890px 옆으로 밀린다.**

실제 사용감:
- 390 에서 12열 중 **2열만 보인다**(상호명·홈페이지 주소).
- 나머지 10열을 보려면 페이지를 옆으로 미는데, 그러면 **제목·필터 버튼·검색창이 같이 사라진다.**
- 첫 열에 `position:sticky` 가 걸려 있지만, 고정 기준이 되는 상자가 페이지와 함께 밀리므로 **아무 일도 하지 않는다.**

**고칠 곳은 한 줄이다** — `main` 에 `min-w-0` 을 준다. 그러면 `main` 이 380px 로 줄고,
`.table-scroll` 의 `overflow-x:auto` 가 그제야 일하고, sticky 첫 열도 살아난다.
(같은 원인으로 `/admin/sites` 의 299px 넘침도 함께 사라진다.)

## 2. 설계 — 어드민 콘솔 껍데기

### 2-1. 구조

`app/admin/layout.tsx` **하나를 새로 만든다.** 지금 8개 화면이 각자 하는 일(인증 확인·제목·여백)을
껍데기가 대신한다. 각 화면은 내용만 그린다.

```
app/admin/layout.tsx          ← 신규. isAdmin() 한 번, 사이드바, 서랍, 현재 위치
components/admin/sidebar.tsx  ← 신규. 메뉴 정의를 읽어 그린다
config/admin-menu.ts          ← 신규. ★ 메뉴의 단일 출처 (config/ 규약 그대로)
```

`config/admin-menu.ts` 에만 메뉴를 적는다. 화면이 늘어나면 **여기 한 줄만 더한다** —
사이드바·서랍·`/admin` 목차·현재 위치 표시가 전부 이 배열을 읽는다.
(지금은 `app/admin/page.tsx` 안에 `menus` 배열이 박혀 있어 목차만 갱신되고 다른 곳은 모른다.)

```ts
export type AdminMenu = { href: string; label: string; desc: string; ready: boolean };
export const ADMIN_GROUPS: { group: string; items: AdminMenu[] }[] = [ ... ];
```

### 2-2. 메뉴 그룹 배치 (회장님 지시 5개 그룹)

`◆` = 지금 있는 것 · `○` = 자리만 잡아 두는 것(회색 비활성)

| 그룹 | 항목 | 주소 |
|---|---|---|
| **현황** | ◆ 대시보드 | `/admin/dashboard` ← **`/admin` 첫 화면이 된다** |
| | ○ 신청 접수함 | `/admin/inquiries` (P3) |
| **회원** | ◆ 회원 목록 | `/admin/members` |
| | ○ 결제 내역 | `/admin/payments` — `payments` 테이블은 이미 있다. 화면만 없다 |
| **사이트** | ◆ 사이트 관리 | `/admin/sites` |
| | ◆ 랜딩 포트폴리오 | `/admin/showcase` |
| | ○ 서브도메인 | `/admin/subdomains` (자리만) |
| **콘텐츠** | ◆ 이미지뱅크 | `/admin/bank` |
| | ○ 영상 관리 | `/admin/videos` (V 배치) |
| | ◆ 온스토리 홈페이지 | `/admin/pages` |
| | ○ 무비 주문 | `/admin/movies` (P6) |
| **설정** | ○ 로고·테마 | `/admin/settings/brand` |
| | ○ 예약 슬러그·운영자 | `/admin/settings` |

기획1·2·3 은 어드민 화면이 아니라 **문서**다. 그룹에 섞지 않고 사이드바 **맨 아래 별도 묶음**으로 내린다.

### 2-3. `/admin` 첫 화면 = 대시보드

`app/admin/page.tsx` 의 목차 13장을 **버린다.** 사이드바가 목차 역할을 하므로 중복이다.
`/admin` 은 지금 `/admin/dashboard` 가 그리던 내용을 그대로 그린다.
`/admin/dashboard` 는 `/admin` 으로 **redirect** 시켜 옛 링크·북마크를 살린다.

### 2-4. 치수와 토큰 (v5 토큰만 — 새 색·새 간격 없음)

| 항목 | 값 | 근거 |
|---|---|---|
| 사이드바 폭 | `240px` 고정 | 회장님 지시 |
| 사이드바 배경 | `var(--n-50)` | 본문(흰색)과 구분 |
| 사이드바 경계 | `1px solid var(--line)` | |
| 그룹 제목 | 13px `var(--w-semi)` `var(--text-soft)` | 기존 토큰 |
| 메뉴 글자 | 15px `var(--text)` / 현재 위치 `var(--text-strong)` + `var(--w-semi)` | |
| 현재 위치 표시 | 배경 `var(--n-100)` + 왼쪽 3px `var(--green-700)` 막대 + `aria-current="page"` | |
| 비활성 항목 | `var(--text-soft)` + `cursor:not-allowed`, 링크 아님 | 이미 쓰는 방식 |
| 모서리 | `var(--r-md)` | |
| 열림/닫힘 모션 | 180ms — **조작(120~200ms)** 구간 | MOTION.md |

⚠ 사이드바에 `position:fixed` 를 쓰므로 조상에 `backdrop-filter`·`transform`·`filter`·`contain` 을 두지 않는다.
(첫 페이지 메뉴 시트가 55px 로 잘렸던 것과 같은 함정이다 — `scripts/verify.js` 의 "갇힌 fixed" 검사로 확인한다.)

### 2-5. 폰(<1024px)

- 사이드바 → **서랍**. 위쪽 고정 바(높이 56px)에 햄버거 + 현재 화면 이름.
- 서랍은 왼쪽에서 밀려 나오고 뒤에 `var(--scrim)`. 바깥을 누르거나 Esc 로 닫힌다.
- 서랍 DOM 은 **`<header>` 밖**에 둔다(위 함정과 같은 이유).
- 현재 위치는 상단 바의 화면 이름 + 서랍 안의 배경 표시, 둘 다에 나온다.

### 2-6. 같이 고칠 것 — 폰 넘침

- `layout.tsx` 의 본문 `<main>` 에 **`min-w-0`** 을 준다. → `/admin/members` 890px·`/admin/sites` 299px 넘침이 함께 사라지고, `.table-scroll` 과 sticky 첫 열이 그제서야 제 일을 한다(0-5).
- 회원 목록 12열은 그대로 둔다. 열을 줄이는 건 별건이다 — 여기서는 **표만 밀리게** 만드는 게 목표다.

### 2-7. 하지 않는 것

- 인증 방식은 **건드리지 않는다**(ADMIN_KEY 유지, P7 묶음).
- 각 화면의 내용·기능은 손대지 않는다. 껍데기와 `min-w-0` 뿐이다.
- `/admin/bank` 의 폰 사용성(24,089px)은 이 작업 범위 밖이다. 별건으로 남긴다.

### 2-8. 완료 조건

1. 8개 화면 전부 사이드바가 뜨고 현재 위치가 표시된다. 막다른 길이 0개.
2. 390 에서 8개 화면 **가로 넘침 0px**. `/admin/members` 는 **표만** 옆으로 밀린다.
3. 390 에서 서랍이 열리고 닫힌다. 잘리지 않는다(`verify.js` 갇힌 fixed 검사 통과).
4. `contrast.js` 통과.
5. 새 색·새 간격 토큰 0개 추가.
6. lint 새 경고 0건.
