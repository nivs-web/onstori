# Meta 개발자 앱 등록·심사 — 진행 기록

작성 2026-09-07 · 담당 클코 · **진행 중단 지점 기록됨**

---

## 0. ⚠ 먼저 보고드릴 것 두 가지 — 계획이 바뀝니다

### (1) 심사는 6~8주가 아니라 **1~4주**입니다

| 출처 | 기간 |
|---|---|
| Meta 공식 제출 안내 | 제출 후 **일주일 안에** 결과 |
| 업계 실무 문서(2026) | **2~4주** (반려·재제출 포함) |

6~8주를 전제로 "이것만은 오늘 시작해야 한다"고 하셨는데, 실제로는 그만큼 급하지 않습니다.
그래도 **먼저 시작하는 게 맞습니다** — 아래 (2) 때문입니다.

### (2) ★ 기능이 완성되기 전에는 **제출 자체가 불가능**합니다

이게 더 중요합니다. Meta 는 앱을 **직접 눌러 보고** 심사합니다.

> 심사원이 앱에 접근할 수 없으면 **제출 전체가 반려된다.**
> 요청한 권한이 화면에서 실제로 쓰이는 것을 **화면 녹화로 보여 줘야** 한다.
> 권한을 요청했는데 녹화에 안 나오면 그 권한은 **삭제되거나 반려**된다.

우리 인스타 발행 기능은 **아직 없습니다**(V-1·V-2 미착수). 그러니 지금 할 수 있는 것은
**계정·앱 만들기와 비즈니스 인증까지**이고, **제출 버튼은 기능이 돌아간 뒤**입니다.
회장님이 "심사 제출 버튼은 누르지 마라" 하신 것과 결론이 같습니다 — 눌러도 반려됩니다.

**따라서 오늘 밤의 목표는 "제출"이 아니라 "제출할 수 있는 상태 만들기"입니다.**
그중 제일 오래 걸리는 것이 **비즈니스 인증**이고, 그건 기능과 무관하게 지금 시작할 수 있습니다.

## 1. 어디까지 갔나 — **0단계에서 막혔습니다**

`developers.facebook.com/apps/` 로 갔더니 로그인 화면이 떴습니다.

```
Meta for Developers에 로그인
[ Facebook으로 계속하기 ]  [ 새 계정 만들기 ]  [ 매니지드 Meta 계정으로 로그인 ]
```

**회장님 크롬에 Facebook 로그인이 안 돼 있습니다.** 비밀번호·인증코드는 제가 다루지 않기로 했으므로
여기서 멈췄습니다. 회장님이 로그인만 해 두시면 그다음부터 제가 이어서 합니다.

| 9. 권한별 설명문 작성 | 클코 | 복붙하면 반려된다. 권한마다 따로 쓴다 |
| 10. 시연 영상 녹화 | 클코 | **기능이 완성된 뒤에만 가능** |
| 11. 심사 제출 | **회장님** | ⚠ 지시대로 제가 누르지 않습니다 |

## 3. 필요한 권한과 전제 조건

### 3-1. 인스타그램 발행

| 항목 | 내용 |
|---|---|
| 권한 | `instagram_business_basic` + `instagram_business_content_publish` |
| 접근 등급 | 고급(Advanced) 또는 표준(Standard) — **심사 필요** |
| 계정 조건 | **인스타 프로페셔널 계정**(비즈니스 또는 크리에이터) |
| 페이스북 페이지 | **필요하다.** 인스타 계정이 페이지에 연결돼 있어야 한다 |
| 발행 한도 | 24시간에 **100건**(캐러셀은 1건으로 센다) |
| 사진·영상 조건 | **공개 주소에 올라가 있어야 한다** — 우리 영상은 지금 **비공개 버킷**이라 그대로는 안 된다(아래 ⚠) |

⚠ **영상 저장 위치와 걸립니다.** 지금 녹화 영상은 `private/stories/...` 비공개 버킷에 들어갑니다.
인스타·쓰레드에 발행하려면 Meta 서버가 **공개 주소로 내려받을 수 있어야** 합니다.
V-2 에서 "발행본은 공개 버킷(img.onstori.com)으로 따로 낸다"를 반드시 넣어야 합니다.

### 3-2. 쓰레드 발행

| 항목 | 내용 |
|---|---|
| 권한 | `threads_basic` + `threads_content_publish` |
| 앱 | 만들 때 **Threads 이용 사례**를 선택해야 한다 |
| 심사 | **필요하다.** 심사 통과 + 앱 게시(published) 후에야 일반 사용자가 권한을 줄 수 있다 |

⚠ 인스타와 쓰레드는 **권한이 완전히 별개**입니다. 한 앱에서 둘 다 요청하되 이용 사례를 둘 다 켜야 합니다.

### 3-3. 우리에게 있는 것 / 없는 것

| 필요한 것 | 있나 | 조치 |
|---|---|---|
| 페이스북 페이지 (온스토리) | **모름 — 로그인 못 해 확인 불가** | 로그인 후 확인. 없으면 만든다 |
| 인스타 프로페셔널 계정 (온스토리) | **모름 — 확인 불가** | 회장님이 전환 |
| 둘의 연결 | 모름 | 회장님 |
| Meta 개발자 계정 | 모름 | 회장님 |

## 6. 반려당하는 흔한 이유 (미리 피할 것)

1. **시연 영상에 권한 동의 화면이 안 나옴** — 사용자가 "허용"을 누르는 장면이 꼭 있어야 한다.
2. **테스트 계정으로 녹화** — 개발자 대시보드의 테스트 사용자 말고 **진짜 인스타 프로페셔널 계정**으로 찍어야 한다.
3. **데이터 삭제 URL 없음** — 자동 반려.
4. **권한 설명을 복사해 붙임** — 권한마다 다르게 써야 한다.
5. **필요 없는 권한까지 요청** — 우리가 쓸 4개만 요청한다.
6. **한 번에 여러 건 자동 발행하는 장면** — 사용자가 매번 직접 누르는 흐름으로 보여야 한다.
   ⚠ 우리 기획(하루 3건 자동 발행)이 여기 걸릴 수 있다. **사장님이 "발행" 을 누르는 화면**을 반드시 만들어야 한다.
