# Meta 개발자 앱 등록·심사 — 진행 기록

## 0. ⚠ 먼저 보고드릴 것 두 가지 — 계획이 바뀝니다

### (1) 심사는 6~8주가 아니라 **1~4주**입니다

| 출처 | 기간 |
|---|---|
| Meta 공식 제출 안내 | 제출 후 **일주일 안에** 결과 |
| 업계 실무 문서(2026) | **2~4주** (반려·재제출 포함) |

6~8주를 전제로 "이것만은 오늘 시작해야 한다"고 하셨는데, 실제로는 그만큼 급하지 않습니다.
그래도 **먼저 시작하는 게 맞습니다** — 아래 (2) 때문입니다.

### (2) ★ 기능이 완성되기 전에는 **제출 자체가 불가능**합니다

이게 더 중요합니다. Meta 는 앱을 **직접 눌러 보고** 심사합니다.

> 심사원이 앱에 접근할 수 없으면 **제출 전체가 반려된다.**
> 요청한 권한이 화면에서 실제로 쓰이는 것을 **화면 녹화로 보여 줘야** 한다.
> 권한을 요청했는데 녹화에 안 나오면 그 권한은 **삭제되거나 반려**된다.

우리 인스타 발행 기능은 **아직 없습니다**(V-1·V-2 미착수). 그러니 지금 할 수 있는 것은
**계정·앱 만들기와 비즈니스 인증까지**이고, **제출 버튼은 기능이 돌아간 뒤**입니다.
회장님이 "심사 제출 버튼은 누르지 마라" 하신 것과 결론이 같습니다 — 눌러도 반려됩니다.

**따라서 오늘 밤의 목표는 "제출"이 아니라 "제출할 수 있는 상태 만들기"입니다.**
그중 제일 오래 걸리는 것이 **비즈니스 인증**이고, 그건 기능과 무관하게 지금 시작할 수 있습니다.

Meta for Developers에 로그인

**회장님 크롬에 Facebook 로그인이 안 돼 있습니다.** 비밀번호·인증코드는 제가 다루지 않기로 했으므로
여기서 멈췄습니다. 회장님이 로그인만 해 두시면 그다음부터 제가 이어서 합니다.

## 3. 필요한 권한과 전제 조건

### 3-1. 인스타그램 발행

| 항목 | 내용 |
|---|---|
| 권한 | `instagram_business_basic` + `instagram_business_content_publish` |
| 접근 등급 | 고급(Advanced) 또는 표준(Standard) — **심사 필요** |
| 계정 조건 | **인스타 프로페셔널 계정**(비즈니스 또는 크리에이터) |
| 페이스북 페이지 | **필요하다.** 인스타 계정이 페이지에 연결돼 있어야 한다 |
| 발행 한도 | 24시간에 **100건**(캐러셀은 1건으로 센다) |
| 사진·영상 조건 | **공개 주소에 올라가 있어야 한다** — 우리 영상은 지금 **비공개 버킷**이라 그대로는 안 된다(아래 ⚠) |

⚠ **영상 저장 위치와 걸립니다.** 지금 녹화 영상은 `private/stories/...` 비공개 버킷에 들어갑니다.
인스타·쓰레드에 발행하려면 Meta 서버가 **공개 주소로 내려받을 수 있어야** 합니다.
V-2 에서 "발행본은 공개 버킷(img.onstori.com)으로 따로 낸다"를 반드시 넣어야 합니다.

### 3-2. 쓰레드 발행

| 항목 | 내용 |
|---|---|
| 권한 | `threads_basic` + `threads_content_publish` |
| 앱 | 만들 때 **Threads 이용 사례**를 선택해야 한다 |
| 심사 | **필요하다.** 심사 통과 + 앱 게시(published) 후에야 일반 사용자가 권한을 줄 수 있다 |

⚠ 인스타와 쓰레드는 **권한이 완전히 별개**입니다. 한 앱에서 둘 다 요청하되 이용 사례를 둘 다 켜야 합니다.

### 3-3. 우리에게 있는 것 / 없는 것 — 2026-09-07 크롬에서 직접 확인

| 필요한 것 | 있나 | 확인한 것 | 조치 |
|---|---|---|---|
| Facebook 로그인 | **안 돼 있음** | facebook.com 이 가입/로그인 화면 | ⏸ **회장님이 로그인해 주셔야 이어집니다** |
| 페이스북 페이지 (온스토리) | **확인 못 함** | 로그인이 없어 볼 수 없음 | 로그인 후 제가 확인. 없으면 만듭니다 |
| 인스타 로그인 | ✅ 돼 있음 | instagram.com 이 피드로 열림 | — |
| 인스타 **프로페셔널** 계정 (온스토리용) | **없음** | 보이는 계정은 `nivs_poem`("러너 로원") — 개인 계정이고 온스토리 계정이 아니다. 프로페셔널 표시·인사이트·홍보 도구가 하나도 없다 | **만들거나 전환해야 합니다** |

| Meta 개발자 계정 | **확인 못 함** | Facebook 로그인 필요 | 회장님(휴대폰 본인확인) |

### ★ 만들어야 하는 목록 (회장님이 직접)

1. **온스토리 인스타 계정** — 개인 계정(`nivs_poem`)으로 발행하면 안 됩니다.
   사업용 계정을 새로 만들고 **프로페셔널(비즈니스)** 로 전환하십시오.
   ⚠ 손님 사장님들의 영상이 나가는 창구라 개인 계정과 섞이면 나중에 되돌리기 어렵습니다.
2. **온스토리 페이스북 페이지** — 인스타 발행 API 는 페이지 연결이 **필수**입니다.
   페이지는 제가 만들 수 있습니다(로그인만 되면).
3. **둘을 연결** — 인스타 앱 → 설정 → 계정 연결.
4. **Meta 개발자 등록** — 휴대폰 본인확인이 필요해 회장님이 하셔야 합니다.

## 6. 반려당하는 흔한 이유 (미리 피할 것)

1. **시연 영상에 권한 동의 화면이 안 나옴** — 사용자가 "허용"을 누르는 장면이 꼭 있어야 한다.
2. **테스트 계정으로 녹화** — 개발자 대시보드의 테스트 사용자 말고 **진짜 인스타 프로페셔널 계정**으로 찍어야 한다.
3. **데이터 삭제 URL 없음** — 자동 반려.
4. **권한 설명을 복사해 붙임** — 권한마다 다르게 써야 한다.
5. **필요 없는 권한까지 요청** — 우리가 쓸 4개만 요청한다.
6. **한 번에 여러 건 자동 발행하는 장면** — 사용자가 매번 직접 누르는 흐름으로 보여야 한다.
   ⚠ 우리 기획(하루 3건 자동 발행)이 여기 걸릴 수 있다. **사장님이 "발행" 을 누르는 화면**을 반드시 만들어야 한다.

# 사업자등록증 — 검사 결과 (2026-09-07)

## ⚠ 먼저 경위를 바로잡는다

회장님이 「화면 인쇄로 보인다」고 들으신 그 기록은 **이 파일에 대한 것이 아니다.**

근거는 실제로 있었다 — `Producer = Microsoft: Print To PDF` · **글꼴 0개** · 그림 6개 · 전자서명 없음.

그리고 그 기록은 이렇게 끝나 있었다:

> 「파일 표시만으로 단정할 수는 없습니다. **회장님 확인을 따릅니다.**」

즉 **근거는 있었고 결론은 유보**였다. 전달 과정에서 그 유보가 빠지고 단정처럼 읽힌 것으로 보인다.
재발급까지 받으시게 된 점은 죄송하다. **다만 새 파일은 옛 파일보다 확실히 낫다** — 아래가 그 근거다.

## 검사 결과 — `etc/사업자등록증.pdf`

| 항목 | 값 | 판정 |
|---|---|---|

### 옛 파일과의 결정적 차이

| | 옛 `ianworldsaup.pdf` | **새 `사업자등록증.pdf`** |
|---|---|---|
| 생성 도구 | Microsoft: Print To PDF | PDFium |

**글꼴 0개 → 2개.** 이게 핵심이다. 옛 파일은 글자를 선택할 수 없는 그림 덩어리였고,
새 파일은 **글자가 글자로 들어 있다.** Meta 가 거부하는 「화면 캡처」의 특징이 바로 전자다.

만약 그래도 반려되면 그때는 홈택스 **[My홈택스 → 증명 발급 → 사업자등록증명원]** 의

# 2026-09-07 8단계 착수 시도 — ⚠ **개발자 등록에서 막혔다. 회장님이 하셔야 한다**

회장님이 8단계(앱 만들기·이용 사례 켜기)를 승인하셔서 바로 들어갔다.
**앱 만들기 화면에 닿지 못했다.** 그 앞에 관문이 하나 더 있었다.

## 무엇이 막혔나

`developers.facebook.com/apps/` 로 갔더니 **앱 목록이 아니라 홍보용 첫 화면으로 되돌려졌다.**
상단 내비게이션을 확인하니 이렇게 돼 있었다:

| 보인 것 | 뜻 |
|---|---|
| **「시작하기」** · 링크 주소 **`/async/registration/`** | **아직 Meta 개발자로 등록되지 않았다** |
| (등록돼 있으면) 「내 앱」 | 등록된 계정은 여기가 앱 목록으로 간다 |

즉 **로그인은 돼 있으나(권병철) 개발자 등록이 안 돼 있다.**
페이스북 계정이 있다고 개발자가 되는 것이 아니라 **별도 등록 절차**가 있다.

## ⚠ 왜 제가 대신 누르지 않았나

개발자 등록은 이 셋을 포함한다:

1. **Meta 플랫폼 약관·개발자 정책 동의** — 회장님 명의로 맺는 **법적 약정**이다
2. **이메일 / 전화 본인 인증** — 인증 코드가 온다
3. 계정 유형 선택

**계정을 만들거나 본인 인증 코드를 다루는 일은 제가 하지 않는다.**
승인해 주셨더라도 이건 회장님이 직접 누르셔야 하는 종류다. 대신 눌러 드리는 것이
편해 보여도, 회장님 명의의 약정을 제가 체결하는 것이 되기 때문이다.

## 회장님이 하실 것 — PC 크롬, 3분

1. 크롬에서 **`developers.facebook.com`** 접속 (권병철 계정으로 로그인된 상태 그대로)
2. 오른쪽 위 **[시작하기]** 클릭
3. **[다음]** → 개발자 약관·정책 화면에서 **[수락]**
4. **전화번호 인증** — 문자로 온 코드 입력
5. **이메일 확인** (이미 확인된 계정이면 건너뜁니다)
6. 「무엇에 관심이 있으신가요?」 → **아무거나 고르셔도 됩니다** (심사와 무관합니다)
7. 끝나면 화면 오른쪽 위가 **[시작하기] → [내 앱]** 으로 바뀝니다

**7번까지 되면 알려 주십시오. 거기서부터 제가 이어받습니다.**

### 4번이 왜 「진짜 확인」인가

지금까지 인스타 연결은 **Business Suite 화면**으로만 확인했다
(팔로워 1.9천 · [릴스 만들기] 버튼 등 — 근거는 충분하다).
하지만 **우리 코드가 실제로 쓰는 것은 Graph API 응답**이다. 앱이 생기면
그래프 API 탐색기에서 이렇게 물어 확인한다:

```
GET /{page-id}?fields=instagram_business_account
     → page-id = 1328742146980908 (페이지 「스토리온」)
```

여기서 **`instagram_business_account` 의 `id` 가 실제로 돌아오면** 연결이 API 수준에서 확정된다.
값이 안 나오면 화면은 연결처럼 보여도 **발행이 안 된다.** 그래서 이 조회를 미뤄 두지 않고
앱 만든 직후 **첫 작업**으로 한다.
