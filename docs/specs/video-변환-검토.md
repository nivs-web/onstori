# 60초 세로 영상 — 변환 수단 검토 (2026-09-07)

회장님 지시로 **Cloudflare Stream 을 1순위**로 검토했다. 요금은 공식 문서에서 확인했다.
**결정은 회장님이 하신다. 아직 구현하지 않았다.**

출처: <https://developers.cloudflare.com/stream/pricing/> ·
<https://developers.cloudflare.com/stream/viewing-videos/displaying-thumbnails/>

---

## 왜 변환이 필요한가 (이게 핵심이다)

**안드로이드에서 찍은 영상이 아이폰에서 안 나온다.**
`/rec` 은 브라우저 MediaRecorder 로 찍는데, 안드로이드 크롬은 **webm(VP8/VP9)** 을,
아이폰 사파리는 **mp4(H.264)** 를 만든다. **아이폰 사파리는 webm 을 못 연다.**
사장님이 안드로이드로 찍은 영상을 손님이 아이폰으로 보면 **까만 화면**이다.

즉 변환은 "화질 개선"이 아니라 **절반의 손님이 영상을 볼 수 있느냐**의 문제다.

## 1순위 — Cloudflare Stream

| 항목 | 요금 |
|---|---|
| 저장 | **$5 / 1,000분** (선불, $5 단위) |
| 전송 | **$1 / 1,000분** (후불, 쓴 만큼) |
| 인코딩·업로드 | **무료** |
| 적응형 화질(여러 화질 자동 생성) | **무료** (저장 용량에 안 잡힌다) |
| 표지 이미지(썸네일) | **무료** — 첫 프레임 자동, `?time=3s` 로 원하는 지점도 가능 |
| 대역폭(egress) | **전송 요금에 포함**, 별도 없음 |
| 최소 약정 | 없음. 다만 저장이 선불 $5 단위라 **사실상 월 $5 부터** |

### 우리 규모(고객 100명 × 영상 20편 × 60초) 월 비용

저장은 2,000분 = **월 $10 고정**. 전송은 **얼마나 보느냐**에 전부 달렸다.

| 영상 1편당 월 시청 | 전송량 | 전송비 | **합계/월** |
|---|---|---|---|
| 10회 | 20,000분 | $20 | **$30** (약 4만원) |
| 30회 | 60,000분 | $60 | **$70** (약 10만원) |
| 50회 | 100,000분 | $100 | **$110** (약 15만원) |
| 100회 | 200,000분 | $200 | **$210** (약 29만원) |
| 300회 | 600,000분 | $600 | **$610** (약 85만원) |

⚠ **전송비는 상한이 없다.** 사이트가 잘 되면 그만큼 는다.
고객 100명이 월 49,900원 = 490만원 매출일 때, 10~30회 구간이면 매출의 1~2% 로 무난하지만
100회를 넘어가면 눈에 띄기 시작한다.
⚠ 시청 횟수는 **아직 아무 데이터도 없다.** 위 표는 가정이고, 실제로는 첫 10명으로 재봐야 한다.

**장점**: 서버 관리 0. 변환·표지·적응형 화질·CDN 이 다 들어 있다. 이미 Cloudflare 를 쓰고 있다.
**단점**: 전송량에 비례해 비용이 는다. 영상 파일이 우리 R2 가 아니라 Stream 에 갇힌다
(규칙 10 "원본을 지우지 않는다" 는 R2 원본을 그대로 두면 지킬 수 있다).

## 2순위 — 별도 워커에서 ffmpeg

작은 서버(또는 사무실 PC) 하나에서 ffmpeg 로 변환하고 결과를 R2 에 올린다.

- **비용**: 작은 VPS 월 $5~6 **고정**. 전송은 R2 라 **egress 무료**.
  시청이 아무리 늘어도 비용이 안 는다 — Stream 과 정반대 성질이다.
- **난이도**: 중~상. 대기열·재시도·실패 알림·서버 감시를 우리가 만들어야 한다.
  자막 워커(STEP 4)가 어차피 필요하니 **같은 워커에 얹으면 추가 부담은 작다.**
- **위험**: 사람이 켜 둬야 한다. 죽으면 영상이 `uploaded` 에서 멈춘다(지금도 그 상태다).

## 3순위 — 브라우저에서 미리 압축

찍는 순간 해상도·비트레이트를 낮춰 올린다.

- **비용 0.** 표지 이미지는 canvas 로 그 자리에서 뽑을 수 있다.
- **하지만 근본 문제를 못 푼다** — 안드로이드는 여전히 webm 을 만들고,
  아이폰에서 안 나오는 건 그대로다. 용량만 줄 뿐이다.
- 다른 방법과 **같이** 쓰면 좋다(올리는 용량이 줄어 업로드가 빨라진다).

## 정리

| | 초기 난이도 | 월 비용 | 시청 늘면 | 아이폰 문제 해결 |
|---|---|---|---|---|
| Cloudflare Stream | **낮음** | $30~210 | **같이 는다** | ✅ |
| 별도 워커 + ffmpeg | 중~상 | **$5~6 고정** | 안 는다 | ✅ |
| 브라우저 압축 | 낮음 | 0 | — | ❌ |

**회장님 결정이 필요한 것: 위 셋 중 무엇으로 갈지.**
판단 기준은 "손님이 영상을 얼마나 볼 것 같은가" 하나다.
- 적게 볼 것 같다 → **Stream** (관리 0, 월 4만원 안팎)
- 많이 볼 것 같다 / 비용을 고정하고 싶다 → **워커** (자막 워커와 겸용)

⚠ 어느 쪽이든 **원본 webm 은 R2 에 그대로 둔다**(규칙 10).
