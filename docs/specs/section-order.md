## 1. `page_sections` 에 순서 칸이 있는가 — **있다**

`supabase/migrations/20260906160000_admin_members.sql`

```sql
create table if not exists page_sections (
  id         text primary key,     -- 'inside' 같은 섹션 식별자
  label      text not null,        -- 어드민 화면에 보일 이름
  visible    boolean not null default true,
  sort       int not null default 100,   -- ★ 이미 있다
  updated_at timestamptz not null default now()
);
```

**`sort` 칸이 이미 있고 값도 들어 있다**(inside 10 · portfolio 20 · channels 30 …).
따라서 **스키마 변경도 db push 도 필요 없다.** 이건 좋은 소식이다.

문제는 그 값을 **아무도 안 쓴다**는 것이다.

- `lib/page-sections.ts` 의 `sectionVisibility()` 는 `select("id, visible")` 만 읽는다 — `sort` 를 버린다.
- 그래서 지금 `sort` 는 **어드민 화면에서 줄 세우는 용도**로만 쓰인다(`sectionRows()`). 첫 페이지는 모른다.

## 3. 걸림돌 하나 — 배경색 번갈아 쓰기

규칙 11: **같은 배경을 연속으로 두지 않는다**(흰 → 연회색 → 어두운).
지금은 사람이 손으로 맞춰 놨다(`surface-0` / `surface-50` / `surface-900`).

순서를 자유롭게 바꾸면 **어두운 섹션 두 개가 붙는 일**이 반드시 생긴다. 그러면 경계가 사라져
한 덩어리로 보인다. 그래서 순서 기능을 붙일 때는 배경을 섹션에 고정하지 말고
**나열된 자리에 따라 자동으로 번갈아 주는 방식**으로 바꿔야 한다.

이게 이 작업에서 제일 손이 많이 가는 부분이다. 순서 바꾸는 화면 자체는 쉽다.

## 4. 붙이는 방법 (권장안)

**한 번에 다 하지 말고 두 단계로 나눌 것을 권한다.**

### 단계 1 — 순서만 (권장, 먼저)
1. `app/page.tsx` 의 섹션 18개를 각각 함수로 쪼개 `const SECTIONS: { id, label, node }[]` 배열로 만든다.
2. `sectionVisibility()` 를 `sectionOrder()` 로 넓혀 `sort` 까지 읽는다.
3. `page.tsx` 는 배열을 `sort` 로 정렬해 그린다.
4. 배경은 `surface-*` 를 섹션에 박지 말고 **나열된 순서(index)에 따라** 흰/연회색/어두움을 돌린다.
   ⚠ 히어로는 항상 첫째이고 흰 배경 고정이다 — 돌리는 대상에서 뺀다.
5. `page_sections` 에 빠져 있는 13개 행을 **마이그레이션 파일로** 추가한다(insert 만, 스키마 변경 없음).
   ⚠ 이건 db push 가 필요하다 — 회장님 승인 사항.

### 단계 2 — 끌어서 옮기는 화면
6. `/admin/pages` 에 위·아래 화살표 버튼을 먼저 붙인다(끌기보다 폰에서 훨씬 잘 된다).
7. 끌어서 옮기기는 그다음. 라이브러리를 새로 넣지 말고 HTML5 드래그로 충분하다.

⚠ **끌기(drag)는 폰에서 잘 안 된다.** 손가락으로 끌면 화면이 같이 스크롤된다.
   회장님이 폰으로도 만지실 거라면 **화살표 버튼이 정답**이고, 끌기는 PC 전용 덤이다.
