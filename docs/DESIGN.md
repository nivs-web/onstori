## 0. v5 에서 바뀐 것 (v1 을 읽었던 사람용)

1. **명조(Noto Serif KR)를 완전히 폐기했다.** 글꼴은 **Pretendard 하나**다.
   제목은 서체가 아니라 **굵기와 자간**으로 낸다.
   이유: 화면당 서른 글자 남짓 쓰자고 한글 세리프 **405KB** 를 받고 있었다(Lighthouse 실측).
   빌드 산출물 `.next/static/media` 가 **6.4MB → 64KB** 로 줄었다.
2. **본문이 16px → 17px**, 행간 1.68, 자간 -0.015em.
3. **보조 버튼이 테두리에서 "면"으로 바뀌었다.** 테두리 버튼이 여럿이면 화면이 격자처럼 보인다.
4. **사진 카드에 호버를 넣었다.** v1 에서 뺐던 것을 v5 에서 규칙을 정해 되살렸다(§6).
5. 간격·모서리 값이 촘촘해졌다(`--s-2` 8→6, `--r-md` 12→10 등).
6. 섹션 모양을 **여덟 가지로 못 박았다**(§7).

## 1. 토큰 (globals.css `:root`)

| 갈래 | 토큰 | 쓰임 |
|---|---|---|
| 초록 | `--green-50` … `--green-900` | 브랜드. **`--green-700` 이 로고 ON 그린이자 주 버튼 색** |
| 중성 | `--n-0` … `--n-900` | 바탕·글자·테두리. 화면의 대부분 |
| 포인트 | `--accent` `--accent-soft` `--accent-ink` | 주황. **"남은 자리"·가격 강조에만** |
| 경고 | `--danger` `--danger-soft` | 오류·삭제·결제 실패 |
| 글꼴 | `--sans` | **하나뿐이다.** Pretendard Variable(자체 호스팅) |
| 글자 크기 | `--t-display` … `--t-caption` | clamp 로 폰↔PC 를 잇는다 |
| 굵기 | `--w-bold`(700) `--w-semi`(600) `--w-med`(500) `--w-reg`(400) | **이 넷 밖은 금지** |
| 자간 | `--ls-display` … `--ls-eyebrow` | 컴포넌트에 letter-spacing 을 적지 않는다 |
| 행간 | `--lh-display` `--lh-h1` `--lh-h2` `--lh-body` `--lh-lead` | |

| 모서리 | `--r-xs`(4) `--r-sm`(6) `--r-md`(10) `--r-lg`(16) `--r-full` | |
| 그림자 | `--shadow-1` `--shadow-2` `--hv-shadow` | 셋뿐 |

| 레이아웃 | `--container` `--gutter` `--section-y` `--measure` `--control-h` `--btn-px` `--tap` `--bar-h` `--dock-h` | |

### Tailwind 유틸리티도 토큰이다

`@theme inline` 으로 등록해 뒀다 — `bg-n-50` · `text-green-700` · `border-danger` 가
곧 `var(--n-50)` 이다. **`neutral-500` · `teal-600` 같은 Tailwind 기본색은 쓰지 않는다.**

### 레거시 별칭

`--forest` `--lime` `--cream` `--muted` `--line` 등 옛 이름 수백 곳이 남아 있다.
전부 위 토큰을 가리키도록 값만 바꿨다. **새 코드에서는 쓰지 않는다.**

⚠ **`--accent` 는 의미가 바뀌었다.** 예전엔 초록, 지금은 **포인트 주황**이다.
⚠ **`--font-display` 는 이제 명조가 아니라 Pretendard 다.** `.font-display` 클래스도 마찬가지.

### 고객 사이트는 별개다

`app/[slug]` 는 사장님이 고른 팔레트를 `--s-bg` 등으로 인라인 주입한다. 그 **색** 스코프는
이 토큰 체계와 **무관**하다. 여기 §2~§9 는 본사 화면(랜딩·메뉴·위저드·에디터·어드민)에 적용된다.

★ **2026-09-17 개정 — 「별개」가 「규칙 없음」은 아니다.**
  그동안 고객 사이트에는 **여백·띠·전환에 대한 규칙이 아예 없었다.** 그 결과 PC 에서
  폰과 같은 여백을 쓰고, 같은 바탕색 섹션이 넷씩 이어졌다(2026-09-17 실측).
  ⇒ **고객 사이트의 규칙은 §10 에 따로 적는다.** 색만 사장님 팔레트를 따르고,
    **뼈대(여백·띠·전환)는 §10 이 정한다.**

## 2. 색 — 비율이 규칙이다

| 몫 | 비율 | 무엇 |
|---|---|---|
| 중성 바탕 | **70%** | `--n-0` 흰색 · `--n-50` 연회색 · `--n-900` 어두운 섹션 |
| 글자 회색 | **20%** | `--n-700` 본문 · `--n-900` 제목 · `--n-500` 보조 |
| 초록 | **8%** | 주 버튼 · 링크 · 선택 상태 |
| 포인트 주황 | **2%** | **"남은 자리"·가격 강조에만.** 그 외 사용 금지 |

주황을 아이콘·배지·구분선에 뿌리기 시작하면 2%가 아니게 되고, 정작 가격이 눈에 안 띈다.

## 2-1. 대비 — 못 박은 규칙 (2026-09-07)

**본문 4.5:1 이상 · 큰 제목(24px 이상 굵게) 3:1 이상.** 예외 없다.

### 밝은 면 위에서 글자로 쓸 수 있는 회색

실측표(2026-09-07, 흰 배경 기준):

| 토큰 | --n-0 위 | --n-50 위 | --n-100 위 | 글자로? |
|---|---|---|---|---|
| `--n-400` | 2.06 | 1.89 | 1.77 | ❌ **플레이스홀더 전용** |
| `--n-500` | 2.78 | 2.55 | 2.39 | ❌ 금지 |
| `--n-600` | 4.04 | 3.71 | 3.47 | ❌ 금지(본문 기준 미달) |
| `--n-700` | 6.17 | 5.66 | 5.30 | ✅ **여기부터 안전** |
| `--n-800` | 11.01 | 10.10 | 9.45 | ✅ |
| `--green-700` | 8.30 | 7.61 | 7.12 | ✅ |

⚠ **`--n-500`·`--n-600` 은 글자에 쓰지 않는다.** 면·테두리·아이콘용이다.
보조 정보는 **색을 옅게 해서가 아니라 크기·굵기로** 낮춘다.

### 그래서 글자는 의미 토큰으로만 쓴다

```
--text-strong   제목      (밝은 면 --n-900 / 어두운 면 --n-0)
--text          본문      (밝은 면 --n-700 / 어두운 면 --n-200)
--text-soft     보조      (밝은 면 --n-700 / 어두운 면 --n-400)
```

`.surface-900` 안에서 이 셋이 **자동으로 뒤집힌다.** 컴포넌트는 `--text` 만 쓰면 되고
밝은 면인지 어두운 면인지 신경 쓸 필요가 없다.
⚠ 이게 없던 동안 비교표의 회색 글자가 어두운 배경 위에 그대로 얹혀 **1.78:1** 이었다.

### 사진 위 글자

**스크림과 그림자를 항상 같이 쓴다.** 둘 중 하나만으로는 밝은 사진에서 글자가 사라진다.

1. `--scrim` — 사진 **전체**를 덮는 그라데이션. 위 28% → 35% 지점 18% → 아래 92%.
   ⚠ 아래쪽에만 깔면 **밝은 사진에서 위쪽 제목이 흰 배경에 흰 글자**가 된다.
   2026-09-07 손님 사이트 히어로에서 실제로 안 읽혔다.
2. `.on-photo` — 흰 글자 + `text-shadow: 0 1px 3px rgba(0,0,0,.4)`. 스크림이 모자랄 때의 최후 보루.
3. 잰다. 히어로 제목 실측 **14.90:1**, 최저 본문 **4.55:1** (interior2, 390·768·1440).

### 재는 법

`scratchpad/contrast.js` — 글자를 잠시 투명하게 만들고 그 자리를 캡처해 **실제 화면 픽셀**로
배경색을 구한다. 사진·그라데이션 위 글자는 CSS 배경색만 봐서는 알 수 없기 때문이다.
⚠ 두 가지를 조심한다: ①등장 애니메이션을 꺼야 한다(페이드 중에 재면 배경이 섞인다)
②사진이 늦게 들어오면 레이아웃이 밀려 좌표가 어긋난다 — 가린 직후 좌표를 다시 읽는다.
그래도 지연 로딩이 많은 페이지에서는 오검출이 남는다. **의심스러우면 DOM 에서
배경색을 직접 읽어 손으로 확인해라.**

## 3. 글자 — 서체는 하나, 차이는 굵기로

- **글꼴은 Pretendard Variable 하나다.** 자체 호스팅(`app/fonts.css`, `ascent-override: 92%`).
- 굵기: **Display·H1 = 700 / H2·H3 = 600 / 라벨 = 500 / 본문 = 400.** 그 외 금지.
- 본문 **17px** · 행간 **1.68** · 자간 **-0.015em** · `word-break: keep-all`.
- ⚠ **한글은 라틴보다 행간이 필요하다. 제목 행간을 1.2 아래로 내리지 않는다.**
  (`--lh-h1` 1.36 · `--lh-h2` 1.4 · `--lh-display` 1.32)
- 본문 한 줄 최대 **38em**(`.measure`). 중앙 정렬 헤드는 **36em**(`.head-center`).
- 숫자는 `tabular-nums` — body 에 전역으로 걸었다.
- 클래스: `.t-display` `.t-h1` `.t-h2` `.t-h3` `.t-lead` `.t-body` `.t-small` `.t-caption` `.kicker`.

**본문 글자는 어디서도 17px 미만으로 내려가지 않는다.** 보조 정보는 `--t-small`(15) 까지,
캡션·법적 고지만 `--t-caption`(13).

## 4. 버튼

- **주 버튼(초록 면)은 뷰포트당 1개.** 두 개가 같이 보이면 손님은 무엇을 눌러야 할지 모른다.
- 높이 **52** (모바일 48) · **17px/600** · 좌우 패딩 **20** · 모서리 `--r-md`.
- **터치 목표 최소 48×48.** 아이콘 버튼도 예외 없다.

```
.btn .btn-primary     초록 면 · 흰 글자      hover --green-500   — 뷰포트당 1개
.btn .btn-secondary   연회색 면 --n-100      hover --n-200       — 그 외 전부
.btn .btn-text        글자만                                     — 부수적 행동
.btn .btn-danger      --danger 면                                — 삭제·해지
어두운 배경 위 보조 = 흰 면 14% + 흰 글자 (.surface-900 .btn-secondary)
```

⚠ **보조 버튼은 테두리가 아니라 면이다.** 테두리 버튼이 여럿 있으면 화면이 격자처럼 보인다.

⚠ **페이지 끝 `CtaBand` 가 그 페이지의 주 버튼이다.** 바로 위 섹션의 CTA 는 보조로 내린다 —
안 그러면 한 화면에 초록 버튼이 둘 잡힌다(2026-09-07 how-it-works·reviews·blog 에서 실제로 그랬다).
위젯 조작 장치(랜덤 질문 바꾸기 등)도 주 버튼이 아니다. 전환 버튼만 초록이다.

## 5. 카드와 사진

- 카드: 배경 `--n-0` · 테두리 1px `--n-200` · 모서리 `--r-lg` · **기본 그림자 없음**.
- **사진에 테두리·여백을 두지 않는다.** 사진이 주인공이다.
- **사진 카드는 4:3 고정**(`.photo`). 비율을 고정해야 로딩 중 화면이 안 튄다(CLS).

## 6. 호버 — 사진이 있는 모든 곳

```
.card-photo          → 카드는 8px 떠오르고(300ms) 그림자가 생기며 테두리가 사라진다
.card-photo img      → 사진만 1.08 배로 커진다 (400ms)
```

**왜 사진만 커지나** — 카드를 키우면 옆 카드를 밀어 레이아웃이 통째로 흔들린다.
카드는 **위로 뜨기만** 하고, 확대는 사진에만 건다. 부모에 `overflow: hidden` 이 필수다.
카드 300ms / 사진 400ms 로 **시간을 다르게 준다** — 같으면 움직임이 납작하다.

**적용**: 실적·포트폴리오·갤러리·블로그 카드, 좌우 교대 사진, 전폭 사진(1.04로 약하게).
**미적용**: 히어로 · 로고 · 아이콘.

**폰에서는 호버를 흉내 내지 않는다.** `@media (hover: hover)` 로 감쌌고,
손가락 화면에서는 `:active` 에 `scale(0.98)` 120ms 만 준다.

| # | 모양 | 클래스 |
|---|---|---|
| ① | 히어로 | (페이지별) |
| ② | 중앙 정렬 헤드 (최대 36em) | `.head-center` |

## 9. 완료 조건 (검사 항목)

- `globals.css` 밖에 하드코딩된 **색상값 · letter-spacing · box-shadow · border-radius ·
  transition · animation** 0건.
- **`Noto Serif` 참조 0건.**
- MOTION.md 금지 목록 0건 · 호버 규칙 적용 확인.
- 390 · 768 · 1440 에서: 가로 넘침 0 · 터치 48 미만 0 · 본문 17 미만 0 ·
  주 버튼 뷰포트당 2개 이상 0 · 카드/사진 기본 그림자 0(hover 제외).

### 문서화된 예외 5가지

1. **라벨이 감싼 체크박스** — 네모는 24px 이지만 누르는 자리는 `<label>`(높이 48)이다.
2. **손님 사이트 푸터의 숨은 에디터 진입로** — 손님에겐 그냥 글자로 보여야 한다.
3. **남의 브랜드 색** — 카카오 노랑 `#FEE500` · 채널 아이콘 6종(유튜브·인스타·쓰레드·X·네이버).
   토큰은 온스토리 화면의 색을 정하는 것이지 남의 로고 색을 정하는 게 아니다.
4. **PWA 매니페스트**(`app/manifest.ts`) — JSON 이라 CSS 변수를 쓸 수 없다.
5. **자동 생성 로고 SVG**(`app/new/wizard.tsx`) — 사장님 파일로 저장되는 그림이다.
   보는 사람 컴퓨터의 글꼴로 그려지므로 var() 를 넣을 수 없다.
6. **글 안의 인라인 링크** (약관·개인정보처리방침의 "제7조" 같은 상호 참조).
   문장 한가운데 있는 링크를 48px 로 키우면 줄 간격이 무너져 글을 못 읽는다.
   문단에서 떨어져 나온 링크·버튼은 예외가 아니다 — 48을 지킨다.

## 10. 고객 사이트(`app/[slug]`) — 뼈대 규칙 (2026-09-17 신설 · 지시 [19]③)

> 색은 사장님 팔레트(`--s-*`)를 따른다. **뼈대는 여기가 정한다.**
> 감싸개 클래스는 `.site-shell` 이다(`app/[slug]/page.tsx`). 본사 화면은 이 클래스 «밖»이라
> 여기 규칙에 **한 픽셀도 영향받지 않는다.**

### 10-1. 여백 — 폰과 PC 를 다르게

| | 폰 | PC(≥768) |
|---|---|---|
| 섹션 세로 여백 | **64** (`--section-y`) | **120** (`--section-y-lg`) |
| 좌우 여백 | **20** (`--gutter`) | **32** (`--gutter-lg`) |

⚠ **2026-09-17 이전에는 PC 에서도 64/20 이었다.** 1440px 화면에서 글이 가장자리에 붙고
  섹션이 다닥다닥 붙어 **「폰 화면을 늘려 놓은 것」**처럼 보였다.
★ 새 값을 만든 것이 아니다 — 원래 있던 토큰을 고객 사이트가 **안 쓰고** 있었을 뿐이다.
  `.site-shell` 안에서 `--section-y`·`--gutter` 를 큰 값으로 갈아 끼운다.
🔴 섹션 컴포넌트는 **`var(--section-y)`** 를 쓴다. `var(--s-8)` 을 직접 쓰지 마라 —
  그러면 PC 에서 다시 64 로 굳는다.

### 10-2. 띠(band) — 같은 바탕을 연속으로 두지 않는다

§7 의 규칙을 고객 사이트에도 적용한다. 계산은 **한 곳**(`bandsOf`, `components/sections/index.tsx`)에서 한다.

| 섹션 | 바탕 |
|---|---|
| 히어로 | 사진 |
| **숏폼 무대** | **검정** |
| 견적 문의 | `--s-soft` (스스로 정한다) |
| 띠 배너 | `--s-accent` (스스로 정한다) |
| **그 밖 전부** | `--s-bg` ↔ `--s-soft` **번갈아** |

- ① 앞 칸과 **반드시 다른** 색을 고른다.
- ② 다음 칸이 자기 색을 갖고 있고 그것과 겹치면 뒤집어 본다.
- ③ 앞뒤가 다 막혀 뒤집을 수 없으면 — 색은 같아도 **`--s-line` 한 줄**로 경계를 만든다.

🔴 **새 색을 만들지 않는다.** 쓰는 것은 팔레트가 이미 가진 `--s-bg`·`--s-soft`·`--s-line` 셋뿐이다.

### 10-3. 숏폼 무대의 전환 — 검게 들어가고 밝게 나온다

| | 어떻게 |
|---|---|
| **들어갈 때** | `.stage::before` 가 무대 **위**(`top: -120px`)에 걸려 **히어로의 마지막 한 뼘을 검게 잠근다** |
| **나올 때** | `.stage + *` 의 위 150px 가 검정 → 투명 그라데이션. 감싸개에 위 여백 110px 을 줘 **제목이 검은 부분에 갇히지 않게** 한다 |

⚠ **`box-shadow` 로 흉내 내지 마라.** 처음에 그렇게 했더니 경계에 **회색 얼룩**만 생기고
  「화면이 다 까맣게 변하면서」가 되지 않았다.
⚠ 감싸개 배경은 **`background-color`** 로 준다. 줄임 표기 `background` 를 쓰면
  그것이 `background-image` 까지 지워 **그라데이션이 사라진다**(2026-09-17 실측으로 잡았다).

### 10-4. 「움직임 줄이기」 — 가두기는 **CSS 로만** 만든다

무대의 가두기는 «바깥 높이 + `position: sticky`» 두 줄이다. **JS 로 스크롤을 가로채지 않는다.**
그래서 `prefers-reduced-motion: reduce` 에서 **높이를 `auto` 로 되돌리기만 하면**
평범한 세로 목록이 된다(화면이 깜빡이지 않는다).

🔴 **스크롤 잭킹 금지**(`docs/MOTION.md`). 뒤로 가기·검색·스크롤바가 전부 망가진다.

### 10-5. 아직 안 한 것

- **카드 그림자·버튼 모양**은 이번에 손대지 않았다. 고객 사이트 카드는 지금 `--s-line` 테두리 +
  `--s-soft` 면으로만 구분한다. 그림자를 넣을지는 **정해진 바 없다.**
- **글자 크기**는 본사와 같은 17px/1.68 을 그대로 쓴다. PC 에서 키울지는 **정해진 바 없다.**
