# 관리자 어드민 기획 (본사 운영자 전용)

위치: `onstori.com/admin` — 고객용 `onstori.com/{slug}/admin`(P7)과 별개인 **운영자 콘솔**.

## 권한

- P4(인증) 전: `ADMIN_KEY` 환경변수 + 쿠키 게이트 (키 입력 1회 → httpOnly 쿠키). 외부 노출 최소화를 위해 robots 차단 + noindex.
- P4 후: Supabase Auth 로그인 + **이메일 화이트리스트**(운영자 계정만). ADMIN_KEY 방식 제거.
- 데이터 접근: 어드민 API 라우트에서만 service_role 키 사용(서버 전용). 클라이언트에 절대 노출 금지.

## 메뉴 구조

```
/admin
├─ 대시보드        가입·생성·발행·활성 퍼널, 오늘 신청 수, AI 비용 요약
├─ 이미지뱅크 관리  ★ 아래 상세
├─ 사이트 관리      전체 사이트 목록(슬러그·업종·상태·만료일), 상태 변경, 미리보기
├─ 신청 접수함      당근/지인 무료 제작 신청 관리 (선판매 트래커의 시스템화)
├─ 무비 주문 관리    movie_orders 상태 보드 (P6)
└─ 설정            예약 슬러그 관리, 운영자 목록
```

도입 순서: P2-후반(이미지뱅크 관리 최소판 + 사이트 목록) → P3(신청 접수함) → P6(무비 보드) → P7(대시보드 지표).

## ★ 이미지뱅크 관리 (상세 기획)

### 목록 화면
- **썸네일 그리드** (한 화면 60장, 무한 스크롤). 카드에: 썸네일 / 업종·무드·역할 뱃지 / quality 상태(승인·대기·거부) / used_count
- **필터 바:** 업종(14) · 무드(4) · 역할(hero/about/gallery/process) · 품질상태 · 출처(ai:모델명/stock) · 방향(가로/세로)
- **태그 검색:** 부분 일치
- **일괄 작업:** 체크박스 다중 선택 → 승인 / 거부 / 삭제 / 태그 일괄 추가

### 추가 (2가지 경로)
1. **업로드:** 파일 다중 업로드 → 업종·무드·역할·태그 지정 → Storage(bank 버킷) 저장 + 카탈로그 등록. 출처(stock:unsplash 등) 기록 필수 — 라이선스 추적.
2. **AI 생성 패널:** 프롬프트 프리셋(업종×무드×역할 템플릿 자동 조합) + 모델 선택(gemini-3-pro-image=고품질 / 3.1-flash-image=대량) + 장수(1~8) → 생성 결과가 "대기" 상태로 그리드에 들어옴 → 눈으로 승인/거부. **생성 건당 비용 로깅.**

### 수정
- 카드 클릭 → 상세 패널: 원본 보기, 업종/무드/역할/방향/태그 편집, quality_ok 토글, 사용처(어떤 사이트가 씀) 목록

### 삭제
- 소프트 삭제 기본(quality_ok=false + deleted 플래그) — 이미 사이트가 참조 중이면 경고. 사이트에는 생성 시점에 URL이 복사되므로 뱅크 삭제가 기존 사이트를 깨뜨리지 않음(원칙 유지).

### 데이터
- `image_bank` 테이블 (마이그레이션 20260831_image_bank.sql): industry, mood, role, orientation, url, storage_path, source, tags[], quality_ok(null=대기), used_count, deleted, created_at
- Storage 버킷 `bank` (public read — 사이트가 직접 참조 가능해야 함)
- RLS: 공개 정책 없음(서버 전용 접근). 버킷만 public read.

## 신청 접수함 (당근 트랙 지원)

- 로우: 채널(당근/지인/랜딩) · 업체명 · 연락처 · 사진 수신 여부 · 지불의사 답변 · 상태(신청→사진수신→제작중→전달→무료중→전환/해지)
- 무료 만료 7일 전 알림 목록 ("전환 안내 보낼 곳")
- P2에서는 수동(카톡) + 시트, P3에서 폼·접수함 시스템화
