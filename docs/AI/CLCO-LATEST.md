# 화질 원인을 찾았습니다 — 폰 탓이 아니라 **우리가 낮게 요청**하고 있었습니다. 틱톡도 만들었습니다

_2026-09-12 · 커밋 `7cea196`(화질) · `916c656`(틱톡) · 배포 확인 완료_

## 1. ★★ 실측 — 회장님 영상을 직접 재 봤습니다 (ffprobe)

| 항목 | 잰 값 | 판정 |
|---|---|---|
| 해상도 | **720×1280** | ⚠ 우리가 **720p 를 «요청»** 하고 있었습니다 |
| 프레임 | **59fps** (요청 60) | ✅ **안 떨어졌습니다.** 버벅임은 프레임 탓이 아닙니다 |
| 영상 초당비트 | 4.97Mbps | ⚠ **정해 주지 않았습니다.** 60장에 나눠 쓰니 장당 화질이 절반 |
| 소리 | **opus 35kbps** | ⚠⚠ 목소리가 이 제품의 상품인데 35k 입니다 |
| 크기 | 11MB / 17.6초 | 60초 환산 약 38MB |

> **S25 울트라 탓이 아닙니다.** 그 폰은 훨씬 잘 찍습니다. **우리 코드가 낮게 달라고 하고 있었습니다.**

## 2. 고친 것

| | 전 | 후 |
|---|---|---|
| 해상도 | 720p 요청 | **1080×1920 세로** 요청 |
| 프레임 | 안 정함(→60) | **30fps** |
| 영상 초당비트 | 안 정함(→4.97M) | **6Mbps** |
| 소리 | 안 정함(→opus 35k) | **AAC 128kbps** |

★ **30fps 로 «내리는» 것이 화질을 올립니다.** 같은 비트를 절반의 장수에 쓰기 때문입니다.
릴스·쇼츠는 30fps 가 표준이고, 60으로 올려 봐야 그쪽에서 30으로 다시 만듭니다.

★ **용량 계산 (지시하신 대로)**

| | 60초 크기 | 비고 |
|---|---|---|
| 지금까지 | 약 38MB | 720p·60fps |
| **바꾼 뒤** | **약 45MB** | 1080p·30fps. 인스타 상한 300MB 안 |

7MB 늘고 **화면 넓이는 2.25배**가 됩니다. LTE(업로드 10Mbps)로 약 36초, 5G면 훨씬 빠릅니다.

⚠ 모두 `ideal`(가능하면) 로 요청합니다. `exact`(반드시) 로 하면 **못 맞추는 폰에서 카메라가 아예 안 열립니다.**
옵션째 거부하는 기기를 대비해 실패하면 옵션 없이 한 번 더 만듭니다 — **녹화가 안 되는 것이 가장 나쁩니다.**

## 3. 「버벅인다」 — 따로 봤습니다

**프레임은 안 떨어졌습니다**(59/60). 인코딩은 폰이 잘 따라갔습니다. 원인은 다른 둘입니다:

1. **60fps 에 비트를 나눠 써서** 장면이 움직일 때 뭉갭니다 → 30fps 로 바꾸면 장당 2배
2. **720p 를 인스타가 1080 으로 늘려서** 흐려집니다 → 처음부터 1080 으로 보냅니다

## 4. ★ 갤러리에서 고르기 — 브라우저 녹화의 «천장»을 넘는 유일한 길

회장님 말씀이 맞습니다. **삼성·애플이 브라우저에 센서를 다 열어 주지 않습니다** —
손떨림 보정·야간 모드·HDR 은 카메라 앱에만 있습니다. 해상도를 아무리 올려도 못 이깁니다.

- 녹화 화면에 **[갤러리에서 고르기]** 를 넣었습니다 (접어 두어 «찍기» 흐름을 가르지 않습니다)
- 안내: 「**폰 카메라 앱으로 찍은 영상이 가장 좋습니다.**」

### 아이폰(.mov)을 어떻게 할지 — **막지 않는 쪽**으로 정했습니다

| 안 | 판단 |
|---|---|
| 통째로 막기 | ✖ 갤러리에는 mp4 도 있습니다(사파리로 찍은 것·남이 보낸 것). **그 길까지 막힙니다** |
| 변환하기 | ✖ **변환 워커가 없습니다.** 없는 것을 있는 척하지 않습니다 |
| **미리 알리고, 고른 뒤 판정** | ✅ 이것 |

버튼 **옆에 미리** 「아이폰 **기본 카메라**로 찍은 영상(mov)은 아직 못 올려요」를 적어 두고,
고르시면 이미 있는 형식 검사가 그 자리에서 정확히 말합니다.

## 7·8·9. 틱톡 — 만들었습니다

**겉모양 8개를 인스타와 같은 구조로** (`lib/sns/tiktok.ts`). 도메인 인증이 끝났으니
**`PULL_FROM_URL`** — 인스타와 같은 길입니다.

### 틱톡만 다른 것 셋

| | 무엇 | 왜 |
|---|---|---|
| ① | 올리기 전 **`creator_info` 를 반드시 먼저** 부른다 | 틱톡이 준 공개범위 **중에서만** 고르게 해야 합니다. 우리가 지어내면 심사 탈락 |
| ② | 사장님이 **매번** 제목·공개범위·댓글/듀엣/이어찍기를 고른다 | 심사 요건. **미리 골라 두지 않습니다** — 안 고르면 버튼이 안 눌립니다 |
| ③ | 토큰이 **24시간** (인스타는 60일) | 올리기 «직전»에 항상 갱신 + 매일 크론에서도 밀어 둡니다 |

★ 「지난번에는…」 같은 기본값 유도는 **심사 전이라 안 넣었습니다**(지시대로).
★ 틱톡이 「이 계정은 못 켠다」고 한 항목은 **아예 안 보여 줍니다.**
★ **[간단 등록]에서 틱톡을 뺐습니다** — 5초가 깨집니다. 화면이 빼고 **서버가 다시 막습니다.**
  조용히 빼지 않고 「위 [틱톡에 올리기]를 눌러 골라 주세요」라고 그 자리에 적습니다.
★ **다른 SNS 화면은 한 글자도 안 바뀌었습니다** — `extra` 는 선택 항목이라 인스타·유튜브 코드는 그대로입니다.

### 규격 (지시 9)

- 길이 상한은 **계정마다 다릅니다.** 틱톡이 `creator_info` 로 알려 주는 값을 씁니다 — 우리가 정하지 않습니다
- 글자 수는 2200자로 넣었고 **첫 게시로 대조 필요**라고 표에 적어 뒀습니다
- 「가장 짧은 곳에 맞춘다」는 이미 도는 장치가 그대로 처리합니다

## ⚠⚠ 틱톡 첫 게시 전에 **반드시** 확인하실 것 — 도메인 인증 대상

`PULL_FROM_URL` 은 **틱톡에 인증된 도메인**의 주소만 받습니다.
그런데 우리 영상은 **`img.onstori.com`** 에서 나갑니다(사진·영상 저장소).

> **`onstori.com` 만 인증하셨다면 그 주소는 거절됩니다.**
> 실패하면 화면의 [자세한 이유 보기]에 `url_ownership_unverified` 가 뜹니다.
> 그때는 틱톡 콘솔에서 **`img.onstori.com` 을 하나 더 인증**하시면 됩니다.
