끝까지 팠습니다. **원인이 W3C 규격 문서로 확정됐고, 회장님 통찰 세 개가 전부 맞았습니다.**

## 원인 — 「카메라를 한 대만 열 수 있는 폰」

W3C 규격에 이렇게 적혀 있습니다: **「브라우저는 한 세션에 카메라 독점 접근을 요구할 수 있다.」** 안드로이드 폰 다수가 앞·뒤 카메라를 **동시에 못 엽니다.**

그래서 제 옛 코드(옛 것을 켠 채 새 것 열기)는:

| 회장님이 보신 것 | 코드에서 벌어진 일 |
|---|---|
| ③ [허용] → **검은 화면** | 새 카메라를 여는 순간 브라우저가 옛 것을 강제로 끊음 |
| ⑤ 두 번째 허용 뒤 **바뀌기 전 카메라** | deviceId 열기가 실패 → 코드가 «되살리기(원래 카메라)»로 떨어짐 |
| ⑥ 2~3번 반복해야 됨 | 매 누름이 한 번의 시도라, OS가 카메라를 풀 때까지 사람이 계속 누른 것 |

**회장님 지적이 세 개 다 정확했습니다:**
- 「새 것을 여는 게 옛 것을 죽인다」 → 맞습니다. 독점 접근 폰이라 그렇습니다.
- 「되살리기는 되는데 전환은 안 된다」 → 맞습니다. deviceId는 깨지고 facingMode만 됩니다.
- 「먼저 놓고, 기다린 뒤, 새 것을 열어라」 → 그게 정답이었습니다.

## 고친 것 — 순서를 뒤집었습니다

```
① 옛 카메라를 먼저 완전히 놓는다
② OS가 카메라를 풀 시간을 준다 (200 → 450 → 900ms, 점점 길게)
③ facingMode로 반대쪽을 연다 (deviceId 안 씀 — 그게 깨진 경로였음)
```

★ **재시도를 «한 번의 누름 안에서»** 합니다. 릴리스가 느린 폰이라도 사장님이 **여러 번 안 눌러도** 됩니다. 안에서 최대 세 번 시도하고, 그동안 「바꾸는 중…」이 떠 있습니다.

★ **영상만 요청**합니다. 마이크는 쓰던 것을 그대로 들고 가서, 팝업이 「카메라·마이크」로 뜨던 문제가 사라집니다.

## 검증 — 회장님 폰 상황을 흉내 내 3갈래, 각각 «한 번만» 눌러 봤습니다

| 상황 | 한 번 눌러서 | 결과 |
|---|---|---|
| 카메라 한 대만 여는 폰 (회장님 상황) | 전환 성공 | cam-front · 미리보기 live · 마이크 재요청 0 |
| 릴리스가 느려 처음 2번 실패하는 폰 | 내부 재시도로 3번째 성공 | 사장님은 오류를 **안 봄** |
| 반대쪽 카메라가 아예 없는 폰 | 원래 카메라 되살림 | live · 소리 유지 · 버튼 숨김 · 단계 기록 표시 |

## ★ 화면에 «단계마다» 사실을 남겼습니다 (회장님 지시)

실패하면 화면 아래에 이렇게 뜹니다 — **폰에서 그대로 옮겨 주십시오:**

```
전환 실패 · 옛 카메라 놓음 → 오류 NotReadableError(1) → 오류 NotReadableError(2)
→ 오류 NotReadableError(3) → 원래 카메라 되살림 · 권한 granted
```

이게 뜨면 저는 ①어느 단계에서 막혔는지 ②권한이 실제로 뭔지 ③되살림이 됐는지를 한눈에 압니다.

## ▶ 두 폰에서 다시 찍어 주십시오

```
https://onstori.com/rec/sample-interior?k=2958.2e49a437ff53
```

**합격 기준(회장님 것):** 허용을 **한 번만** 눌러 앞↔뒤 양방향 전환. 두 폰 모두.

- 「영상으로」 → 「어느 쪽으로 찍을까요?」에서 고르고 켜면 **그 카메라로 바로** (전환이 아예 필요 없는 길)
- 화면에서 [카메라 전환]을 누르면 **한 번에** (이번에 고친 길)
- 혹시 또 안 되면 **화면 아래 「전환 실패 · …」 줄**을 그대로 알려 주십시오 — 그게 유일한 창구입니다

그다음 아직 못 보신 넷(글씨·카톡 경고·보내기·표지)도 이어서 봐 주십시오.
