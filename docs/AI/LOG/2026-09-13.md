## 김팀장이 확정한 원문을 «코드 안에» 넣었습니다

링크만 적으면 나중에 읽는 사람이 안 들어가 봅니다. **원문이 옆에 있어야 판단이 안 흔들립니다.**

```
support.google.com/youtube/answer/7300965
  "…you will not be able to appeal."
  "You'll need to re-upload the video via a verified API service or via the YouTube app/site."

developers.google.com/youtube/v3/revision_history  (2020-07-28)
  "All videos uploaded via the videos.insert endpoint from unverified API projects
   created after 28 July 2020 will be restricted to private viewing mode."
```

넣은 곳 네 군데: 게이트 판정 파일 · 게이트 읽는 곳 · 관리자 API · **관리자 화면**
(마지막이 제일 중요합니다 — 사람이 실제로 손을 대는 자리라서요).

## ★ 2번은 «한 겹 더» 쌓았습니다

어제 넣은 장치는 **업로드**를 막습니다. 그런데 그것만으로는
**화면에 「정식 공개」라고 적혀 있는데 아무도 못 올리는** 상태가 남습니다.

> 그 상태를 본 사람이 「고장났나」 하고, **그다음에 하는 일이 「감사 표시를 확인 없이 켜는 것」**입니다.
> 바로 그 순간 사장님 영상이 죽습니다.

그래서 **저장 자체를 막았습니다.** 「정식 공개」를 감사 표시 없이 저장하면 거절됩니다.
**문은 한 번에 하나씩만 열립니다** — 감사 통과를 켜고 저장 → 그다음 정식 공개.

**운영에서 실제로 시험했습니다:**

```
바꾸기 전 : 준비 중 · 감사 표시 없음
「정식 공개」 저장 시도 → 거절 ✅
바꾼 뒤    : 준비 중 · 감사 표시 없음   ← 그대로. 아무것도 안 바뀌었습니다
```

화면에도 가장 흔한 착각을 붉은 글씨로 넣었습니다:

> ⚠ 신청서를 **「냈다」**와 **「통과했다」**는 다릅니다. 구글에서 **통과 메일**을 받으신 뒤에만 켜 주세요.

## ★ 김팀장 문서에서 새로 안 것 하나 더

> **그 「감사」는 우리가 준비 중인 «할당량 증액 신청서»와 같은 서식입니다** ("Audit and Quota Extension Form").

즉 그 신청서는 「하루 500건으로 늘리는 **선택**」이 아니라
**「영상을 공개로 올릴 수 있게 만드는 필수 절차」**입니다.
**늦을수록 그 사이 올라간 영상이 전부 버려집니다.** 코드(`lib/sns/limits.ts`)에도 적어 뒀습니다.

## 4번 — review 는 손대지 않았습니다

김팀장 확인대로 review 는 **비공개로만** 올려서 이 위험과 무관합니다.

나중에 누가 여기까지 잠그려 하면 검사가 막습니다.
