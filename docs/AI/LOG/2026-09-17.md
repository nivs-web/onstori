## [16] 가로 카메라로 찍어 **세로 파일**이 나옵니다 — 파일로 증명했습니다

헤드리스 크롬에 **가로 영상을 «가짜 카메라»로 물려** 녹화하고 `ffprobe` 로 뜯었습니다.

```
카메라 원본   : 1080×720  (가로)
중계가 그린 것 : 720×1280, 500장/8초
나온 파일     : h264 720×1280 (세로) + aac 48000 (소리 있음)
```

🔴 **권반장이 가장 걱정하신 「무음 영상」도 안 납니다.** 시키신 다섯(스위치·프레임 측정·소리·
`setShotLand` 유지·`aspectRatio` 유지)을 **전부** 지켰습니다. 스위치는 `CANVAS_RELAY` 하나입니다.

### 🔴 권반장 판단 하나를 고쳐서 보고드립니다 — **카카오톡은 «절반»만 고쳐집니다**

| 카톡에서 생기는 일 | 고쳐지나 |
|---|---|
| 카메라가 **가로로 열린다** | ✅ 고칩니다 |
| 🔴 **아이폰 인앱은 「허용」 창이 아예 안 뜬다** — 카메라가 열리지도 않는다 | ❌ 못 고칩니다 |

⇒ **「사파리로 열어 주세요」 안내를 그대로 뒀습니다.** 빼면 아이폰 카톡 사장님이 막다른 길에 갇힙니다.
★ 다만 **안드로이드 카톡은 이제 그냥 됩니다** — 대표님 걱정의 대부분은 풀립니다.

## [18] 틱톡 — 이제 **우리가 직접 밀어 넣습니다**

도메인 인증이 **영영 필요 없어집니다.** 만들면서 **조용히 실패할 뻔한 것 둘**을 잡았습니다:

1. 🔴 **서명된 주소에 `HEAD` 를 쓰면 403** 입니다(서명은 `GET` 에만 유효).
   제가 처음 넣은 크기 상한 검사가 **늘 0 으로 읽혀 죽어 있었습니다.** `Range: bytes=0-0` 로 고쳤습니다.
2. 🔴 **파일 이름은 `.webm` 인데 내용은 mp4** 였습니다(실측). 이름으로 딱지를 붙였으면
   **틱톡이 거절했을 것**입니다. 파일 머리로 진짜 형식을 봅니다.
3. 덤 — 상태 확인이 잠깐 끊겼을 때 **같은 영상이 두 번 올라갈 수 있던 구멍**을 막았습니다.

## [17] **두 번째 누르기를 없앴습니다**

마지막 화면을 실제로 띄워 확인했습니다:

```
[ ⚡ 한 방에 올리기 ]      → /{상호}/edit?tab=video&oneshot={영상id}#video-list
[ 세부내용 수정해서 올리기 ] → /{상호}/edit?tab=video#video-list
```

한 번만 누르시면 넘어간 화면이 **저절로** 올립니다. 딱 한 번만 돌고, 주소의 표시는 곧바로
지웁니다(새로고침으로 또 올라가지 않게). `#video-list` 앵커로 **영상 칸까지** 데려갑니다.

## [19]③ 디자인 — **글은 한 글자도 안 바꿨습니다**

🔴 「손님 글은 먼저 여쭙는다」 규칙 때문입니다. 바꾼 것은 **여백·배경·전환** 셋뿐입니다.

### 🔴 「평범한 회사 홈페이지」의 가장 큰 이유를 찾았습니다

```

후 : 무대(검정) → 소개(연) → 진행 과정(흰) → 시공 갤러리(연) → 견적(연) → 오시는 길(흰)
```

우리 디자인 문서가 「**같은 배경 연속 금지 — 경계가 사라져 한 덩어리로 보인다**」고 못 박아 뒀는데,
**그 규칙이 손님 사이트에는 적용된 적이 없었습니다.**

### 🔴 PC 에서 **폰과 똑같은 여백**을 쓰고 있었습니다

```
전 : 폰 64/20 · PC 64/20   ← 1440 화면에서도 폰 여백
후 : 폰 64/20 · PC 120/32  ← 원래 정해져 있던 값
```

큰 화면에서 **「폰 화면을 늘려 놓은 것」**처럼 보였습니다.
★ **새 값을 만든 게 아닙니다** — 원래 있던 값을 **안 쓰고** 있었습니다.
⚠ **본사 화면(첫 페이지·에디터·어드민)은 한 픽셀도 안 바뀝니다** — 실측으로 확인했습니다.

### 그리고 **검게 들어갔다 다시 밝게 나옵니다**

히어로의 마지막 한 뼘이 **검게 잠기고**, 무대가 끝나면 검정이 **다음 섹션 색으로 풀립니다.**

이제 바꾸는 길은 **서버 한 곳**이고, 화면은 **묻는지 마는지를 받아서 보여 줄 뿐**입니다.

**「지금 비밀번호」를 안 묻는 경우는 «둘»뿐입니다 — 둘 다 «물을 수가 없는» 경우입니다.**

| 언제 | 왜 |
|---|---|
| 메일 링크로 들어오신 분 | **잊어버려서** 오셨습니다. 물으면 영영 못 바꿉니다 |
| 카카오로만 시작하신 분 | 비밀번호를 **만든 적이 없습니다** |

🔴 그 판정을 **주소나 화면이 준 값으로 하지 않습니다** — 공격자가 그 값을 붙여 건너뜁니다.
**Supabase 가 서명한 「이 세션이 무엇으로 만들어졌나」**를 봅니다. **브라우저에서 못 고치는 값**입니다.

**함께 넣은 것:** 무차별 대입 막기(사람·IP 둘 다) · **다른 기기 로그아웃** · **「바꿨어요」 화면**

## 3. 🔴 제가 두 번 틀렸고, **둘 다 재 보고 잡았습니다**

**① 운영자 열쇠로 바꿨더니 — 사장님이 «자기 브라우저에서» 쫓겨났습니다.**
바꾸자마자 그 창이 `401`(로그인이 필요해요)이 됐습니다. 운영자 열쇠로 바꾸면 **세션이 전부 날아갑니다.**
⇒ **사장님 자신의 자격으로** 바꾸게 고쳤습니다. 지금은 **이 기기는 살고 다른 기기만 끊깁니다.**

**② 🔴 비밀번호를 «잊은» 분을 영영 못 바꾸게 만들 뻔했습니다.**
「메일 복구 세션은 `recovery` 로 표시된다」고 **문서를 읽고** 썼는데, **재 보니 `otp`** 였습니다.
지금 **메일이 안 나가는 환경이라 아무도 못 밟아 보는 길**이라, 그대로 냈으면
**회장님이 메일을 붙이시는 날 조용히 터졌을** 것입니다.
⇒ 메일을 **보내지 않고** 복구 링크만 받아 **실제로 그 세션으로** 확인했습니다. 지금은 잘 됩니다.

★ 배운 것: **「문서에 그렇게 적혀 있다」는 실측이 아닙니다.** 아무도 못 밟아 보는 길일수록 더 그렇습니다.

# 지시 [49]① — 이모지를 SVG 아이콘 아홉 개로

날짜: 2026-09-17 · 요청: 권반장(규격서 `15-인스타릴스-UI정밀해부.md` §3) · 상태: 처리함

| 🔊 🔇 | ① 소리 켜짐 · ② 꺼짐(사선) | 무대 우상 · 몰입 좌상 · 카드 우상 |

— **그 `font-size` 가 그대로 그림 크기가 됩니다.**
숫자를 SVG 에도 박으면 크기가 적힌 자리가 둘이 되고, CSS 만 고친 사람이 「왜 안 바뀌지」 하게 됩니다.

# 지시 [49]② — ⌃⌄ 와 점 표시기의 5px 겹침

## 1. 원인 (확정)

⇒ 단추를 `.world`(화면 전체)의 **직계 자식**으로 옮겼습니다.

- **바깥을 눌러 닫는 길도 안 막힙니다** — 단추를 누르면 `target` 이 단추라 닫기가 안 걸립니다

```

영상 프레임은 `aspect-ratio: 9/16` · `height: 100svh` 라 **창이 세로로 길수록 넓어집니다.**
너무 길면 프레임이 **화면 폭을 꽉 채워** 「바깥」이 사라지고 단추가 **영상 위로 다시 올라탑니다.**

## 0. 🔴 먼저 제 말을 바로잡습니다

**이 말은 불완전했습니다.** 만들기 전에 코드를 끝까지 읽었더니 **사본에는 «진짜 할 일»이 둘 있었습니다.**

## 1. 사본이 왜 있나 — 이유 둘 (코드에서 확인)

```

⇒ 폰에서 바로 공개 자리로 올리면 **「1년 보관」 딱지를 못 붙입니다.**
  복사(`CopyObject` + `MetadataDirective:"REPLACE"`)를 **거쳐야만** 그 딱지가 붙습니다.
  🔴 그 딱지가 없으면 **손님이 영상을 볼 때마다 새로 내려받습니다** — 느려지고, 통신량이 늡니다.

### ② 비공개 원본을 «발행 뒤에도» 세 곳이 읽고 있다

| 읽는 곳 | 무엇에 |
|---|---|

| (앞으로) 자막 워커 STEP 4 | 아직 안 만들었지만 원본이 필요하다 |

## 4. 🔴 재다가 잡은 것 둘

### ① 안내가 **화면 오른쪽 끝에 붙어** 있었다 (고쳤습니다)

처음에 `.world-help`(몰입모드 안내)의 모양을 그대로 베끼면서 `animation: world-in` 도 같이 가져왔습니다.
그런데 —

```
@keyframes world-in { from { transform: scale(1.04); } to { transform: none; } }
```

🔴 **`transform: none` 으로 «끝납니다».** `both` 라 끝값이 그대로 남아,
가운데 정렬용 `translateX(-50%)` 를 **영구히 지웁니다.**
⇒ 실측: **왼쪽여백 190 · 오른쪽여백 0** — 안내가 화면 끝에 붙었습니다.
⇒ **투명도만 바꾸는 애니메이션**(`shorts-help-in`)을 따로 만들어 고쳤습니다.
⇒ 고친 뒤: **왼쪽 81 · 오른쪽 81 ✅**

★ **교훈을 CSS 주석에 적었습니다** — 「자리를 `transform` 으로 잡는 요소에는
  `transform` 을 건드리는 애니메이션을 쓰지 않는다」.

### ② 안내가 **영영 안 뜰 수 있는** 조건이었다 (고쳤습니다)

처음엔 「레일이 **절반 이상 보이면**」(`intersectionRatio >= 0.5`)으로 썼습니다.
🔴 **레일이 화면보다 두 배 넘게 크면 그 비율에 «영영» 못 닿습니다** — 안내가 평생 안 뜹니다.
⇒ **「화면 한가운데에 닿았나」**로 바꿨습니다(`rootMargin: "-25% 0px -25% 0px"`).
  레일이 크든 작든 똑같이 동작합니다.

## 5. 왜 «윗줄»을 감추나

> 권반장: 「**두 개가 동시에 뜨지 않게 하십시오. 손님이 어느 것을 읽어야 할지 모릅니다**」

윗줄이 이미 **「옆으로 넘겨 보세요」**라고 말합니다 — 거의 같은 말입니다.
⇒ 안내가 떠 있는 동안만 윗줄을 **`visibility: hidden`** 으로 둡니다.
⚠ **`display: none` 이 아닙니다** — 줄이 사라지면 **아래가 위로 튑니다.** 자리는 두고 글자만 감춥니다.
실측: 안내 뜨기 «전» `visible` → «후» `hidden` ✅

⚠ **윗줄의 글자는 한 자도 안 바꿨습니다.** 이름표(`shorts-say`)만 달았습니다.

## 6. 시간은 `HINT_MS`(2800ms) 를 그대로 씁니다

대표님은 「3초」라 하셨고 권반장님은 재량을 주셨습니다.
**눈에 안 띄는 차이**라 **「값이 적힌 자리를 하나로」** 두는 쪽을 골랐습니다 — 무대·몰입모드와 같은 값입니다.

## 1. 「주소 없는 published 2건」의 정체 — 둘 다 채울 수 없는 것이었습니다

| 2 | **인스타** `18095011289101521` · **이미 «지워짐»으로 표시된 것** | ❌ **그 글이 존재하지 않습니다.** 물어볼 대상이 없습니다 |

  (`lib/sns/instagram.ts:306`). 최근 2건 모두 주소가 들어 있습니다.

## 2. 🔴 확인하다가 «[48] 이 옳았다»를 훨씬 센 증거로 확인했습니다
