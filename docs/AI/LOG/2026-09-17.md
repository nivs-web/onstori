## [16] 가로 카메라로 찍어 **세로 파일**이 나옵니다 — 파일로 증명했습니다

헤드리스 크롬에 **가로 영상을 «가짜 카메라»로 물려** 녹화하고 `ffprobe` 로 뜯었습니다.

```
카메라 원본   : 1080×720  (가로)
중계가 그린 것 : 720×1280, 500장/8초
나온 파일     : h264 720×1280 (세로) + aac 48000 (소리 있음)
```

🔴 **권반장이 가장 걱정하신 「무음 영상」도 안 납니다.** 시키신 다섯(스위치·프레임 측정·소리·
`setShotLand` 유지·`aspectRatio` 유지)을 **전부** 지켰습니다. 스위치는 `CANVAS_RELAY` 하나입니다.

### 🔴 권반장 판단 하나를 고쳐서 보고드립니다 — **카카오톡은 «절반»만 고쳐집니다**

| 카톡에서 생기는 일 | 고쳐지나 |
|---|---|
| 카메라가 **가로로 열린다** | ✅ 고칩니다 |
| 🔴 **아이폰 인앱은 「허용」 창이 아예 안 뜬다** — 카메라가 열리지도 않는다 | ❌ 못 고칩니다 |

⇒ **「사파리로 열어 주세요」 안내를 그대로 뒀습니다.** 빼면 아이폰 카톡 사장님이 막다른 길에 갇힙니다.
★ 다만 **안드로이드 카톡은 이제 그냥 됩니다** — 대표님 걱정의 대부분은 풀립니다.

## [18] 틱톡 — 이제 **우리가 직접 밀어 넣습니다**

도메인 인증이 **영영 필요 없어집니다.** 만들면서 **조용히 실패할 뻔한 것 둘**을 잡았습니다:

1. 🔴 **서명된 주소에 `HEAD` 를 쓰면 403** 입니다(서명은 `GET` 에만 유효).
   제가 처음 넣은 크기 상한 검사가 **늘 0 으로 읽혀 죽어 있었습니다.** `Range: bytes=0-0` 로 고쳤습니다.
2. 🔴 **파일 이름은 `.webm` 인데 내용은 mp4** 였습니다(실측). 이름으로 딱지를 붙였으면
   **틱톡이 거절했을 것**입니다. 파일 머리로 진짜 형식을 봅니다.
3. 덤 — 상태 확인이 잠깐 끊겼을 때 **같은 영상이 두 번 올라갈 수 있던 구멍**을 막았습니다.

## [17] **두 번째 누르기를 없앴습니다**

마지막 화면을 실제로 띄워 확인했습니다:

```
[ ⚡ 한 방에 올리기 ]      → /{상호}/edit?tab=video&oneshot={영상id}#video-list
[ 세부내용 수정해서 올리기 ] → /{상호}/edit?tab=video#video-list
```

한 번만 누르시면 넘어간 화면이 **저절로** 올립니다. 딱 한 번만 돌고, 주소의 표시는 곧바로
지웁니다(새로고침으로 또 올라가지 않게). `#video-list` 앵커로 **영상 칸까지** 데려갑니다.

## [23] 어드민 «회원 등급 올리기·내리기» — 대표님이 잡아내신 구멍

> 「정회원으로 올려줬는데 **무료회원으로 다시 바꾸는 게 없어.**
> 그리고 **정회원으로 올려주는 버튼도 만들어.**」

사이트 목록에서 **한 곳을 체크**하면 버튼 둘이 생깁니다.

| 누르면 | 무슨 일이 |
|---|---|
| **⬆ 정회원으로 올리기** | 이유 한 줄 적고 누르면 **결제하신 분과 똑같이** 쓰실 수 있게 됩니다 |
| **⬇ 무료회원으로 내리기** | **어디로** 내릴지 고릅니다 — **무료회원(체험)** 또는 **폐쇄** |

**검사: `npm run check` 0 · `npx tsc --noEmit` 0 · `npm run build` 0**

---

## 🔴🔴 눌러 보다 «버그»를 잡았습니다 — 안 해 봤으면 그냥 나갔습니다

[⬆ 정회원으로 올리기] 를 눌렀더니 **엉뚱한 확인창**이 떴습니다:

```
1곳을 «다시 열기» 합니다.
폐쇄해도 자료는 지워지지 않고, 손님에게만 안 보입니다.
```

**등급을 올리는데 「다시 열기」라고 묻습니다.** 예전 코드의 확인창 조건이 한 줄뿐이라
새로 만든 기능이 **자동으로 그 그물에 걸린** 것입니다.

**고친 뒤 실제로 뜨는 말:**

```
「zz-gate-test-a」 을 정회원으로 올립니다.
결제 없이 올리는 것이라 매출로는 잡지 않습니다.
```

⚠ **타입 검사도 빌드도 이건 하나도 못 잡습니다.** 문법은 완벽했습니다.

---

## 🔴 시키신 여섯 — 전부 «눌러서» 확인했습니다 (열여섯 건)

```
열쇠 없이            → 401            두 곳을 한 번에 → 400 「한 곳만」
이유 안 적음         → 400            엉뚱한 등급     → 400
없는 홈페이지        → 404            이미 그 등급    → 400
   여기까지 DB 가 바뀌었나 : 안 바뀜 ✅

🔴 진짜 올리기        → 200 suspended → active
   돈 받은 것으로 안 잡혔나 : 예 (paid_at 비어 있음) ✅
   왜 올렸는지 남았나      : {"by":"admin","reason":"…","prev":"suspended"} ✅

🔴 자동결제 걸린 채 내리기 → 409 「먼저 해지해야 합니다」 · DB 안 바뀜 ✅
   내리기                 → 200 active → trial · 올렸던 기록 «안 지워지고» 덧붙음 ✅

화면 : 이유 비면 버튼 잠김 ✅ · 확인창 문구 ✅ · 표에 「정회원(손으로)」 뜸 ✅
```

## 🔴 왜 «정회원으로 올려도» 매출이 안 흐려지나

| | 결제로 된 정회원 | 손으로 올린 정회원 |
|---|---|---|
| 손님·사장님 화면 | 똑같습니다 | 똑같습니다 |
| **돈 들어온 날(`paid_at`)** | **찍혀 있습니다** | 🔴 **비어 있습니다** |
| 어드민 표 | **유료회원**(초록) | **정회원(손으로)**(검정) |

⇒ 「이번 달 매출」을 셀 때 **돈 들어온 날이 있는 것만 세면** 섞이지 않습니다.
⇒ ★ **시키신 것보다 한 걸음 더 갔습니다** — 데이터에만 표시를 남기면 **표에서 둘이
   똑같아 보여 소용이 없습니다.** 그래서 회원 칸을 갈랐습니다.

🔴 **손님 사이트는 하나도 안 건드렸습니다.** 제가 전에 만든 시험용 사이트에서만 하고
**원래대로 돌려놨습니다.** 결제 표에 시험용 한 줄을 넣었다 지웠고(**돈은 1원도 안 움직였습니다**),
끝나고 **0건**을 다시 셌습니다.
