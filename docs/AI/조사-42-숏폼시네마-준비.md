## ① 두 모양으로 가르려면 어디를 가르나

### 🔴 좋은 소식 — **두 모양이 이미 «따로» 있습니다. 새로 만들 것이 없습니다**

| 모양 | 파일 | 그리는 자리 | 성질 |

| **카드형태**(가로·안 가둠) | `components/sections/shorts-feed.tsx` | `components/sections/index.tsx:517` | 평범한 섹션 «안». 옆으로 넘기는 카드 |

### 가르는 스위치도 이미 있습니다 — 지금은 «편수»가 정합니다

```
app/[slug]/page.tsx:132        const stageOn = stageItems.length > 0;      ← 영상이 있으면 무대
components/sections/index.tsx:480   if (ctx.stageOn && feed.length) return null;  ← 무대가 서면 카드는 비킨다
```

⇒ **이 두 줄의 판정을 「편수」에서 「사장님이 고른 모양」으로 바꾸면 끝입니다.**
`stageOn` 이라는 이름만 `style === "shorts"` 로 바뀝니다. **컴포넌트를 새로 만들 필요가 없습니다.**

### 🔴 진짜 공사는 이것 하나 — **몰입모드가 «무대 안»에만 있습니다**

`ShortsWorld` 가 `shorts-stage.tsx` **428~621행**에 들어 있습니다. **카드형태에는 몰입모드가 없습니다.**

**떼어낼 수 있습니다. 얽힘이 얕습니다:**

| 무대가 아는 것 | **`world` 열림 여부 한 개**(`shorts-stage.tsx:94`) | 부르는 쪽마다 하나씩 들면 된다 |

| ⚠ **CSS 이름을 빌려 씀** | 몰입모드 안에서 **`stage-pill`·`stage-dot`**(575~576) | 떼면 이름을 정리할지 정해야 한다 |

⇒ **`components/sections/shorts-world.tsx` 로 통째로 옮기고 두 모양이 같이 부릅니다.**
★ `StageVideo`(380~426 · **창 밖 영상의 재생기 반납**)도 카드형태에 값어치가 있습니다.
  다만 지금은 클래스명이 무대 전용이라 **같이 뺄지는 [42] 때 정하면** 됩니다.

### ⚠ 미리 알고 계셔야 할 것 — **카드형태는 «지금 아무 데서도 안 그려집니다»**

```

```
⇒ **카드형태는 사실상 잠들어 있습니다.** [42] 에서 되살릴 때 **한 번은 눈으로 봐야** 합니다 —

## ② 「모양」과 「재생 순서」를 어디에 저장하나

### 🔴 **db push 가 «필요 없습니다».**

`sites.settings` 가 **`jsonb not null default '{}'`** 입니다 (`supabase/migrations/20260831120000_core.sql:31`).
자유 형식이라 **칸을 새로 만들지 않고** 키만 하나 더하면 됩니다.

**이미 같은 방식으로 사는 이웃들:** `channels` · `ctaChannels` · `snsDefaults` · `weekly` · `shots` · `hashtags` · `logo` …

**손님 화면도 이미 읽습니다:** `lib/sites.ts:145` 가 `settings` 를 select 하고 `:202` 로 넘깁니다.
⇒ **읽는 길이 이미 깔려 있습니다.**

### 권하는 모양

```ts
settings.shorts = { style: "shorts" | "cards", order: "newest" }
```

### 🔴 「재생 순서가 더 늘어난다」를 감당하는 법 — **if 세 개를 박지 않습니다**

값은 **문자열 하나**로 두고, **목록을 `config/shorts.ts` 한 곳**에 둡니다:

```ts
export const SHORTS_ORDERS = [
  { key: "newest", label: "최신순" },
  { key: "random", label: "무작위" },
  …                                   ← 늘어날 때 «이 한 줄»만 더한다
] as const;
```

- 화면은 이 목록을 **돌려 그립니다** ⇒ 옵션이 늘어도 **화면 코드를 안 고칩니다**
- 서버는 `key` 로 정렬을 고릅니다
- 🔴 **모르는 `key` 가 오면 조용히 기본값으로 떨어뜨립니다** — 옛 사이트·손으로 고친 값이 화면을 깨면 안 됩니다

### ⚠ 새 키를 쓸 때 반드시 지킬 것

`settings` 를 쓰는 곳이 **열 곳 넘게** 있는데 전부 **통째로 읽어 통째로 다시 씁니다**(`update({ settings })`).
지금은 다들 스프레드(`{...settings, 새키}`)로 합치고 있어 안전하지만,
🔴 **새로 만드는 화면도 반드시 스프레드해야 합니다.** 안 그러면 **남의 칸(채널·주간알림)을 날립니다.**

### 개수 상한(10 / 20)

`config/shorts.ts` 에 **모양별 상수**로 두면 됩니다. 지금 그 자리에 `STAGE_MAX = 12` 가 있습니다.
⚠ `SHORTS_MAX(200)` 는 **DB 에서 몇 편을 가져오나**라 **별개**입니다 — 몰입모드는 그 200 편을 봅니다.
⇒ 대표님 말씀 「10·20편은 홈페이지만, 몰입모드는 전부」가 **지금 구조와 정확히 맞습니다.**
★ **그래서 대표님께 여쭙던 항목 하나가 «코드로 이미 답이 나와» 빠졌습니다**(권반장 확인).
  대표님 결정 대기가 **여섯 → 다섯**이 되었습니다.

## ③ 어드민 「영상」 메뉴에 넣을 자리

### 🔴 **그 화면이 «아직 없습니다».**

```
config/admin-menu.ts   { href: "/admin/videos", label: "영상 관리", … ready: false }   ← 자리만
app/admin/videos/      ← 폴더 자체가 없습니다
```

메뉴 한 칸을 더하는 것은 **`config/admin-menu.ts` 배열에 한 줄**이면 됩니다 —
그 배열이 **단일 출처**라 사이드바·폰 서랍·현재 위치 표시가 **전부 같이** 바뀝니다.

### ⚠ 그런데 «고르는 것»은 사이트마다입니다 — 제 제안 하나

어드민에 넣으면 **「어느 사이트의 모양인가」를 먼저 고르는 단계**가 필요합니다.
반면 **사장님 편집화면에는 이미 사이트별 영상 패널이 있습니다** (`app/[slug]/edit/videos-panel.tsx` · `ui.tsx:637`).

```
제안 : 사장님 편집화면 «영상 패널 맨 위»에 고르는 자리를 두고,
       어드민 /admin/videos 는 «전체 사이트의 모양을 한눈에 보고 대신 바꿔 주는 표»로 만든다
```
대표님 지시(어드민 메뉴 신설)를 지키면서 **사장님도 스스로 고를 수 있습니다.**
🔴 **이건 제 제안이지 확정이 아닙니다.** 「어드민에서만」이 뜻이시면 **사이트 고르는 단계만** 만들면 됩니다.

### 🔴 **이 항목은 «대표님께 올라갔습니다» — 답이 올 때까지 손대지 마십시오**

대표님 원문이 「**홈페이지 관리자 - 어드민 - 영상 - "숏폼 스타일 선택"**」인데,
**「홈페이지 관리자」가 «사장님»인지 «우리»인지 갈립니다.**
고르는 것이 **사이트마다**라 사장님 편집화면이 자연스럽지만, 글자만 보면 **우리 `/admin`** 으로도 읽힙니다.
**잘못 만들면 통째로 헛수고**라 권반장님이 대표님께 여쭙고 계십니다(제 제안도 권반장 추천으로 함께 올라갔습니다).
