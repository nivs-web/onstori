---

## 1. 실측 — **가로로 들어와서 세로로 나갑니다**

헤드리스 크롬에 **가로 영상(1280×720)을 «가짜 카메라»로 물려** 녹화를 끝까지 통과시키고,
나온 파일을 `ffprobe` 로 뜯어봤습니다.

**들어간 것 (카메라):**
```
카메라 원본 크기: {"w":1080,"h":720}   ← 가로!
```

**중계가 그린 것 (우리 캔버스):**
```
{"evt":"relay_fps","frames":500,"sec":8,"fps":63,"want":30,"size":"720x1280"}
```

**나온 파일 (`ffprobe` 실측):**
```
codec_type=video   codec_name=h264   width=720   height=1280   ← 🟢 세로
codec_type=audio   codec_name=aac    sample_rate=48000        ← 🟢 소리 들어 있음
```

⇒ **가로 카메라 → 세로 파일.** 지시하신 것이 그대로 됩니다.
⇒ 🔴 **권반장이 가장 걱정하신 「무음 영상」도 안 납니다** — 오디오 트랙이 붙어 있습니다.

### 그린 장수도 재고 있습니다

권반장 지시 2번(「느린 폰에서 프레임이 밀리는지 보십시오」)대로 **기계가 재게** 했습니다.
녹화가 끝날 때마다 위 `relay_fps` 한 줄이 로그에 남습니다.
⚠ **그 `fps` 가 20 아래로 자주 나오면 `config/recording.ts` 의 캔버스를 540×960 으로 낮추십시오.**
릴스·틱톡 최소 기준을 여전히 넘습니다. 숫자 두 개만 바꾸면 됩니다.

*(위 실측의 63fps 는 PC 헤드리스라 그렇습니다. 폰 숫자가 아닙니다 — 아래 §4 ①을 봐 주십시오.)*

---

## 2. 지시하신 다섯 가지 — 하나씩

| 시키신 것 | 했나 |
|---|---|
| **1. 되돌릴 수 있게 스위치** | ✅ `config/recording.ts` 의 `CANVAS_RELAY`. 끄면 **예전(카메라 직접 녹화)으로 정확히** 돌아갑니다. 환경변수로도 끕니다 — **배포 없이** |
| **2. 느린 폰에서 프레임 확인** | ✅ 매 녹화마다 실제 장수를 재서 로그에 남깁니다(위) |
| **3. 소리가 빠지지 않게** | ✅ `captureStream()` 뒤에 오디오 트랙을 옮겨 붙였습니다. **파일에서 aac 확인** |
| **4. 찍은 뒤 검사는 그대로** | ✅ `setShotLand`(`onLoadedMetadata`) 한 글자도 안 건드렸습니다 |
| **5. `aspectRatio` 부탁은 그대로** | ✅ `videoWant()` 무수정. 자를 양이 줄어 화질이 좋습니다 |

**그리고 지시하신 구조 그대로입니다:**
```
[카메라] → 안 보이는 <video> → 매 프레임 9:16 으로 «잘라» 그린다 → <canvas 720×1280 고정>
        → captureStream(30) + 원래 오디오 → MediaRecorder → 언제나 세로 mp4
```
⚠ **찌그러뜨리지 않고 «잘라냅니다».** 늘리면 사장님 얼굴이 길쭉해지고, 손님이 바로 알아봅니다.

## 3. 🔴 권반장 판단 하나를 **고쳐서** 보고드립니다 — 카카오톡

> 권반장: 「**[16] 이 카카오톡 문제를 «통째로» 없앱니다.** … 「크롬으로 여세요」 안내를
> **아예 뺄 수 있습니다.**」

**절반만 맞습니다. 안내를 빼면 안 됩니다.** 카카오톡 문제는 **두 가지**인데 서로 다릅니다.

| 카톡에서 생기는 일 | 캔버스 중계가 고치나 |
|---|---|
| **카메라가 «가로»로 열린다** (인앱이 회전을 안 해 줌) | ✅ **고칩니다.** 그게 이 일의 전부입니다 |
| 🔴 **아이폰 인앱은 «허용» 창이 아예 안 뜬다** — 카메라가 **열리지도 않는다** | ❌ **못 고칩니다.** 열리지 않은 카메라는 중계할 그림이 없습니다 |

⇒ **「사파리로 열어 주세요」 안내를 그대로 두었습니다.** 빼면 아이폰에서 카톡으로 링크를 받은
사장님이 **막다른 길에 갇힙니다.** (그 안내는 `rec-client.tsx` 의 error 화면에 있고,
[링크 복사]·[크롬으로 열기] 탈출구와 한 벌입니다.)

★ **다만 대표님 걱정은 거의 풀립니다** — 「사장님이랑 카톡으로 대화하다 링크도 보내고 싶은데」.
**안드로이드 카톡은 이제 그냥 됩니다**(가로 문제가 사라지니까). 남는 것은 아이폰 카톡뿐이고,
거기는 원래도 안 되던 것입니다.

## 4. 🔴 못 한 것 · 걱정거리

### ① **폰으로는 못 해 봤습니다** — 여기가 가장 큰 구멍입니다

권반장이 적어 주신 확인 다섯 중 제가 «기계로» 증명한 것은 **둘**입니다.

| 확인할 것 | 제가 한 것 |
|---|---|
| 눕혀서 찍기 → 세로 | ✅ **증명함** (가로 1080×720 → 세로 720×1280) |
| 소리가 들어갔나 | ✅ **증명함** (aac 48000) |
| 세워서 찍기 → 세로 | ⚠ 같은 코드 한 줄을 지나갑니다만 **따로 안 재 봤습니다** |
| 🔴 **찍는 도중에 돌리기** → 세로 | ⚠ **못 해 봤습니다** — 가짜 카메라는 도중에 크기가 안 바뀝니다 |
| 카카오톡 안에서 찍기 | ⚠ **못 해 봤습니다** |

**「도중에 돌리기」에 대해 제가 말할 수 있는 것:** 녹화기(`MediaRecorder`)가 보는 것은
**카메라가 아니라 우리 캔버스**이고, 그 캔버스는 `720×1280` 으로 **만들 때 정해 놓고 다시는
안 바꿉니다.** 카메라가 도중에 1280×720 으로 갈아타면 그 그림을 «잘라서» 같은 캔버스에 그릴 뿐입니다.
⇒ **구조상 바뀔 수 없습니다.** 하지만 그건 제 «설명»이지 **실측이 아닙니다.**

🔴 **대표님이 폰으로 한 번만 더 재현해 주셔야 끝납니다** — 그때 하셨던 그대로,
**찍는 도중에 폰을 흔들고 돌려** 주십시오. 그것이 이 일의 진짜 합격선입니다.

### ② 카메라 전환은 «찍기 전»에만 됩니다 — 확인했습니다

[카메라 전환] 버튼은 `setup` 화면에만 있습니다(`screen === "setup"`).
그래서 **찍는 도중에 앞/뒤를 바꿔 중계가 옛 그림을 계속 그리는 사고는 안 납니다.**
⚠ 나중에 그 버튼을 녹화 화면에도 넣으신다면 **중계를 다시 시작해야 합니다.** 지금은 안 됩니다.

### ③ 화면에 보이는 미리보기는 **카메라 그대로**입니다

찍는 동안 사장님이 보시는 화면은 예전처럼 카메라 그림입니다(중계 캔버스가 아닙니다).
⇒ **보시는 것과 저장되는 것이 다를 수 있습니다** — 눕혀 찍으시면 화면은 넓게 보이는데
파일은 가운데만 세로로 잘립니다. **지금은 그게 «고치는 목적»이라 맞습니다만**,
「내가 본 것과 다르다」는 문의가 나올 수 있습니다.
⇒ 미리보기도 캔버스로 바꾸면 완전히 같아집니다. **시키지 않으셔서 안 했습니다** — 30분쯤입니다.

### ④ 배터리·발열

매 프레임 그림을 한 장씩 옮겨 그립니다. 60초짜리면 1,800장입니다.
PC 에서는 아무 일도 아니지만 **오래된 폰에서는 발열이 있을 수 있습니다.**
⚠ 그 경우도 위 `relay_fps` 로그가 먼저 알려 줍니다.

### ⑤ 배포는 안 했습니다

`main` 커밋까지입니다.
