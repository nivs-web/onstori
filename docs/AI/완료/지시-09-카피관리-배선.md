## 1. 무엇을 했나 — 「배선」만

`readConfig()` 는 서버에서만 돕니다. 화면들은 전부 서버 컴포넌트라 그대로 부를 수 있었지만
`config/faq.ts` 는 **상수 배열**이라 못 불렀습니다. ⇒ 권반장 권고대로 **함수로 바꿨습니다.**

| 어디 | 전 | 후 |
|---|---|---|
| `config/faq.ts` | `export const FAQ` / `FAQ_FEATURED` (상수) | **`faqGroups(snsLine)` / `faqFeatured(snsLine)`** (함수) |
| `app/faq/page.tsx:10` | `FAQ` 직접 | `await readConfig()` → `faqGroups(cfg.snsLine)` |
| `app/page.tsx:41` | `FAQ_FEATURED` 직접 | 이미 `async` — `Promise.all` 에 `readConfig()` 를 **함께** 태웠습니다(왕복이 안 늘어납니다) |
| `app/how-it-works/page.tsx:19` | `CHANNELS_LINE_MARKED` 직접 | `async` 로 바꾸고 `cfg.snsLine` |
| `app/our-story/page.tsx:23` | `COMPARE_ROWS` (상수) | **`compareRows(snsLine)`** + `async` |
| `app/admin/seo/page.tsx:162` | `CHANNELS_LINE_MARKED` 직접 | `cfg.snsLine` — 미리보기가 **지금 진짜 나가는 값**을 보여 줍니다 |

### ⚠ `snsLine` 에 **기본값을 두지 않았습니다** — 일부러입니다

`faqGroups(snsLine = CHANNELS_LINE_MARKED)` 처럼 두면 편하지만, **배선을 빠뜨린 새 화면이
조용히 옛 값을 보여 줍니다.** 이번에 고친 병이 정확히 그것입니다. 인자를 필수로 두면
다음에 화면이 생겼을 때 **`tsc` 가 대신 잡아 줍니다.**

## 2. 🔴 권반장 목록에 없던 **다섯 번째 곳**을 찾았습니다 — 함께 배선했습니다

지시는 「실측 4곳」이었는데, 흉내 저장을 넣고 화면을 훑으니 **첫 페이지에 한 곳이 더** 있었습니다.

> `app/page.tsx:211` — 「**6곳 동시 발행 — 지금 2곳**」 카드의 설명 줄
> `config/channels.ts` 의 **`CHANNELS_PITCH`** (= `CHANNELS_LINE_MARKED` + `PENDING_NOTE`) 를 씁니다.

**왜 그냥 두지 않았나:** 이대로 두면 대표님이 저장하셨을 때 **같은 첫 페이지 안에서**
자주묻는질문 칸은 새 문구, 바로 위 카드는 옛 문구가 됩니다 — **「고쳤는데 왜 안 바뀌죠?」가
절반만 고쳐진 채로 남습니다.** 그래서 `channelsPitch(snsLine)` 을 더해 함께 배선했습니다.

⚠ **뒤쪽 `PENDING_NOTE`(「지금 나가는 곳은 2곳이고…」)는 갈아 끼우지 않았습니다.**
   그것은 문구가 아니라 `live` 값에서 저절로 나오는 **사실**입니다. 손으로 적게 하면
   2026-09-06 의 「182곳 중 175곳이 어긋난」 사고를 문구에서 되풀이하게 됩니다.

🔴 **권반장 판단이 필요하면 되돌리기 쉽습니다** — `config/channels.ts` 의 `CHANNELS_PITCH`
   상수를 그대로 남겨 두었습니다. `app/page.tsx:211` 한 줄만 되돌리면 됩니다.

## 3. 🔴 저장해도 **한 시간 동안 안 바뀔** 뻔했습니다 — 같이 고쳤습니다

빌드 출력 실측입니다:

```
┌ ○ /                 Revalidate 1m
├ ○ /faq              Revalidate 1h
├ ○ /how-it-works     Revalidate 1h
├ ○ /our-story        Revalidate 1h
```

넷 다 **정적(ISR)** 입니다. 그런데 저장 라우트(`app/api/admin/config/route.ts:32`)는
**`revalidatePath("/")` 하나만** 풀고 있었습니다. 배선만 하고 여기를 안 고쳤으면
대표님이 저장하시고 **`/faq` 는 최대 한 시간** 옛 글자가 나갔을 것입니다 — **이 지시의 병 그대로입니다.**

⇒ 네 경로를 전부 풀도록 고쳤습니다. `/admin/seo` 는 `force-dynamic` 이라 원래 즉시입니다.

⚠ **앞으로 `readConfig()` 를 읽는 화면을 새로 만들면 그 목록에도 반드시 더해야 합니다.**
   그 경고를 코드 주석으로 박아 두었습니다.

## 6. 그 밖에 걱정거리

1. **채널 «칩»(둥근 조각) 은 저장값을 안 따릅니다.** 푸터와 첫 페이지의
   「유튜브 쇼츠(준비 중) / 인스타 릴스 / …」 **낱개 조각**은 `CHANNELS` 배열에서 직접 나옵니다.
   그건 「한 줄」이 아니라 목록이라 `/admin/copy` 가 다루는 대상이 아니라고 봤습니다. **일부러 뒀습니다.**
2. **`config/faq.ts` 의 「정회원에 무엇이 포함되나요?」는 `CHANNELS_LINE`(«준비 중» 표시 없는 것)을 씁니다.**
   `snsLine` 과 **다른 상수**입니다. 섞지 않았습니다. 지시도 18 줄만 지목하셨습니다.
3. **`/admin/copy` 에 「지금 이 문구를 읽는 화면은 여기입니다」 안내가 없습니다.** 대표님이
   저장하시고 어디를 봐야 확인되는지 모르십니다. **시키지 않으셔서 안 만들었습니다.**
4. **`readConfig()` 가 화면마다 한 번씩 돕니다.** ISR 이라 손님 요청마다는 아니고 갱신 때만입니다.
   `/` 는 `Promise.all` 에 함께 태워 왕복을 안 늘렸습니다. 나머지 셋은 원래 DB 를 안 읽던 화면이라
   **갱신 때 한 번의 왕복이 새로 생깁니다.** 1시간에 한 번이라 문제될 크기는 아니라고 봅니다.
