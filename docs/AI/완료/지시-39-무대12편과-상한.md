| | |
|---|---|
| 상태 | **처리함** · 2026-09-17 · 클코 |
| 🔴 결과 | **21편 제한이 «풀렸습니다».** 이제 **200편**까지 홈페이지에 실립니다 |
| 방법 | 「가두는」 무대는 **앞 12편**(높이 **13화면 고정**) · 나머지는 **「숏폼피드 세상」**에서 이어 봄 |
| 검사 | `npm run check` **0** · `npx tsc --noEmit` **0** · `npm run build` **0** |

## 1. 무엇을 풀었나

> 조사: 「`.stage` 높이가 `(N+1)×100svh` 라 **1000편이면 81만px** — 스크롤바가 못 쓰게 됩니다」

무대 높이가 **편수에 따라 늘어나는 것**이 상한을 못 푸는 진짜 이유였습니다.
⇒ **가두는 것은 앞 12편까지**로 못 박고, 나머지는 **전체화면**에서 이어 보게 했습니다.
전체화면은 **한 편씩만** 그리므로 **편수가 늘어도 높이가 안 늘어납니다.**

**실측 — 무대 상한을 잠깐 3으로 낮춰 7편짜리 사이트로 재현했습니다:**

```
① 무대 높이가 «편수와 무관하게» 고정되나
   { 무대에 선 편수: "3", 화면수: 4, 눈금: 3, 점: 3 }      ← 7편인데 무대는 3편·4화면

② 무대 위 표시 : 1 / 3 · 전체 7
   「전부 보기」 단추 : 전부 보기 (7편) →
   「건너뛰기」와 겹치나 : false

③ 🔴 「전부 보기」를 누르면 «전부» 볼 수 있나
   열린 곳 : 1 / 7 · 소리 🔊
   ↓ 를 여섯 번 : 7 / 7        ← **무대에 없던 편까지** 갑니다

④ 무대 안에서는 상한까지만 : 1/3 → 2/3 → 3/3
```

⇒ **무대 상한을 12로 되돌린 뒤** 7편짜리 사이트에서는
`{편수 7, 화면수 8}` · **「전부 보기」 없음** — **상한에 안 닿으니 안 뜨는 것이 정상**입니다.

## 2. 🔴 상한을 «순서대로» 풀었습니다

권반장님이 못 박으신 순서 그대로:

```
① ④(무대 12편 + 세상) 완성        ✅
② 그다음 SHORTS_MAX 를 올린다      ✅  20 → 200
③ 올린 뒤 [38]① 안내가 «안 뜨는지» 확인   ✅  7편 < 200 이라 안 뜸(실측)
```

### 🔴 왜 200 인가 — 근거

| | |
|---|---|
| **주 1회** 찍으시면 | **약 4년치**입니다 |
| 지금 가장 많은 사장님 | **17편** |
| 🔴 「무제한」으로 안 한 이유 | **편집화면·DB 조회·첫 화면에 실어 보내는 목록**이 함께 늘어납니다 |

**실측한 비용:**

```
지금(7편) 페이지 : 179,680 자
영상·표지 주소가 차지하는 글자 : 2,088 (건수 24) → 한 편당 약 298 자
→ 200편이면 약 58KB 가 더 실립니다 (압축 전 · gzip 이면 대략 그 1/5~1/8)
```

⇒ **200편이어도 첫 화면에 더 실리는 것은 «주소 글자» 수십 KB 뿐**입니다.
**영상 바이트는 여전히 «두 편치»**입니다(가상화 · [38]).

## 3. 화면에 더한 것 둘

| | |
|---|---|
| **「전부 보기 (N편) →」** | 무대 왼쪽 아래. **「건너뛰기 ↓」와 나란히** — 나가는 길과 더 보는 길이 함께 있어야 고를 수 있습니다 |
| **「3 / 12 · 전체 40」** | 무대 위 표시에 **전체 편수**를 덧붙였습니다. 뒷부분은 흐리게 — **지금 위치가 먼저 읽혀야** 합니다 |

🔴 **무대에서 잘린 편은 «못 보는 게» 아닙니다.** 한 번 누르면 **처음부터 끝까지** 이어 봅니다.

## 4. 🔴 못 한 것 · 걱정거리

### ① **200편을 실제로 걸어 보지 못했습니다**

가장 많은 사이트가 **17편**입니다. **무대 상한을 3으로 낮춰** 「넘치는 상황」을 재현한 것이지,
**진짜 200편으로 돌려 본 것이 아닙니다.**
⚠ 특히 **전체화면에서 200편을 ↓ 로 끝까지 넘길 때** 어떤지는 모릅니다 —
한 편씩만 그리므로 구조상 괜찮아야 합니다만 **그건 설명이지 실측이 아닙니다.**

### ② **「무한 스크롤」이 아니라 «한 번에 다 싣기»입니다**

조사서는 「무한 스크롤」이라 했는데, 저는 **200편을 한 번에 실어** 보내고 전체화면이 그 안에서
움직이게 했습니다. **200편이 58KB 뿐**이라 나눠 싣는 장치가 값어치보다 복잡했습니다.
⚠ **상한을 200보다 크게 올리는 날에는 나눠 실어야 합니다.**

### ③ **전체화면에서 ↓ 를 «200번» 눌러야 끝까지 갑니다**

「바로 뒤로 돌아가기」나 「목록으로 보기」가 없습니다. 조사에 없던 항목이라 안 만들었습니다.

### ④ **폰에서는 「전부 보기」가 안 뜹니다**

전체화면이 **마우스가 있는 기기에서만** 열리기 때문입니다(대표님 「폰은 이대로 좋아」).
🔴 **그래서 폰 사장님의 13편째부터는 «여전히 손님이 못 봅니다».**
⚠ 이건 **[39] 의 가장 큰 구멍**입니다 — **폰에서도 전체화면을 열지 정해 주셔야** 합니다.

### ⑤ **편집화면의 옛 오류는 그대로**입니다

「Encountered two children with the same key」 — 권반장님이 [40] 으로 잡아 두셨습니다.
