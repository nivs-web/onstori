# 지시 [42] **2단계** — 몰입모드 화면 새로 짜기 + 미리 당겨 오기

**날짜:** 2026-09-17 (밤) · **2단계만 했습니다. 3~5단계는 손대지 않았습니다.**
**한 줄:** 대표님 설계대로 다시 짰고, **PC 에서 대칭이 깨져 있던 것을 재서 잡았습니다.**

## 1. 화면 — 대표님 설계대로

| 자리 | 무엇 | 한 일 |
|---|---|---|
| 좌상 | 🔊 (원형) | 그대로 |
| 우상 | **✕ (원형)** | 🔴 **「나가기」 글자를 뗐다.** 🔊 와 **같은 CSS 규칙**을 쓴다 — 한쪽만 고쳐 대칭이 깨질 수가 없다 |
| 상단 정중앙 | **1 / N** | 그대로 |
| 우측 정중앙 | **점3 + 긴 막대1 + 점3** | 🆕 **⌃⌄ 를 지운 그 자리** |
| 좌하 (위) | **영상 제목** | 자리만 옮김 · **두 줄에서 자름** |
| 좌하 | **[인스타에서 보기] / [쇼츠에서 보기]** | **세로로 쌓음**(오른쪽이 §6 ♡·💬 자리) |
| 우하 | **✕ + 「몰입모드 나가기」** | 🆕 우상이 글자를 뗀 몫을 받는다 |
| 없앤 것 | ⌃⌄ | 🔴 **JSX·CSS 전부 지웠다**(남은 것 0개) |

### 🔴 막대는 **일곱 칸 «고정»**입니다 — 2000편에서도 안 깨지게

무대의 점(`.stage-dots`)은 **편수만큼** 그립니다. 그 방식이면 2000편에서 점이 2000개가 됩니다.
⇒ 여기서는 **지금 편을 가운데 두고 앞뒤 세 칸씩만** 그립니다.
막대는 **언제나 한가운데**, 끝에 가까우면 **바깥 점이 비어 갑니다.**

```
1편째 : gone|gone|gone|on|·|·|·        4편째 : ·|·|·|on|·|·|·
```

## 2. 🔴🔴 재서 잡은 것 — **PC 에서 대칭이 깨져 있었습니다**

권반장님이 **「숫자로 맞추지 말고 나란히 놓고 보십시오」**라고 하신 항목입니다. 재 봤더니:

```
PC 1280×800 · 영상 프레임 폭 450 (9:16 이라 좌우가 검은 띠)
  🔊  영상 왼쪽에 붙음   → 화면 기준 431
  ✕   화면 오른쪽 구석   → 화면 기준 1264
  ⇒ 둘이 «415px» 떨어져 있었다. 대칭이 아니라 남남이었다
```

**폰에서는 프레임이 화면과 같은 폭이라 «멀쩡해 보였습니다».** PC 에서만 깨져 있었습니다.

⇒ **✕ · 1/N · 막대 · 우하 나가기 · 안내문구를 전부 «영상 프레임 안»으로** 옮겼습니다.

**고친 뒤 실측:**

| | 폰 375×812 | PC 1280×800 |
|---|---|---|
| 프레임 | 375 (=화면) | **450** (가운데) |
| 🔊 · ✕ | **양쪽 16px · 같은 높이 · 같은 크기** ✅ | **양쪽 16px · 같은 높이** ✅ |
| 1 / N | 영상 한가운데 ✅ | 영상 한가운데 ✅ |
| 막대 | 세로 한가운데 ✅ | 영상 오른쪽 24px ✅ |

⚠ 바깥(검은 띠)을 눌러 닫는 길은 그대로입니다 — 그건 `.world` 가 받습니다.

## 3. 🔴 또 하나 — **제목이 「몰입모드 나가기」 밑으로 깔렸습니다**

```
폰 375px : 제목 오른끝 359 · 나가기 단추 왼끝 255  ⇒ 104px 이 겹쳤다
```
⇒ **제목에만** 오른쪽 여백을 줬습니다(알약은 짧아 안 겹칩니다 — 묶음 전체에 주면 알약까지 좁아집니다).
**고친 뒤:** 제목 오른끝 **235** · 단추 왼끝 **255** → **20px 띄움** ✅

## 4. ⚠ 「1 / N」의 N — **지시서와 다르게 했습니다**

지시서에 **「전체 편수는 «가져온 수»가 아니라 «있는 수»여야 합니다」**라고 돼 있었습니다. **안 그렇게 했습니다.**

DB 에 300편이 있어도 한 번에 싣는 것은 **`SHORTS_MAX`(200)까지**입니다.
「1 / 300」이라고 쓰면 **손님이 끝까지 내려도 200에서 멈춥니다** — 화면이 거짓말을 합니다(불변 규칙 12).
⇒ **N 은 「손님이 실제로 닿을 수 있는 수」**로 뒀습니다. 🔴 진짜 300을 보여 주려면 **300편을 실을 수 있게 만드는 것이 먼저**입니다.

## 5. 미리 당겨 오기 (권반장 조건)

몰입모드를 **필요할 때만** 내려받게 하되, **무대가 화면에 닿는 순간 조용히 미리** 당겨 옵니다
(PC 는 마우스를 올릴 때 한 번 더). 그래서 **클릭할 때쯤엔 이미 와 있습니다.**

**잰 값(개발 서버 · 클릭 → 열림):**

```
정적으로 늘 싣기      : 첫 251~284ms · 두 번째부터 12~14ms
미리 당겨 오기        : 첫 315~334ms · 두 번째부터 10~14ms
```

**운영에서 다시 잰 값:**

```
첫 열림 311~331ms · 두 번째부터 6~9ms
```

★ **첫 열림이 느린 것은 «내려받기» 때문이 아닙니다** — **정적으로 늘 실어도 첫 번째는 251~284ms** 입니다.
  둘째부터 6~9ms 인 것이 그 증거입니다. 그 시간은 **영상·화면을 처음 만드는 값**입니다.

### 🔴🔴 그런데 «미리 당겨 오기»를 **재 볼 수가 없었습니다** — 그래서 만드는 방식을 바꿨습니다

운영에서 재 보니 몰입모드 뭉치가 **무대에 닿을 때가 아니라 «클릭할 때»** 받아졌습니다.
「미리 당김이 안 도는구나」 싶어 표시를 넣어 확인해 보니 —

```
무대로 굴린 뒤 :  미리당김 안 돎  ·  stage-dark 도 안 붙음
```

🔴 **`stage-dark`(무대가 덮이면 상단 바를 까맣게)까지 같이 죽어 있었습니다.** 그건 원래 잘 돌던 것입니다.
⇒ **원인은 제 코드가 아니라 «창이 숨어 있는 것»**이었습니다. 숨은 창에서는 브라우저가
`IntersectionObserver` 를 **아예 안 돌립니다**(등장 애니메이션이 멈춰 있던 것과 같은 이유).

**⇒ 그래서 «재 볼 수 없는 길 하나»에 기대지 않기로 했습니다.**
**한가해지면 무조건 한 번** 미리 받아 둡니다(`requestIdleCallback`, 없으면 타이머).
첫 화면을 그리는 동안엔 끼어들지 않고, 손님이 누르기 훨씬 전에 조용히 받습니다.
★ 무대가 보일 때·마우스를 올릴 때도 그대로 부릅니다 — **먼저 오는 쪽이 이깁니다.**

⚠ **그래도 「진짜 손님 브라우저에서 미리 받아지는가」는 제가 못 봤습니다.**
🔴 **사람이 한 번 봐 주셔야 합니다** — PC 에서 `sample-interior` 를 열고 F12 → Network 에서
**영상을 누르기 «전»에** 몰입모드 뭉치가 와 있는지.

## 6. ⚠ 못 한 것 · 안 한 것

| 무엇 | 왜 |
|---|---|
| **♡ 좋아요 · 💬 댓글 숫자** | **자리만** 잡았습니다. 숫자를 가져오는 일은 **§6** 이고 따로 합니다(권반장 지시). **0 이면 아예 안 그립니다** |
| **3~5단계** | 🔴 **일부러 안 했습니다** |
| **눈으로 못 봤습니다** | 창이 숨어 있어 **화면 그림을 못 찍었습니다.** 대신 **자리·크기를 숫자로** 쟀습니다. 🔴 **대표님이 한 번 눈으로 봐 주셔야 합니다** |
| ⚠ **「쇼츠에서 보기」** | 대표님 설계서엔 「유튜브에서 보기」인데 화면 글자는 **「쇼츠에서 보기」**입니다([31]④ 때 정해진 값). **손님 글이라 제가 안 바꿨습니다** |
| **진짜 폰 아님** | 쓸어넘기기는 코드로 만든 손가락입니다 |

⚠ **숨은 창에서는 등장 애니메이션이 멈춰 있어** 처음 잰 값이 4% 커져 있었습니다(`scale(1.04)` 에서 정지).
  **애니메이션을 끝난 상태로 보낸 뒤 다시 쟀습니다** — 위 숫자는 전부 그렇게 잰 것입니다.
