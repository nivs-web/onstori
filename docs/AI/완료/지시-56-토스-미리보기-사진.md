# [토스 마무리] `/my` 「하남 종합인테리어」 미리보기 사진 — 처리함 · 2026-09-18

지시: 대표님 · 2026-09-18 (심사 자체를 막지는 않으나 심사관 눈에 회색 상자가 보임)

## ① 무엇이 문제였나 — 대표님 진단이 그대로 맞았습니다

```
sites(sample-toss).settings 에 `shots` 가 «없음»  →  /my 가 「미리보기 준비 중」 회색 상자를 그린다
```
백업 때 확인한 `settings` 칸 아홉: `address · channels · hours · notify · oneLiner · pending_order · phone · snsDefaults · weekly` — **`shots` 만 없었습니다.**

## ② 스크립트를 고쳤습니다 — `--slug` 를 주면 **showcase 를 거치지 않습니다**

```
전 : 대상 목록을 «언제나» showcase 에서 가져오고 --slug 는 그것을 «거르기»만 했다
     ⇒ showcase 에 없는 sample-toss 는 --slug 를 줘도 「찍을 사이트가 없다」로 조용히 끝난다
후 : --slug 를 주면 그 이름만 찍는다. 목록에 있든 없든 상관없다
     ⚠ 그 홈페이지가 «실제로 있는지»는 먼저 묻는다(오타로 크롬을 띄우는 낭비를 막는다)
```

🔴 **showcase 에 넣는 방법은 쓰지 않았습니다** — 대표님 말씀대로입니다.
  showcase 는 **첫 페이지 「온스토리로 만든 홈페이지」 목록**이라, 넣는 순간
  「하남 종합인테리어 (토스 심사용 예시)」가 **손님 첫 화면에 걸립니다.**

## ③ 찍었습니다 — 운영 주소 기준

```
npx tsx --env-file=.env.local scripts/site-shots.ts --slug sample-toss --origin https://onstori.com

  «이름을 집어» 찍는다 — showcase 는 보지 않는다
  pc    원본 2880x6912 → 내보냄 1080x2592 · 69KB
  phone 원본  780x1872 → 내보냄  640x1536 · 26KB
  ✅ sample-toss (15초) · 완료 1곳 · 실패 0곳
```

⚠ 찍힌 것이 **진짜 그 사이트**인지 확인했습니다 — 촬영 로그가 제목을 읽었습니다:
  「20년 된 아파트, 다시 살고 싶은 …」 (로그인 화면·오류 화면이 아닙니다)

## ④ DB 를 바꾸기 «전에» 백업했고, 바꾼 «뒤에» 대조했습니다

| 무엇 | 결과 |
|---|---|
| 백업 | `backups/sample-toss-settings-2026-09-18T10-37-00.json` (읽어서 검증까지 함) |
| 사라진 칸 | ✅ **없음** — 아홉 칸 그대로이고 `shots` 만 늘었습니다 |
| 사진이 실제로 열리나 | ✅ PC `200 image/webp 69KB` · 폰 `200 image/webp 26KB` |
| 배지 | ✅ **「무료 D-29」** (9999 아님 — `/my` 가 쓰는 규칙 그대로 계산해 확인) |

## ⑤ 무엇을 «못» 했나

🔴 **`/my` 화면을 제 눈으로 못 봤습니다.** 심사 계정 열쇠가 **로컬에 없습니다**(운영에만 있습니다).
  ⇒ **대표님이 `/my` 를 한 번 새로고침**해 주시면 됩니다.
  ⚠ `/my` 는 `force-dynamic` 이라 **캐시가 없습니다** — 새로고침 한 번이면 바로 바뀝니다.
  ⚠ 배포를 기다리실 필요 **없습니다.** 이번 것은 **DB 와 사진 파일**만 바뀐 일입니다
    (스크립트 수정은 다음 배포에 함께 올라가면 됩니다).
