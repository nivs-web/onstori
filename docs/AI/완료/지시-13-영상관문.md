## 1. 만든 것

가입 마법사의 **맨 마지막(9단계)** 에 「영상」 관문이 생겼습니다.
`STEP 9 / 9 · 영상` — 진행 바도 9칸으로 늘었습니다.

```
마지막입니다. 60초만 찍어 주세요.

온스토리는 홈페이지를 만드는 곳이 아닙니다.
사장님의 60초를 «여러 곳에 한 번에» 퍼뜨리는 곳입니다.
그래서 영상 한 편이 있어야 홈페이지가 완성됩니다.
…
[ 지금 찍기 ]   왜 꼭 찍어야 하나요? ▾   저장하고 중단
```

| 지시하신 규칙 | 했나 |
|---|---|
| **건너뛰기 버튼을 두지 않는다** | ✅ 없습니다(실측으로 확인) |
| **[저장하고 중단]은 둔다** | ✅ 있습니다 |
| 다시 들어오면 **그 단계부터** 이어진다 | ✅ `localStorage` 에 남기고, `/new` 를 다시 열면 관문으로 바로 갑니다 |
| 녹화 실패 때 **막다른 길이 되면 안 된다** | ✅ 이유를 적고 [다시 시도]를 줍니다. 원래 녹화 화면의 탈출구(사파리로 열기·갤러리에서 고르기)도 그대로입니다 |
| 완성도 규칙을 **안 고친다** | ✅ `config/completeness.ts` 무수정 |
| 「왜 꼭 찍어야 하나요?」 펼침 | ✅ 만들었습니다 |
| 🔴 **「6곳」이라고 쓰지 않는다** | ✅ **인스타 릴스·틱톡 둘만** 적었습니다(실측으로 확인) |

### 「왜 꼭 찍어야 하나요?」에 실제로 나가는 글

> 찍으신 영상은 **사장님 홈페이지 첫 화면 바로 아래**에 걸립니다.
> 그리고 **인스타 릴스·틱톡**에 올릴 수 있게 준비됩니다 — 올릴지 말지는
> **사장님이 «홈페이지 관리»에서 직접 고르십니다. 저희가 마음대로 올리지 않습니다.**
> 유튜브 쇼츠·쓰레드·X·페이스북은 아직 준비 중입니다.
> 영상이 없으면 **매주 오는 질문도, 쌓이는 이야기도 시작되지 않습니다** —
> 그게 온스토리의 전부라서, 안 찍으시면 받으실 것이 홈페이지 한 장뿐입니다.

🔴 **손님이 보는 글입니다.** 위 문장과 관문 본문은 **권반장 초안을 거의 그대로** 썼습니다.
대표님이 고치실 자리입니다.

## 2. 🔴 지시서에 없던 것 — **고치지 않으면 관문이 «헛돌» 뻔했습니다**

### ① 영상을 찍어도 **점수가 안 올랐습니다**

완성도 「첫 영상」(10점)의 판정은 `story_entries.video_key` 가 있나인데,
**그 판정을 부르는 곳이 녹화 제출 길에 없었습니다.** `recomputeScore` 를 부르는 곳은
저장·발행·글스토리·로고 넷뿐이고 `app/api/story/submit` 에는 **없었습니다.**

⇒ 사장님이 영상을 찍어도 점수가 그대로였고, 나중에 «다른 일»을 했을 때에야 10점이 뒤늦게 붙었습니다.
   **「시키는 대로 했는데 안 오른다」** — 규칙 12 가 경계하는 바로 그 모양입니다.

**고쳤습니다:** `app/api/story/submit` 이 끝에서 점수를 다시 셉니다.
⚠ 점수 «규칙»은 한 글자도 안 고쳤습니다. **이미 있던 규칙이 실제로 켜지게** 한 것뿐입니다.
⚠ 점수 계산이 실패해도 녹화는 성공으로 둡니다 — 60초를 인질로 잡지 않습니다.

**이건 관문과 무관하게 «원래» 있던 결함입니다.** 오늘부터는 편집화면에서 찍으셔도 바로 오릅니다.

### ② 「홈페이지에만 걸고」 — 대표님 추가 지시를 따로 만들었습니다

대표님(채팅): 「관문에서 찍은 «첫 영상»은 **홈페이지에만 걸고** SNS 발행은 **기본 꺼짐**으로.
빈 컵·하늘이 사장님 인스타에 진짜로 올라가면 사고입니다.」

**SNS 는 원래 안 나갑니다 — 확인했습니다.** 저장소에서 SNS 로 보내는 길은 `app/api/sns/publish`
하나뿐이고, 그것을 부르는 곳은 **편집화면의 [올리기] 버튼 하나**입니다
(`app/[slug]/edit/videos-panel.tsx`). 자동으로 올리는 크론도 워커도 **없습니다.**
그 사실을 `config/onboarding.ts` 주석에 근거와 함께 못 박아 두었습니다 —
**나중에 자동 발행을 만드는 사람이 그 문단을 먼저 읽어야 합니다.**

**「홈페이지에 걸기」는 새로 만들었습니다.** 관문이 끝나면 방금 찍은 영상이
**첫 화면 바로 아래**에 자동으로 걸리고 발행까지 됩니다(`/api/site/video` 에 `publishNow`).
실측에서 `draft`·`published` 양쪽 섹션이 `["hero","video","about",…]` 로 확인됐습니다.

⚠ **거기서 `story_entries.visible` 을 건드리지 않았습니다.** 건드리면 완성도 `story_1`(10점)이
저절로 붙어 지시 [15] 의 숫자가 깨집니다. 원래 코드가 같은 이유로 그렇게 해 두었습니다.

## 3. 가입을 **네 번 끝까지 통과**시킨 실측

`npm run dev` + 진짜 크롬으로 가입을 처음부터 끝까지 통과시키고, DB 를 직접 읽었습니다.
영상은 ffmpeg 로 만든 3초짜리 mp4 를 「갤러리에서 고르기」로 올렸습니다.

| # | 슬러그 | 「시작한 이유」 | 영상 | 스위치 | 결과 |
|---|---|---|---|---|---|
| A | `zz-gate-test-a` | 안 씀 | 안 찍음 | ON | 관문 뜸 · **50점** |
| B | `zz-gate-test-b` | 안 씀 | **찍음** | ON | **60점** · 영상 걸림·발행됨 |
| C | `zz-gate-test-c` | **씀** | **찍음** | ON | **70점** · 영상 걸림·발행됨 |
| D | `zz-gate-test-off` | 안 씀 | — | **OFF** | **관문 없음** · `STEP 8 / 8` · 바로 「완성됐어요」 |

### 스위치를 끄면 «예전 그대로» 입니다 — 확인했습니다

```
① STEP 1 / 8 · 상호명  …  ⑧ STEP 8 / 8 · 만들기
🟡 관문 없이 바로 완료 화면 — 스위치 OFF 동작
```

진행 바도 **8칸으로 돌아갑니다.** (9칸을 남겨 두면 「한 단계가 사라졌다」로 보입니다.)

### 켜면 이렇습니다

```
① STEP 1 / 9 · 상호명  …  ⑧ STEP 8 / 9 · 만들기  →  ⑨ STEP 9 / 9 · 영상
🟢 관문이 떴다 — 「마지막입니다. 60초만 찍어 주세요.」
   건너뛰기 단추 있나: 없다 ✅
   저장하고 중단 있나: 있다 ✅
   왜-펼침에 「6곳」이 있나: 없다 ✅
```

영상을 보낸 뒤 서버 응답:

```
submit  : {"ok":true,"id":"…","score":70}          ← 점수가 그 자리에서 오른다
걸기    : {"section":{"type":"video",…},"published":true}
draft 섹션      : ["hero","video","about","gallery","processSteps","storyFeed","quoteForm","map"]
published 섹션  : ["hero","video","about","gallery","processSteps","storyFeed","quoteForm","map"]
```

## 4. 🔴 못 한 것 · 걱정거리

### ① **localhost 에서는 영상 올리기가 브라우저로는 안 됩니다** (우리 설정 문제)

브라우저가 R2 로 직접 올릴 때 **`localhost` 는 허용 목록에 없어** 막힙니다.
화면에는 「저장소가 업로드를 받아 주지 않았어요 … 저희 쪽 설정 문제입니다」가 뜹니다 —
**그 안내가 정확했습니다.** 그래서 실측에서는 그 한 단계만 서버(node)에서 대신 올리고
나머지(제출·걸기·점수)는 **진짜 라우트를 그대로** 탔습니다.

⚠ **운영(onstori.com)에서는 문제가 없을 것으로 봅니다** — 이미 `sample-interior` 에 녹화 13건이
   올라가 있습니다. 다만 **제 손으로 운영에서 확인하지는 못했습니다.**
   🔴 배포 뒤에 **폰으로 한 번** 끝까지 해 보셔야 합니다. 여기가 가장 불확실한 곳입니다.

### ② 관문에서 «처음» 가입하는 분은 카메라 권한을 두 번 만납니다

가입 중에 카메라를 켜야 해서, 브라우저 권한 창이 가입 한복판에 뜹니다.
거절하시면 녹화 화면이 「카메라를 열지 못했어요」로 가고, 거기서 [갤러리에서 고르기]로
빠져나갈 수 있습니다. **막다른 길은 아닙니다.** 다만 **이탈이 여기서 날 것**입니다.

### ③ 「저장하고 중단」은 **편집화면으로 보냅니다**

찍은 것이 없으니 홈페이지 관리로 보내는 것이 맞다고 봤습니다. 다시 `/new` 로 오시면
**관문부터** 이어집니다(하루가 지나면 그 표시를 지웁니다 — 그보다 오래됐으면
«가입»이 아니라 «새로 만들기»를 하러 오셨을 가능성이 높습니다).
⚠ **다른 브라우저·다른 폰으로 오시면 이어지지 않습니다.** `localStorage` 라서입니다.
   그건 로그인한 분께만 서버에 남겨야 하는데, **시키지 않으셔서 안 만들었습니다.**

### ④ 녹화 링크를 받으려고 **기존 라우트의 «물어보기» 길**을 씁니다

`/api/story/send-link` 에 `probe: true` 로 물어 링크만 받습니다.
🔴 **그 길은 아무것도 보내지 않습니다**(그 파일 머리말이 그렇게 정합니다). **문자 요금 0원.**
⚠ `mode` 를 실어 보내면 **진짜 문자가 나갑니다.** 그 경고를 코드 주석에 박아 두었습니다.

### ⑤ 지금 만든 «테스트 홈페이지 넷»을 **정지**시켜 두었습니다

`zz-gate-test-a` · `-b` · `-c` · `-off` — 운영 DB 에 진짜로 만들어졌습니다(같은 DB뿐이라서).
**지우지 않고 `status='suspended'`** 로 돌려 두었습니다(불변 규칙 10).
⇒ 손님에게 안 보이고, 사이트맵에도 안 들어갑니다. 바꾸기 «전» 원본은 백업해 두었습니다.
🔴 **권반장이 확인하신 뒤 지울지 정해 주십시오.** 제가 지우지 않았습니다.

### ⑥ `first_edit_at` 을 **일부러 안 건드렸습니다**

영상을 걸 때 `/api/site/update` 를 쓰면 「한 번이라도 직접 고쳤다」 표시가 저절로 찍힙니다.
그건 **사이트맵의 세 관문 중 하나**(`lib/indexable.ts`)라, 가입에서 자동으로 찍히면
**AI 가 지어 준 그대로인 홈페이지를 막는 장치가 모두에게 풀립니다.**
⇒ 서버에서 직접 넣고 `applyPublish` 만 부르는 길로 만들었습니다. 실측에서 `funnel` 에
`first_edit_at` 이 **없는 것**을 확인했습니다.
