## ① 무엇을 했나

`app/my/page.tsx` — **로그인한 메일이 `REVIEW_EMAIL` 과 같을 때만** 목록 자르기를 건너뛴다.

| 누구 | 보이는 것 |
|---|---|
| 심사 계정(`REVIEW_EMAIL`) | 가진 홈페이지 **전부** (지금은 2곳) |
| 그 밖의 모든 계정 | **지금 그대로 1곳** |

```
const reviewEmail = process.env.REVIEW_EMAIL?.trim().toLowerCase();
const isReviewer  = !!reviewEmail && (user.email ?? "").trim().toLowerCase() === reviewEmail;
const sites = isReviewer ? all : all.slice(0, SITES_PER_ACCOUNT);
```

**지킨 것 셋**

1. 🔴 `SITES_PER_ACCOUNT`(1) 를 **손대지 않았다** — 일반 회원의 제품 규칙이다.
2. `REVIEW_EMAIL` 이 없는 곳(로컬 등)에서는 **아무 일도 일어나지 않는다.** 빈 값끼리 우연히
   같아지는 길을 막으려고 **「있나」부터 본다**(`!!reviewEmail &&`).
3. 대소문자·공백을 **양쪽 다 지운 뒤** 견준다 — 메일 주소는 대소문자를 안 가린다.

**하지 않은 것 둘**(권반장이 「하지 말라」 한 것 그대로)

- `sample-toss` 의 `updated_at` 을 올려 **순서로** 맞추기 — 심사관은 **1~2개월 뒤에** 본다.
  그 사이 사이트를 한 번만 고쳐도 다시 뒤집힌다.
- 계정을 새로 만들거나 사이트 주인을 옮기기 — 두 샘플이 이 계정에서 떨어져 나간다.
