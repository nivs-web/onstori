## 1. ① 소리 — **이미 「한 번 켜면 끝까지」였습니다**

권반장님이 `shorts-feed.tsx:85`(옛 **가로 레일**)를 가리키셨는데,
**지금 손님이 보는 것은 «무대»**(`shorts-stage.tsx`)입니다. 무대는 처음부터 「켬/끔 하나」였습니다.

**실측:**

```
① 처음                : 음소거 · 버튼 🔇
② 소리 단추를 한 번 누르면 : 소리 켜짐 · 버튼 🔊
   🔴 2화면 넘긴 뒤     : 2/7 — 소리 그대로 🔊
   🔴 3화면 넘긴 뒤     : 3/7 — 소리 그대로 🔊
   🔴 5화면 넘긴 뒤     : 4/7 — 소리 그대로 🔊
⑤ 페이지를 «새로» 열면  : 다시 음소거 ✅  (2026-09-10 회장님 결정 그대로)
```

### 🔴 그럼 왜 대표님은 불편하셨나 — **누를 생각이 안 났기 때문**입니다

권반장님 말씀대로입니다: 「지금은 **작은 아이콘뿐이라 누를 생각이 안 납니다**」.
⇒ **말로 한 번 알려 주는 안내**를 넣었습니다.

```
🔇 탭하면 소리가 나요      ← 무대에 들어오면 2.8초 동안. 누르면 그 자리에서 소리가 켜집니다
```

**실측:** 「무대에 들어오면 뜨나 : 🔇 탭하면 소리가 나요」 · 「2.8초 뒤 사라지나 : 예」 ·
「눌렀더니 : 소리 🔊 · 힌트 사라짐」 · **딱 한 번만** 뜹니다(오르내릴 때마다 뜨면 더 성가십니다).

### 그리고 **옛 가로 레일도 같이 고쳤습니다**

`/x/{상호}`(운영자 미리보기)에는 아직 레일이 나옵니다. 거기만 옛 방식(한 편만 소리)이면
**화면 둘이 다른 말**을 하게 됩니다. 레일도 **「한 번 켜면 끝까지」**로 맞췄습니다.

## 2. ② 폰에서 한 편이 꽉 차는가 — **이미 꽉 찹니다**

```
칸 : 390×844   화면 : 390×844   꽉참 : true
```

⚠ 대표님이 말씀하신 **「↔ 좌우로 슬라이드」**는 **옛 가로 레일**의 움직임입니다.
지금 무대는 **위아래**로 넘깁니다(틱톡·릴스·쇼츠와 같은 방향). 실측:

```
굴리면 1/7 → 2/7 → 3/7 → 4/7 → 6/7
세로 스와이프 : 위로 쓸면 2/7 · 아래로 쓸면 1/7
```

🔴 **그래서 「↔ 좌우로 넘겨 보세요」는 «넣지 않았습니다».** 넣으면 **화면이 거짓말을 합니다** —
좌우로 밀어도 아무 일이 안 일어납니다(불변 규칙 12: 말과 동작이 같아야 합니다).

⚠ **대표님께 여쭙니다:** 위아래가 맞는데 「좌우」로 안내하면 안 되니,
**「↕ 위아래로 넘겨 보세요」**로 넣을까요? (지금은 **숫자 `1 / 7`** 과 **오른쪽 점**으로만 알려 줍니다.)

## 3. ③ PC 에서 마우스만 올려도 소리 — **소리는 «안» 켭니다. 안내만 띄웁니다**

> 대표님: 「pc에선 마우스가 있으니깐 **마우스를 올리기만 해도 소리** 나오면 안 됨?」

### 🔴 저절로 켜지 «않은» 이유 둘

| | |
|---|---|
| ① | **2026-09-10 회장님 결정과 정면으로 부딪칩니다** — 「손님이 들어왔는데 **갑자기 사장님 목소리가 나면 그 자리에서 나간다**」. 마우스가 **지나가기만** 해도 소리가 나면, 그건 손님이 **원한 적 없는 소리**입니다. 우리가 막으려던 바로 그 일입니다 |
| ② | **브라우저가 막을 수 있습니다.** 「한 번도 안 누른 손님에게는 소리를 못 켠다」가 정책인데 브라우저마다 다릅니다(**사파리가 특히 엄격**합니다). ⚠ 제가 잰 것은 **헤드리스 크롬**이라 **진짜 손님 브라우저의 답이 아닙니다.** 「됩니다」라고 말할 근거가 없습니다 |

### ⇒ 대신 만든 것 — **올리면 «권하고», 켜는 것은 손님이**

```
① 가만히 있을 때        : (없음)
② 🔴 영상 위에 마우스를 올리면 : 🔇 탭하면 소리가 나요
③ 검은 여백으로 벗어나면 : (없음)
④ 눌러서 소리를 켠 뒤     : (없음) · 소리버튼 🔊
```

⚠ **마우스가 있는 기기에서만** 동작합니다 — 폰에서는 탭이 hover 처럼 들어와 안내가 붙어 버립니다.

🔴 **대표님이 「그래도 소리가 나게 해」라고 하시면 만들 수 있습니다.** 다만 위 ①번
(회장님 결정)과 부딪치는 일이라 **제가 혼자 정하지 않았습니다.**

## 4. ④ 바깥 링크는 **둘만**

```
1 / 7 → ["인스타에서 보기"]     2 / 7 → []     3 / 7 → []  …
```

**인스타그램·유튜브 쇼츠 둘만** 영상 위에 뜹니다.
⚠ **데이터를 지우지 않았습니다.** 틱톡·페북·쓰레드·X 기록은 그대로 쌓이고,
아래 ⑤ 칸에서는 **전부 보입니다.** 여기서는 «가리기»만 합니다.

★ 같은 표(이름·색)를 `shorts-feed` 와 `shorts-stage` 가 **따로** 들고 있었습니다 —
한쪽만 고치면 화면 둘이 다른 말을 합니다. **한 파일로 모았습니다**(`sns-brand.ts`).

## 5. ⑤ 「이 가게 영상이 나가고 있는 곳」 — 무대 **바로 아래**

```
무대 다음이 그 칸인가 : sns-strip  ✅
제목        : 이 가게 영상이 나가고 있는 곳
나열된 곳   : ["인스타그램"]
링크        : https://www.instagram.com/reel/…
```

### 🔴 무엇을 «연결»로 볼 것인가 — 가장 정직한 값을 골랐습니다

| 후보 | |
|---|---|
| 사장님이 **적어 넣은 주소**(`settings.channels`) | ⚠ **적기만 하고 아무것도 안 나갔을 수** 있습니다. 게다가 이미 **떠 있는 채널 위젯**이 보여 줍니다 — 두 번 그릴 이유가 없습니다 |
| 🔴 **실제로 «올라간» 기록**(`sns_posts` 의 발행 완료) | ✅ 대표님 말씀이 「퍼뜨리고 **있구나**」이므로 **진짜 나간 것만** 세는 것이 맞습니다 |

🔴 **연결 안 된 것을 「준비 중」으로 늘어놓지 않았습니다**(권반장 지시).
**하나도 없으면 이 칸 자체를 안 그립니다.**

★ 자리도 신경 썼습니다 — 무대(검정)에서 본문(밝음)으로 넘어가는 **딱 그 자리**라
이 칸을 **검은 채로** 두고, 밝아지는 것은 **그 다음 섹션**이 하게 옮겼습니다.
⚠ 안 옮겼으면 「검정 위에 검정」이라 **밝아지는 연출이 통째로 사라지고** 다음 섹션이 툭 끊겼습니다
— **실측으로 잡았습니다.**

다만 **대표님이 폰으로 보셔야 판단이 되실 것** 같아 **일단 넣고** 여쭙니다(§2-0 「일단 만들어」).

| SNS 모음 칸 제목 | **「이 가게 영상이 나가고 있는 곳」** |

🔴 **바꾸라고 하시면 각각 한 줄만 고치면 됩니다.**

### ② **「↔ 좌우로 넘겨 보세요」는 안 넣었습니다**

지금 무대는 **위아래**로 넘어갑니다. 좌우라고 쓰면 **화면이 거짓말**을 합니다.
⇒ **「↕ 위아래로 넘겨 보세요」로 넣을까요?**

### ③ **진짜 폰·사파리에서는 못 재 봤습니다**

특히 ③(마우스 소리)의 브라우저 정책은 **헤드리스 크롬의 답을 믿으면 안 됩니다.**

### ④ **`sample-interior` 에는 인스타 기록 하나뿐**입니다

⑤ 칸이 **한 줄만** 나옵니다. 대표님이 기대하신 「여러 SNS 가 죽 나열되는」 모습은
**실제로 여러 곳에 올린 뒤에야** 보입니다. **없는 것을 그리지 않기로** 한 결과입니다.

### ⑤ 옛 레일(`/x/` 미리보기)은 **여전히 좌우**입니다

손님 화면이 아니라 **운영자 미리보기**라 그대로 뒀습니다. 소리·링크만 맞췄습니다.
