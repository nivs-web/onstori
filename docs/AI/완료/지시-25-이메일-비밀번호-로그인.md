## 1. 🔴 완료 조건 여섯 — **실제로 눌러 본 결과**

대표님이 「테스트까지 꼭 해보라」고 하셔서, 진짜 크롬으로 **가입부터 재설정까지 끝까지** 돌렸습니다.
⚠ 메일함을 읽을 수 없어, **메일에 들어갈 그 링크·그 번호**를 서버에서 뽑아 **같은 흐름**을 태웠습니다.

| # | 조건 | 결과 |
|---|---|---|
| 1 | 새 이메일로 **가입** → 확인 메일 → 링크 눌러 인증 | ✅ 계정 생성됨 · 링크 누른 뒤 **`메일 확인됨: 예`** 로 바뀜 |
| 2 | 로그아웃 후 **다시 로그인** | ✅ **`/my` 로 들어감** |
| 3 | **비밀번호 재설정** → 새 비밀번호로 로그인 | ✅ `/login/new-password` → 저장 → **`/my`** · 새 비밀번호로 로그인 **`/my`** |
| 4 | **카카오 로그인이 여전히 되는지** | ✅ `/auth/kakao` → **307 → `kauth.kakao.com`** (코드는 한 글자도 안 건드렸습니다) |
| 5 | **심사용 계정이 살아 있는지** | ⚠ **로컬에서 확인 못 함** — 아래 §4 ① |
| 6 | 틀린 비밀번호 문구가 **어느 쪽인지 흘리지 않는지** | ✅ 「**이메일이나 비밀번호가 맞지 않아요.**」 — 흘리지 않음 |
| ★ | 카카오 계정에 비밀번호 로그인 → 안내 | ✅ 「**이 이메일은 카카오로 시작하셨어요**」 뜸 |

**실제 출력 그대로:**

```
② 가입 누른 뒤: … 메일을 보냈어요 / zz-login-test-…@onstori.com 로 보냈습니다 …
   DB 에 계정 생겼나: 예 | 메일 확인됨: 아니오(확인 메일 필요)
③ 확인 메일 링크: 받음 → 메일 확인됨으로 바뀌었나: 예
④ 로그아웃 후 다시 로그인 → 간 곳: /my
⑤ 틀린 비밀번호 문구: 이메일이나 비밀번호가 맞지 않아요.
   어느 쪽이 틀렸는지 흘리나: 안 흘린다
⑥ 카카오 계정에 비밀번호 로그인 → 안내 떴다
② 링크가 데려간 곳: /login/new-password?next=%2Fmy
③ 저장 뒤 간 곳: /my
④ 새 비밀번호로 로그인 → 간 곳: /my
⑨ /auth/kakao → 307 카카오로 보낸다
```

## 2. 만든 화면 — 「요즘 사이트들 업계 표준」

로그인 화면 하나가 **넷으로** 움직입니다:

| 화면 | 무엇 |
|---|---|
| **로그인** | 이메일 + 비밀번호 · **[보기]** 눈 · [비밀번호를 잊으셨나요?] · [처음이신가요? 가입하기] |
| **가입** | 이메일 + 비밀번호(8자 이상) → **확인 메일** 안내 |
| **비밀번호 찾기** | 메일 주소 하나 → 재설정 메일 |
| **메일 보냄** | 「스팸함도 봐 주세요」까지 |

**새 비밀번호 정하기**(`/login/new-password`)는 메일 링크가 도착하는 자리입니다.
바꾸는 순간 **그대로 로그인된 채로** 갈 곳으로 보냅니다 — 다시 로그인하라고 하지 않습니다.

### 시키신 여섯 가지

| 시키신 것 | 한 것 |
|---|---|
| 1. **비밀번호를 잊으셨나요?** | ✅ 로그인 화면 왼쪽 아래 |
| 2. 인증번호로 가입한 분께 **「비밀번호 만들기」** 길 | ✅ 같은 길을 **다른 말로 한 번 더** 안내합니다 — 「전에 **인증번호**로 로그인하셨나요? 그때는 비밀번호가 없었어요」 |
| 3. **8자 이상**, 대문자·특수문자 강요 금지 | ✅ 8자만 봅니다 |
| 4. **[보기] 눈** | ✅ 두 화면 모두 |
| 5. **어느 쪽이 틀렸는지 알려 주지 않기** | ✅ 「이메일이나 비밀번호가 맞지 않아요」 |
| 6. 카카오 계정이면 **카카오로 안내** | ✅ 실측으로 뜨는 것 확인 |

## 3. 🔴 만들다가 찾은 것 — **안내가 영영 안 뜰 뻔했습니다**

카카오 안내(6번)를 만들려면 「이 메일이 카카오로만 들어오는가」를 알아야 합니다.
처음에는 `listUsers()` 가 주는 `identities` 를 그대로 믿었는데, 실제로 찍어 보니:

```
listUsers 가 identities 를 주나 : null      ← 🔴 늘 비어 있다
getUserById 가 주나            : ["email"] ← 한 명을 다시 물어야 온다
```

⇒ 그대로 뒀으면 **어떤 계정도 카카오로 안 보여 그 안내가 한 번도 안 떴을 것**입니다.
한 명을 다시 묻도록 고쳤고, **실측으로 안내가 뜨는 것을 확인**했습니다.

## 4. 🔴 못 한 것 · 알고 계셔야 할 것

### ① 심사용 계정(`REVIEW_EMAIL`)은 **로컬에서 확인하지 못했습니다**

`REVIEW_ID`·`REVIEW_PASSWORD`·`REVIEW_EMAIL` 이 **`.env.local` 에 없습니다**(Vercel 에만 있습니다).
그래서 `/login/review` 는 로컬에서 **404** 입니다 — **그게 맞는 동작**입니다(열쇠가 없으면 그 화면은 없습니다).

**대신 «깨질 수 없다»는 근거를 댑니다:**
- 심사용 로그인은 `/api/auth/review` 가 **magiclink 로 서버에서** 세션을 엽니다 —
  제가 고친 `/login/ui.tsx` 와 **길이 완전히 다릅니다**
- `git status` 로 확인했습니다: **`review` 가 들어간 파일을 하나도 안 건드렸습니다(0건)**
- 계정 목록에 `re***@onstori.com` 이 **그대로 있고**, 방식은 `email` 입니다

🔴 그래도 **배포 뒤 한 번 눌러 봐 주십시오.** 「안 건드렸으니 괜찮다」는 제 추론이지 실측이 아닙니다.

### ② 🟢 비밀번호 재설정 — **운영에서는 됩니다. 로컬에서만 안 됩니다**

재설정 메일의 링크가 어디로 돌아올지는 **Supabase 허용 목록**이 정합니다. 직접 물어봤습니다:

```
http://localhost:3000/login/new-password  → 🔴 거절 (https://onstori.com/ 으로 떨어짐)
https://onstori.com/login/new-password    → ✅ 허용됨
https://onstori.com/                      → ✅ 허용됨
```

⇒ **운영 주소는 이미 허용돼 있습니다. 대시보드를 건드릴 필요가 없습니다.**
⇒ 로컬에서는 그 링크가 운영으로 가 버려서, **같은 메일에 들어 있는 1회용 번호**로
   재설정 세션을 만들어 **우리 화면의 진짜 로직을 그대로** 태워 확인했습니다(위 §1 3번).

⚠ **배포 뒤 폰에서 한 번 «진짜 메일»로 해 보시면 완전히 끝납니다.**

### ③ 「가입 확인 메일」이 **정말 나가는지**는 확인 못 했습니다

계정이 `메일 확인됨: 아니오` 로 만들어진 것 ⇒ **Supabase 가 확인을 요구하도록 켜져 있다**는 뜻이고,
그러면 확인 메일이 나갑니다. 다만 **메일함을 못 읽어 «도착»은 확인 못 했습니다.**
⚠ Supabase 기본 메일은 **시간당 발송 한도**가 있습니다. 가입이 몰리면 막힐 수 있습니다 —
   `docs/WAITING.md` 에 「SMTP 를 붙일지」 한 줄 올렸습니다.

### ④ ⚠ 카카오 안내는 **「그 메일이 있다」는 사실을 흘립니다**

지시 5번(어느 쪽이 틀렸는지 숨겨라)과 **일부 상충**합니다. 권반장 지시 6번이 막으려는 손해
(카카오 사장님이 **영영 못 들어옴**)가 더 크다고 보아 만들었습니다.
줄이려고 셋을 지켰습니다: **로그인이 실패한 뒤에만** 물어봄 · 돌려주는 값은 **참/거짓 한 칸** ·
**카카오 전용일 때만** 참(없는 메일·비밀번호 있는 메일은 전부 거짓이라 여전히 구별 안 됨).
🔴 **대표님이 아니라고 하시면 `app/api/auth/how` 만 지우면 됩니다** — 화면은 그대로 돕니다.
