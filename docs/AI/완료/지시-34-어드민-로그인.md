| 🔴 대표님 제안과 다르게 한 것 | **심사용 비밀번호를 쓰지 않았습니다.** 이유 §2 |

## 1. 대표님 질문에 먼저 답합니다 — **메뉴가 «없었습니다»**

> 대표님: 「**우리 고객이 비밀번호 변경하는 거 메뉴 만들었나?**」

**화면은 [25] 때 이미 있었습니다**(`/login/new-password`). 그런데 **거기로 가는 길이 없었습니다.**

로그인한 사장님이 비밀번호를 바꾸려면 —
**로그아웃 → 「비밀번호를 잊으셨나요?」 → 메일 확인 → 링크 누르기.**
그건 **「바꾸기」가 아니라 「되찾기」**입니다.

⇒ **마이페이지에 「비밀번호 바꾸기」 한 줄을 냈습니다.**
★ **새 화면을 만들지 않았습니다.** 그 화면은 **로그인만 돼 있으면 그대로 돕니다** — **길만** 냈습니다.

---

## 2. 🔴 대표님 제안대로 «안» 한 것 — 이유를 말씀드립니다

> 대표님: 「일단 비번에 시간 낭비하지 말고 **`review@onstori.com` 비번이랑 똑같은 걸로 일단 만들어.**
> 내 admin 비번은 **첫 로그인할 때 즉시 내가 스스로 바꿀게.** … **보안 걱정 안 해도 됨**」

### 🔴 그 비밀번호는 «심사관에게 우리가 직접 알려 주는» 값입니다

토스·유튜브·메타 심사관에게 **그 아이디와 비밀번호를 적어서 제출**합니다.
어드민이 그 값을 받아 주면 — **심사관이 `/admin` 에 들어올 수 있습니다.**

거기에는 **회원 명부 · 결제 내역 · 문자 발송 · 사이트 폐쇄 버튼**이 다 있습니다.

⚠ 「곧 바꿀 거니까 괜찮다」로 넘기기엔 **바꾸시기 «전»까지**가 위험합니다.
그리고 심사는 **며칠에서 몇 주** 걸립니다 — 그동안 그 값이 바깥에 나가 있습니다.

### ⇒ 대신 **대표님이 화면에서 «직접» 정하는 길**을 만들었습니다

```
/admin  맨 아래 — 「어드민 로그인」
   [ 아이디·비밀번호 만들기 ]
      아이디 (영문·숫자)   새 비밀번호 (8자 이상)   [저장]
```

**한 번 정하시면 끝입니다.** 「첫 로그인할 때 즉시 내가 스스로 바꿀게」가 **그대로 됩니다** —
오히려 **바꾸실 필요 없이 처음부터 대표님 값**입니다.

🔴 **제가 그 값을 볼 일이 없습니다.** 불변 규칙 6을 **구조로** 지킵니다.

## 3. 🔴 비상구를 «지우지 않았습니다»

> 권반장님: 「**지금 방식을 «바로 지우지» 마십시오.** 못 들어가면 **대표님이 어드민에서 잠깁니다.**」

**문이 둘입니다:**

| 문 | 무엇으로 | |
|---|---|---|
| ① **아이디 + 비밀번호** | 대표님이 정하신 값 | 평소에 쓰는 길 |
| ② **열쇠(ADMIN KEY)** | Vercel 환경변수 | 🔴 **비상구. 그대로 살아 있습니다** |

**실측:**

```
⑥ 🔴 비상구(열쇠)가 여전히 되나 : 200 · 쿠키 줌
   틀린 열쇠 : 401
```

⚠ 로그인 화면에서 **［열쇠(ADMIN KEY)로 들어가기］** 한 줄로 오갑니다.
기본은 아이디·비밀번호이고, 열쇠는 **접혀** 있습니다.

## 4. 실측 — 여덟 가지

```
① 만들기 전 상태        : 200 {"ready":false,"id":null}
② 운영자가 아닌 사람이 보면 : 401 unauthorized

③ 🔴 못 쓰게 막는 것들
   한글 아이디      : 400 「아이디는 영문·숫자로 3~40자로 …」
   짧은 비밀번호    : 400 「비밀번호는 8자 이상으로 …」
   🔴 열쇠와 같은 값 : 400 「지금 쓰시는 열쇠와 다른 비밀번호로 …」

④ 제대로 만들기 : 200 {"ready":true,"id":"zz-test-admin"}

⑤ 🔴 아이디·비밀번호로 들어가기
   맞게 넣으면     : 200 · 쿠키를 줌
   비밀번호 틀리면 : 401     아이디 틀리면 : 401
   🔴 어느 쪽이 틀렸는지 : 둘 다 같은 401 — 안 알려 줍니다

⑥ 🔴 비상구(열쇠) : 200 · 쿠키 줌      틀린 열쇠 : 401

⑦ 🔴 저장소에 «비밀번호 자체»가 있나
   칸 : ["id","salt","hash","at"]      비밀번호가 그대로 있나 : false

⑧ 🔴 시험용 비밀번호를 지웠습니다 (대표님이 직접 정하셔야 합니다)
```

### 안전하게 만든 것 다섯

| | |
|---|---|
| ① | **비밀번호를 그대로 저장하지 않습니다** — `scrypt` 로 되돌릴 수 없게. 저장소를 통째로 가져가도 안 나옵니다(실측 ⑦) |
| ② | **어느 쪽이 틀렸는지 안 알려 줍니다** — 알려 주면 아이디를 하나씩 맞혀 볼 수 있습니다 |
| ③ | **시간이 일정한 비교**(`timingSafeEqual`) — 응답 시간 차이로 한 글자씩 알아내는 것을 막습니다 |
| ④ | **무차별 대입을 막습니다** — 10분에 10번, 하루 60번. ⚠ **열쇠 쪽에는 원래 없던 장치**인데 이제 **둘 다** 걸었습니다(문이 둘이면 약한 쪽으로 들어옵니다) |
| ⑤ | **심사용·열쇠와 같은 값을 못 쓰게** 막습니다 |

⚠ **새 표를 안 만들었습니다.** 이미 있는 `admin_notes`(설정 보관함)에 **id 하나만 더** 씁니다 —
**마이그레이션이 필요 없습니다.**

## 5. 🔴 못 한 것 · 걱정거리

### ① **대표님이 «아직 안 만드셨습니다»**

제가 만든 시험용 값은 **지웠습니다.** 지금 `/admin` 은 **「아직 아이디·비밀번호를 안 만드셨습니다」**로 뜹니다.
⇒ **배포 뒤 열쇠로 한 번 들어오셔서 만드셔야** 합니다. **30초**입니다.

### ② **잊으시면 저도 못 알려 드립니다**

되돌릴 수 없게 저장하기 때문입니다. 그때는 **［열쇠로 들어가기］**로 들어와 **다시 정하시면** 됩니다.
🔴 **그래서 열쇠를 안 지웠습니다.** 열쇠까지 잃으시면 **아무도 못 여는 문**이 됩니다.

### ③ **아이디·비밀번호는 «한 벌»뿐입니다**

사람이 여럿이면 누가 들어왔는지 못 가립니다. 지금은 대표님 한 분이라 문제가 없습니다만,
직원이 생기면 **사람별 계정**이 필요합니다(원래 `P7 운영자 인증 교체`로 이월돼 있는 일입니다).

### ④ **로그아웃 버튼이 여전히 없습니다**

쿠키가 **30일**입니다. 공용 PC 에서는 위험합니다. 이것도 P7 이월 건이라 이번 범위 밖으로 뒀습니다.

### ⑤ **사장님 「비밀번호 바꾸기」는 카카오로 들어오신 분께는 «안 맞습니다»**

카카오로 시작하신 분은 **비밀번호가 아예 없습니다.** 그 링크를 누르시면 새로 만드는 화면이 뜹니다 —
동작은 하지만 **「바꾸기」라는 말과는 어긋납니다.** ⚠ 지금은 그대로 뒀습니다.
