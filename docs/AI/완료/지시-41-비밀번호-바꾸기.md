# 지시 [41] — 비밀번호 바꾸기가 「지금 비밀번호」를 안 묻던 것

**날짜:** 2026-09-17 (밤) · **급함: 🔴 높음 (오픈 전)**
**한 줄:** 막았습니다. **그리고 만들면서 제 판단이 두 번 틀렸는데, 둘 다 «재 보고» 잡았습니다.**

---

## 1. 무엇이 뚫려 있었나 — 권반장님 진단이 **맞았습니다** (제가 직접 열어 확인)

`app/my/ui.tsx` 의 「비밀번호 바꾸기」가 **`/login/new-password` 로 그냥 보냅니다.**
그 화면은 원래 **「비밀번호 찾기」**(메일 링크로 온 사람) 용이라 **안 묻는 것이 «정상»**입니다.
그 파일 주석에도 그렇게 적혀 있었습니다 — 「⚠ 그 화면은 **로그인만 돼 있으면 그대로 돈다**」.

⇒ **로그인한 채 자리를 비우면, 남이 마이페이지에서 비밀번호를 바꿔 계정을 통째로 가져갑니다.**

## 2. 고친 방식 — **자물쇠를 «화면»에서 «서버»로 옮겼습니다**

전에는 화면이 `sb.auth.updateUser({ password })` 를 **직접** 불렀습니다.
🔴 화면에서만 물으면 **개발자도구로 그 칸을 건너뛰면 그만**입니다.

⇒ 바꾸는 길을 **`/api/account/password` 한 곳**으로 모았습니다. 화면은 **묻는지 마는지를 «받아서 보여 줄» 뿐**입니다.

### 「지금 비밀번호」를 안 묻는 경우가 둘 — **둘 다 «물을 수가 없는» 경우입니다**

| 언제 | 왜 안 묻나 |
|---|---|
| **메일 링크로 들어온 세션** | 잊어버려서 오신 분입니다. 물으면 **영영 못 바꿉니다** |
| **카카오로만 시작하신 분** | 비밀번호를 **만든 적이 없습니다.** 물으면 무엇을 넣어도 틀립니다 |

🔴 **그 판정을 «주소나 화면이 준 값»으로 하지 않습니다.** 그러면 공격자가 그 값을 붙여 물음을 건너뜁니다.
**세션 토큰 안의 `amr`**(이 세션이 «무엇으로» 만들어졌나)을 봅니다 — **Supabase 가 서명한 값이라 브라우저에서 못 고칩니다.**

### 함께 넣은 것

- **무차별 대입 막기** — 「지금 비밀번호」를 받는 칸이라 안 막으면 **여기서 남의 비밀번호를 찍어 볼 수 있습니다.**
  **사람과 IP 를 «둘 다»** 셉니다(10분 10회 · 하루 60회). IP 를 바꿔 가며 한 계정을 노리는 것도 막힙니다.
- **다른 기기 로그아웃**(권반장 지시 ②) — 바꾸는 이유의 절반은 「누가 내 계정을 보고 있을지도 모른다」입니다.
- **바꿨다고 «분명히» 알리기**(지시 ③) — 「비밀번호를 바꿨어요」 화면 + **다른 기기를 끊었는지까지 사실대로.**
- **`PW_MIN` 을 `config/password.ts` 한 곳으로** — 숫자 8 이 **세 곳**에 따로 박혀 있었습니다.

## 3. 🔴🔴 제가 두 번 틀렸고, **둘 다 재 보고 잡았습니다**

### ① 운영자 열쇠로 바꿨더니 — **사장님이 자기 브라우저에서 쫓겨났습니다**

처음에는 `admin.updateUserById()`(운영자 열쇠)로 짰습니다. 실측:

```
⑤ 맞는 비밀번호로 바꾸기      → 200 {"ok":true,"othersOut":false}
⑥ 바꾼 뒤 이 기기는 살아 있나 → 401 「로그인이 필요해요」        ← 🔴 나도 쫓겨났다
서버 로그                     → pw_change_others_signout_failed … "Auth session missing!"
```

운영자 열쇠로 바꾸면 **그 사람의 세션을 «전부» 날립니다.** 그다음 줄의 「다른 기기 끊기」는
**이미 다 끊겨서** 실패했습니다. 사장님은 비밀번호를 바꾸자마자 **영문도 모르고 로그아웃**됩니다.

⇒ **사장님 «자신의 세션»으로** 바꾸게 고쳤습니다. 다시 재니:

```
⑤ 바꾸기              → 200 {"ok":true,"othersOut":true}
⑥ 이 기기 살아 있나    → 200          ⑦ /my 열리나 → 200
다른 기기 — 지금 토큰   → 끊김 403
다른 기기 — 이어가기    → ✅ 끊김 400
옛 비밀번호로 로그인    → 안 됨        새 비밀번호로 → 됨
```

### ② 🔴 **비밀번호를 «잊은» 분을 영영 못 바꾸게 만들 뻔했습니다**

「메일 복구 세션의 `amr` 은 `recovery` 일 것」이라고 **문서를 읽고** 썼습니다.
그건 **실측이 아니었습니다.** 그리고 **지금 메일이 안 나가는 환경이라 아무도 못 밟아 보는 길**이라,
그대로 냈으면 **SMTP 를 붙이는 날 조용히 터졌을** 것입니다.

**메일을 «보내지 않고»** 복구 링크만 받아(`admin/generate_link`) **링크를 누른 것과 똑같은 확인 절차**를 밟아 재 봤습니다:

```
복구 세션의 amr = [{"method":"otp","timestamp":…}]        ← 🔴 "recovery" 가 «아니다»
비밀번호 로그인  = [{"method":"password","timestamp":…}]
```

⇒ 받아들이는 이름을 **`otp`·`magiclink`·`recovery` 셋**으로 고쳤습니다. 그리고 **그 세션으로 실제로 확인**했습니다:

```
① 복구 세션 — 지금 비밀번호를 묻나        → 200 {"needsCurrent":false,"why":"recovery"}
② 복구 세션 — 지금 비밀번호 «없이» 바꾸기 → 200 {"ok":true,"othersOut":true}
바뀐 비밀번호로 로그인                    → 됨      옛 비밀번호 → 안 됨
```

★ **배운 것: 「문서에 그렇게 적혀 있다」는 실측이 아닙니다.** 특히 **아무도 못 밟아 보는 길**일수록.

## 4. 구멍이 막혔는지 — **재 본 것 전부**

| 무엇 | 결과 |
|---|---|
| 로그인 없이 GET · POST | `401` |
| 🔴 **`amr=recovery` 로 «위조»한 토큰**으로 POST | `401` — 서명이 가짜라 Supabase 가 거절 |
| 로그인한 채 「물어야 하나」 | `{"needsCurrent":true,"why":"signed-in"}` |
| 지금 비밀번호 **없이** | `400` 「지금 쓰시는 비밀번호를 넣어 주세요.」 |
| 지금 비밀번호가 **틀림** | `401` 「지금 비밀번호가 맞지 않아요.」 |
| 새 비밀번호가 **너무 짧음** | `400` 「비밀번호는 8자 이상으로 만들어 주세요.」 |
| 맞는 비밀번호로 바꾸기 | `200` · 이 기기 살아 있음 · **다른 기기 끊김** · 옛 비밀번호 안 됨 |
| 화면(`/login/new-password`) | 「**지금 쓰시는 비밀번호**」 칸이 뜨고, 다 하면 「**비밀번호를 바꿨어요**」 |

⚠ **시험은 «버리는 계정 둘»로 했고, 끝나고 지웠습니다.** 남은 흔적 0건을 확인했습니다
(`pw41 시험 계정 남은 것 : 0` · `그 계정에 붙은 사이트 : 0` · 전체 계정 수 6 그대로).
🔴 **손님 계정과 사장님 자료는 한 줄도 건드리지 않았습니다.**

## 5. ⚠ 못 한 것 · 걱정되는 것

| 무엇 | 왜 |
|---|---|
| **카카오로만 시작하신 분**은 못 재 봤습니다 | 그런 시험 계정을 만들려면 **진짜 카카오 로그인**이 필요합니다. 코드는 「이메일 신원이 없으면 안 묻는다」인데 **눌러 보지 못했습니다** |
| 🔴 **「로그아웃 뒤 뒤로가기로 화면이 다시 보이나」** | 권반장님이 「실제 브라우저로 눌러 봐야 안다」고 남기신 항목입니다. **이번에 못 했습니다** |
| **어드민 쿠키 값이 열쇠 그 자체인 것** | 권반장님이 「지금 뚫린 것은 아니다 · 이번에 같이 할 필요 없다」고 하셔서 **안 건드렸습니다**(P7) |
| ⚠ **메일은 여전히 안 나갑니다** | 복구 «세션»은 재 봤지만 **메일 도착은 못 봤습니다** — SMTP 는 회장님 손입니다(`WAITING.md` 맨 위) |
| ⚠ **심사용 로그인(`/login/review`) 세션도 `otp`** 입니다 | 그 세션은 지금 비밀번호를 안 묻습니다. 심사관 전용 계정이고 그 길 자체가 서버 열쇠로 잠겨 있어 **손님 계정과는 상관없습니다.** 다만 **알고는 계셔야** 합니다 |
