## 1. ③ 가상화 — **화면에 살아 있는 영상은 «항상 세 개»**

> 조사: 「크롬은 한 화면에 살아 있는 영상 재생기를 **폰 40개·PC 75개**까지만 허용한다.
> 넘으면 「Blocked attempt to create a WebMediaPlayer」와 함께 **조용히 검은 화면**이 된다」

**실측 — 끝까지 굴려 봤습니다:**

```
① 첫 화면에서 내려받은 «표지» 장수 : 2   (전에는 7장 = 편수만큼)
   칸(figure) 수 : 7 · <video> 수 : 2

② 굴리는 내내
   1/7 → <video> 2개      2/7 → 3개      3/7 → 3개
   4/7 → 3개              5/7 → 3개      7/7 → 2개
```

★ **칸(`<figure>`)은 N개 그대로** 뒀습니다 — 무대 높이·눈금은 CSS 가 그 수로 계산합니다.
**건드리지 말라**는 그 계산입니다. 실측으로 확인:

```
③ 무대 높이·눈금 : { 편수: "7", 화면수: 8, 눈금: 7 }   ← 전과 똑같습니다
④ 소리·재생      : { 지금 편이 재생 중인가: true, 음소거: true }
⑤ 「움직임 줄이기」 : <video> 7개 · 전부 멈춰 있음      ← 평범한 목록은 그대로
```

⚠ 「움직임 줄이기」에서는 **전부 그립니다.** 그건 평범한 목록이고, 자동재생이 없고
`preload="none"` 이라 **바이트가 안 샙니다.**

## 2. 🔴 만들다 잡은 것 «셋» — 전부 «눌러 보지 않으면» 안 보이는 것들

### ① **살아 있는 영상의 `src` 를 제가 지우고 있었습니다**

조사서가 시킨 세 줄(`pause` · `removeAttribute('src')` · `load()`)을 **`ref` 콜백**에 넣었습니다.
그런데 **React 는 화면을 다시 그릴 때마다 인라인 `ref` 를 «뗐다 붙입니다».**
저는 그 «떼는 순간»을 「사라진다」로 착각했습니다.

```
고치기 전 : 모든 영상이 { src있나: false, 준비: 0, 멈춤: true }   ← 아무것도 안 나옴
고친 뒤   : { on: true, 멈춤: false, 준비: 4, src있나: true }      ← 지금 편만 재생
```

⇒ 정리를 **효과(`useEffect`)의 뒷정리**로 옮겼습니다 — 그건 **진짜 사라질 때만** 돕니다.
⚠ 개발 중에는 React 가 효과를 두 번 돌리므로(StrictMode) **화면에서 실제로 떨어졌는지
(`isConnected`)** 를 한 번 더 봅니다.

### ② **빈 칸이 «클릭을 가로챘습니다»**

가상화로 멀리 있는 칸은 **영상 없는 빈 상자**만 남는데, 그 상자가 화면 전체를 덮어
**눌러도 전체화면이 안 열렸습니다**(DOM 뒤쪽 칸이 위에 깔립니다).
⇒ **빈 칸은 못 누르게** 했습니다.

### ③ 🔴 **제 ① 안내가 «영영 안 뜰» 뻔했습니다**

편집화면에서 **목록 길이로** 편수를 세었는데, **그 목록은 이미 20편으로 잘려서 옵니다.**
25편을 거셔도 화면에는 20줄뿐이라 **「20편을 넘었다」가 성립할 수가 없었습니다.**

⇒ **서버가 «걸린 전체 편수»를 따로 세어** 주게 했습니다(줄은 안 가져오고 수만 셉니다).

**상한을 잠깐 5로 낮춰 실제로 띄워 본 화면:**

```
지금 7편을 걸어 두셨는데, 홈페이지에는 최신 5편이 나옵니다.
꼭 보여 주고 싶은 영상은 [▲ 위로] 로 순서를 올려 주세요.
```

⚠ **상한은 20으로 되돌렸습니다**(7편이라 지금은 안 뜨는 것이 정상 — 실측 확인).

## 3. ① 숫자 20 이 **두 곳에 따로 박혀** 있었습니다

`lib/shorts.ts` 의 `SHORTS_MAX` 와 `app/api/site/videos/route.ts` 의 `LIMIT`.
**한쪽만 고치면** 편집화면은 25편을 보여 주는데 홈페이지는 20편만 나오는 식이 됩니다.

⇒ **`config/shorts.ts` 한 곳**으로 모았습니다.

### ⚠ 왜 `lib/` 이 아니라 `config/` 인가

`lib/shorts.ts` 는 **R2·S3 도구를 끌어옵니다** — 서버에서만 도는 코드입니다.
편집화면은 **화면 코드**라, 거기서 그것을 import 하면 **손님 브라우저로 갈 뭉치에
S3 도구가 딸려 갈 위험**이 있습니다.
🔴 **[32] 에서 `lib/admin-auth.ts` 로 똑같은 병을 겪었습니다**(그때는 빌드가 아예 깨졌습니다).
이번에는 **빌드가 통과했지만** 같은 자리라 **위험을 없애는 쪽**을 골랐습니다.

## 4. ② 표지 — **재 보고 나서** 고쳤습니다

조사서가 「**먼저 잴 것**: 정말로 표지 N장이 다 내려오는지」라고 했습니다. 쟀습니다:

```
고치기 전 : 첫 화면(히어로)에서 이미 표지 7장 요청 · poster 붙은 <video> 7개
고친 뒤   : 첫 화면에서 2장
```

⇒ **필요한 작업이 맞았습니다.** 가상화가 표지까지 함께 해결했습니다.

⚠ `loading="lazy"` 는 **안 붙였습니다.** `<video>` 에는 React 가 그 속성을 인정하지 않고,
**영상이 세 개뿐이라 값어치가 없습니다.**

## 5. 🔴 못 한 것 · 걱정거리

### ① 🔴 **④(무대 12편 + 무한스크롤)를 안 했습니다** — 그래서 **21편 제한이 «그대로»입니다**

지금 한 것은 **「거짓말을 멈추고, 느려지지 않게」**까지입니다.
**여전히 21편째부터는 홈페이지에 안 나옵니다** — 다만 이제 사장님이 **그 사실을 압니다.**

⚠ 조사서는 「**③ 없이 상한만 풀면** 태그가 100개 생겨 진짜로 느려진다」고 했고,
**③이 끝났으므로 이제 상한을 풀 수 있습니다.** 다만 ④까지 해야 안전합니다 —
`.stage` 높이가 `(N+1)×100svh` 라 **1000편이면 81만px**, 스크롤바가 못 쓰게 됩니다.

### ② **진짜 폰에서는 못 쟀습니다**

크롬 재생기 상한(폰 40개)에 걸리는지는 **실제 폰**에서 봐야 압니다.
`chrome://media-internals` 확인도 못 했습니다(헤드리스로는 못 엽니다).

### ③ **편집화면에 옛 오류가 하나 보입니다**

콘솔에 「Encountered two children with the same key」가 뜹니다.
**제 변경 전부터 있던 것**으로 보이나 **확인은 못 했습니다.** 범위 밖이라 그대로 뒀습니다.

### ④ **1000편을 실제로 걸어 보지 못했습니다**

가장 많은 사이트가 **17편**입니다. 「항상 3개」는 7편으로 확인한 것이라
**100편·1000편에서도 그런지는 «구조상 그렇다»는 설명**이지 실측이 아닙니다.
