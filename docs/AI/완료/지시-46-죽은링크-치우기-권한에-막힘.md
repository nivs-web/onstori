# 죽은 인스타 링크 2건 치우기 — **권한에 막혀 «못 했습니다»**

날짜: 2026-09-18 · 승인: 권반장(조건 셋) · 상태: **막힘 — 대표님이 모드를 바꾸셔야 함**

## 0. 한 줄

**백업까지 끝냈는데 `auto` 모드가 DB 쓰기를 거부했습니다. 아무것도 안 바뀌었습니다.**
**모드만 열리면 아래 §3 을 그대로 실행하면 «1분»입니다.**

## 1. 무엇을 치우려 했나

`/sample-interior` 「다산 리모델링 (샘플사이트)」의 **「인스타에서 보기」 링크 2개**.
**그 글들은 인스타에 없습니다** — 누르면 없는 페이지로 갑니다(불변 규칙 12: 화면이 거짓말을 한다).

|---|---|---|
| `bc91ef0c-f0a6-431a-9463-c641f69edb9d` | `17875798389564182` | `https://www.instagram.com/reel/DdWnIP-lMzi/` |
| `75845510-cffd-4213-a413-854159f3c895` | `18129024544774483` | `https://www.instagram.com/reel/DdYq0GiEkah/` |

## 2. 왜 손으로 하나 — 크론을 기다리지 않는 이유

- 크론은 `RECHECK_AFTER_DAYS(7)` 이라 **09-23~24** 에야 잡습니다
- 🔴 **토스페이먼츠 심사관이 이 사이트를 봅니다** — `WAITING.md` 의 `REVIEW_SITE = sample-interior`
  (심사관이 로그인하면 **이 사이트로 들어옵니다**). 그전에 치우는 것이 낫습니다

⚠ **자동 판정 규칙(`isPostAlive`·주기)은 손대지 않습니다.** 이건 **확인된 사실 2건을 손으로 적는 것**입니다.

## 3. 🔴 근거 — 왜 「없다」고 단정할 수 있나

> **2026-09-18 · 계정 글을 «끝까지» 넘겨 144건 «전부»와 대조해 없음을 확인.**
> `me/media` 2쪽 · CAROUSEL 108 · IMAGE 33 · VIDEO 3 · **가장 최근 글 2025-04-30 · 2026년 글 0건.**
> 우리 2건은 **id 로도 주소로도 없음.**
> ⚠ 「릴스라서 안 읽히나」를 먼저 의심하고 확인함 — **아니다.** 2023년 릴스 3건은 잘 읽힌다.
> **권반장 승인(조건 셋: 그 2건만 · 근거 기록 · 되돌릴 수 있게).**

⚠ **처음엔 첫 50건만 보고 판단할 뻔했습니다.** 릴스가 뒤쪽 쪽에 있었습니다. **끝까지 읽고** 결론을 냈습니다.

## 4. 실행 방법 (모드가 열리면)

`sns_posts` 의 그 **두 행만** 이렇게 바꿉니다:

```
remote_deleted_at = (지금 시각)
remote_checked_at = (지금 시각)
updated_at        = (지금 시각)
```

⚠ **`id = eq.<row id>` 로 «하나씩»** 합니다. `in(...)` 로 뭉뚱그리지 않습니다.
⚠ 조건에 **`remote_deleted_at=is.null`** 을 함께 겁니다 — 이미 표시된 것을 덮지 않기 위해서입니다.

## 5. 🔴 되돌리는 방법

**바꾸기 «전» 값은 둘 다 이렇습니다:**

| row id | `remote_deleted_at` | `remote_checked_at` |
|---|---|---|
| `bc91ef0c-f0a6-431a-9463-c641f69edb9d` | **`null`** | `2026-09-17T00:20:20.659+00:00` |
| `75845510-cffd-4213-a413-854159f3c895` | **`null`** | **`null`** |

⇒ 되돌리려면 **위 값으로 다시 쓰면 됩니다.** (주소·상태 등 다른 칸은 **안 건드렸습니다.**)

## 6. 확인하는 법 (바꾼 뒤)

1. 그 두 행의 `remote_deleted_at` 이 채워졌는지 다시 읽어 확인
2. `/sample-interior` 를 열어 **「인스타에서 보기」가 사라졌는지** 확인
   (손님 화면은 ISR 60초라 **1분 안에** 반영됩니다)

## 7. 왜 못 했나

```
① 칸 이름 확인   ✅
② 두 건 백업     ✅ (2건 · 둘 다 remote_deleted_at=null · 파일로 저장 후 다시 읽어 검증)
③ 표시           🔴 «auto 모드가 DB 쓰기를 거부»
```

⚠ **채팅으로 「해도 된다」고 해서는 안 풀립니다.** **대표님이 앱 화면에서 모드를 바꾸셔야** 합니다.
**우회하지 않았습니다.**
