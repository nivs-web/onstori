## 1. 🔴🔴 만들기 전에 찾은 것 — **그대로 만들었으면 2주 뒤 죽습니다**

녹화 화면 주소는 `onstori.com/rec/{상호}?k=…` 입니다. 이 **`k`(열쇠)** 는
**그 주에만 유효**합니다(`lib/story-link.ts` — 이번 주·지난 주만).

⇒ 홈 화면 아이콘에 그 주소를 그대로 박으면,
**사장님이 2주 뒤에 아이콘을 누르시면 「이 링크는 만료됐어요」만 뜹니다.**

> 대표님 말씀: 「**폰 할 때마다 앱을 보게 될 거고, 자주 영상 찍어 올려줄 거 같다**」
> ⇒ **매일 눈에 띄게 하려던 아이콘이, 매일 실망을 줍니다.** 정반대입니다.

### 그래서 이렇게 풀었습니다

| | |
|---|---|
| 바로가기가 가는 곳 | `/rec/{상호}` — 🔴 **열쇠를 안 박습니다** |
| 열쇠가 없으면 | 그 자리에서 **「이 사람이 주인인가」를 물어봅니다** |
| 주인이면 | **새 열쇠를 즉석에서 찍어** 그대로 열어 드립니다 → **아이콘은 영원히 삽니다** |
| 주인이 아니면 | 예전과 **똑같이** 「이 링크는 만료됐어요」 |

🔴 **문을 넓힌 것이 아닙니다.** 주인 판정은 **이미 쓰던 `loadOwnedSite` 그대로**입니다 —
①로그인 세션이 주인과 같거나 ②브라우저 익명표가 같거나 ③운영자. **새 규칙을 하나도 안 만들었습니다.**

**실측 — 남이 열쇠 없이 들어오면:**

```
첫 줄            : 이 링크는 만료됐어요
녹화가 열렸나    : false
relink 가 준 답  : 403 {"error":"forbidden"}
```

## 2. 만든 화면 — 시키신 버튼 셋 그대로

```
[ 60초 영상 촬영하기 ]
[ 어떻게 찍나요? · 30초면 읽어요 ]
[ 📱 홈 화면에 바로가기 만들기 ]
   홈 화면에 추가해 두고 생각이 나면 바로 찍어요!
```

⚠ **첫 화면에만** 두었습니다. 찍는 도중에 권하면 찍던 것을 놓치십니다.

---

## 3. 🔴 기기마다 다른 안내 — **네 갈래를 전부 눌러 확인했습니다**

| 기기 | 실제로 뜨는 것 (실측) |
|---|---|
| **안드로이드 크롬** | 크롬의 **설치 창이 바로** 뜹니다 — 아래 §4 |
| **아이폰 사파리** | 「아이폰은 두 번만 누르시면 됩니다 ①맨 아래 가운데 **공유 단추** ②**［＋ 홈 화면에 추가］**」 **+ 그 두 모양을 그림으로** |
| **카카오톡 안** | 「지금은 카카오톡 안에서 보고 계세요 … **오른쪽 위 ⋮ → ［다른 브라우저로 열기］** 를 누르신 뒤 한 번만 더」 |
| **자동 설치가 안 될 때** | 「**오른쪽 위 ⋮** 를 누르고 **［홈 화면에 추가］**」 (폰에 따라 ［앱 설치］) |
| **이미 설치됨** | 🔴 **버튼을 아예 숨깁니다** (실측: 숨김 확인 · 녹화는 그대로 됨) |

### ⚠ 제가 가장 신경 쓴 것 — **「눌러도 아무 일이 안 나는 버튼」을 안 만들었습니다**

크롬이 설치 창을 **안 줄 수도** 있습니다. 그때 버튼이 죽으면 사장님은 **우리가 고장 났다**고 느끼십니다.
⇒ 자동 설치가 없으면 **손으로 하는 길이 그대로 펼쳐집니다.** 어느 경우에도 길이 있습니다.

## 4. 🟢 가장 큰 물음표가 풀렸습니다 — **서비스워커 없이도 «한 번에 설치»가 됩니다**

지시 3번이 「**서비스워커는 만들지 마십시오**」였습니다. 그런데 예전 크롬은
**서비스워커가 없으면 설치 이벤트를 안 줬습니다.** 그래서 「한 번에 설치」가 영영 안 뜰 위험이 있었습니다.

**진짜 크롬으로 재 봤습니다:**

```
1번째 방문 — 크롬이 설치 이벤트를 줬나: true | 버튼이 보이나: true
```

⇒ **첫 방문에 바로 줍니다. 서비스워커 없이도 됩니다.** 지시 3번을 그대로 지켰습니다.
⚠ 다만 이것은 **PC 크롬에 안드로이드 탈을 씌워** 잰 것입니다. **진짜 안드로이드 폰에서는 못 재 봤습니다**(§6 ①).

## 5. 함께 만든 것 — **사장님마다 다른 바로가기**

지시 2번: 「🔴 `start_url` 에 그 사장님 주소가 들어가야 합니다. 그냥 `/rec` 로 두면
**아이콘을 눌렀을 때 어느 가게인지 모릅니다.**」

⇒ 주소마다 다른 바로가기 설명서를 내줍니다. **실제로 나오는 내용:**

```json
{"id":"/rec/zz-gate-test-a",
 "name":"테스트 가게 st-a 60초",
 "short_name":"테스트 가게 st-a",
 "start_url":"/rec/zz-gate-test-a?src=home",
 "scope":"/rec/zz-gate-test-a",
 "display":"standalone","orientation":"portrait",
 "theme_color":"#005B2A", …}
```

· **아이콘 밑 글자는 «상호»입니다** — 「온스토리」가 아니라 **사장님 가게 이름**이 박힙니다
· `id` 가 주소마다 달라 **가게가 둘인 사장님은 아이콘도 둘** 두실 수 있습니다
· 🔴 **아이콘은 이미 있는 것을 썼습니다** — 새로 안 만들었습니다(`public/brand/v1/icon/` 의 192·512·maskable-512)
· ⚠ **서비스워커는 안 만들었습니다**(지시 3번)

**실측 — 화면이 자기 것을 제대로 가리키나:**

```
manifest 링크 : /rec/zz-gate-test-a/manifest.webmanifest   ← 전체용이 아니라 «그 가게 것»
나쁜 주소      : 400
```

## 6. 🔴 못 한 것 · 걱정거리

### ① **진짜 안드로이드 폰·아이폰에서는 못 눌러 봤습니다**

전부 **PC 크롬에 폰 탈을 씌워** 잰 것입니다. 특히 이 둘은 **기계가 있어야** 압니다:

- 🔴 **아이폰**: 공유 → [홈 화면에 추가] 를 하면 **아이콘 그림과 이름이 우리가 정한 대로 나오는지**
  (애플은 설명서를 일부만 읽습니다 — `apple-touch-icon` 을 쓰는데 그건 이미 있습니다)
- 🔴 **안드로이드**: 설치한 아이콘을 눌렀을 때 **주소창 없이 «앱처럼»** 열리는지

⇒ `docs/WAITING.md` 에 「**폰으로 한 번 만들어 봐 주십시오**」를 올렸습니다.

### ② ⚠ 첫 화면의 딱지와 **말이 어긋나 보일 수 있습니다**

첫 화면에 **「⤓ 앱 설치 없음」** 이라는 딱지가 있는데, 바로 아래에서 **「홈 화면에 바로가기」** 를 권합니다.
사장님이 「설치하라는 거야 말라는 거야?」 하실 수 있습니다.

🔴 **제가 안 고쳤습니다.** 「**손님이 보는 글은 먼저 여쭙는다**」가 규칙이라서입니다.
**바꾸라고 하시면 한 줄입니다.** 제 제안은 「⤓ **앱 없이 바로**」 정도입니다 —
스토어에서 받는 앱이 없다는 뜻은 지키면서 바로가기와 싸우지 않습니다.

### ③ **바로가기로 들어오시면 «그 가게»에 고정됩니다**

`scope` 를 `/rec/{상호}` 로 잡아서, 아이콘으로 열면 그 가게 녹화 화면만 앱처럼 보입니다.
다른 곳(마이페이지 등)으로 가면 **보통 브라우저로 튀어나옵니다.** 의도한 것이지만,
가게가 여럿인 사장님은 **아이콘도 여러 개** 만드셔야 합니다.

### ④ **얼마나 효과가 있었는지 «세지» 않습니다**

`start_url` 에 `?src=home` 을 붙여 뒀지만, **그 값을 세는 곳은 안 만들었습니다.**
나중에 「바로가기로 들어와 찍은 사장님이 몇 분인지」를 보시려면 그때 붙이면 됩니다.

### ⑤ **가입 전 홈페이지는 «그 폰에서만»** 열립니다

가입 전에 만든 홈페이지는 주인이 **브라우저 안**에 있습니다(서버가 못 읽습니다).
그래서 화면이 한 번 더 물어보는 길을 뒀는데, **폰을 바꾸시면 그 길이 끊깁니다.**
⚠ 그때는 예전처럼 **문자로 새 링크**를 받으셔야 합니다. (가입하신 사장님은 상관없습니다.)
