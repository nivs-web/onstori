# 지시 [18] · 틱톡 — `PULL_FROM_URL` 을 버리고 `FILE_UPLOAD` 로

| | |
|---|---|
| 상태 | **처리함** · 2026-09-17 · 클코 |
| 고친 파일 | `lib/sns/tiktok.ts` **하나** |
| 검사 | `npm run check` **0** · `npx tsc --noEmit` **0** · `npm run build` **0** |
| 🔴 못 한 것 | **틱톡에 실제로 올려 보지는 못했습니다** — §4 를 꼭 읽어 주십시오 |
| 안 건드린 것 | 인스타·유튜브 어댑터. 이 변경은 **틱톡에만** 해당합니다 |

---

## 1. 무엇이 바뀌었나

**전:** 우리가 공개 주소를 주면 **틱톡이 가지러 왔습니다.**
그 주소가 `img.onstori.com` 인데 틱톡에 인증된 것은 `onstori.com` 뿐 → `url_ownership_unverified`.

**후:** **우리가 영상 바이트를 틱톡에 직접 밀어 넣습니다.**

```
① init  → source_info: { source:"FILE_UPLOAD", video_size, chunk_size, total_chunk_count:1 }
        ← publish_id + upload_url
② PUT   → upload_url 에 바이트 그대로 (Content-Type · Content-Range)
③ status → 예전과 똑같이 한 번만 보고 돌려준다
```

⇒ **틱톡이 우리 주소로 오지 않으니 도메인 인증이 «영영» 필요 없습니다.**
저장소를 옮기거나 도메인을 바꿔도 안 깨집니다 — 권반장이 (나)를 고르신 이유 그대로입니다.

⚠ **한 덩이로 보냅니다.** 틱톡 규칙은 「덩이 하나는 5MB 이상 64MB 이하, 5MB 미만이면 통째로」라
60초 영상은 **언제나 한 덩이**입니다. 여러 덩이로 나누는 길은 **만들지 않았습니다** —
만들어도 **시험할 방법이 없고**, 64MB 를 넘는 60초 영상은 나올 수 없습니다.
그 위는 「너무 커요」로 되돌려보냅니다.

---

## 2. 🔴 만들다가 찾은 것 둘 — **둘 다 조용히 실패할 뻔했습니다**

### ① `HEAD` 로 크기를 물으면 **403** 이 옵니다 — 상한 검사가 «죽어» 있었습니다

처음에는 지시대로 「먼저 크기를 재고 너무 크면 읽지도 않는다」로 만들었습니다.
그런데 실제로 돌려 보니:

```
③ HEAD 로 잰 크기: 403  0 바이트     ← 🔴
④ 실제로 받은 바이트: 4,917,100      ← 🔴 HEAD 와 다르다
```

**서명된 주소는 `GET` 에만 유효합니다.** `HEAD` 로 물으면 서명이 안 맞아 403 입니다.
⇒ `declared` 가 늘 `0` 이라 **상한 검사가 한 번도 안 걸렸습니다.** 있는데 없는 검사였습니다.

**고친 법:** `Range: bytes=0-0` 으로 **한 바이트만** 받습니다. 그러면
`Content-Range: bytes 0-0/4917100` 이 와서 **전체 크기를 알려 줍니다.**

```
① 한 바이트로 잰 전체 크기: 206  4,917,100 = 4.69 MB
② 실제로 받은 바이트: 4,917,100  ← 잰 값과 같다 ✅
```

### ② 파일 «이름»은 `.webm` 인데 내용은 **mp4** 입니다

저장소의 영상을 실제로 열어 봤습니다:

```
원본 키 : private/stories/sample-interior/3a476bfc-….webm
파일 머리로 본 진짜 형식 : mp4      ← 🔴 이름과 다르다
```

틱톡은 `Content-Type` 이 **mp4 · quicktime · webm** 중 하나여야 하고, **딱지가 내용과 다르면 거절**합니다.
⇒ 이름(`.webm`)을 보고 딱지를 붙였으면 **mp4 파일에 webm 딱지**를 붙여 보냈을 것입니다.
**파일 머리 64바이트로 진짜 형식을 봅니다**(`lib/media-sniff.ts` — 이미 있던 도구입니다).

⚠ 이건 2026-09-12 에 이 저장소가 이미 겪고 적어 둔 일입니다 —
「저장된 녹화 12건이 전부 `.webm` 이름인데 내용은 진짜 mp4」. **같은 함정을 두 번 밟지 않았습니다.**

### ③ 덤 — **같은 영상이 두 번 올라갈 수 있는 구멍**을 막았습니다

바이트를 다 보내고 접수 번호까지 받은 뒤, **상태 확인에서 인터넷이 잠깐 끊기면**
옛 코드는 「실패」로 끝내고 **접수 번호를 버렸습니다.** 사장님이 다시 누르면 처음부터 다시 →
**같은 영상이 사장님 틱톡에 두 번 올라갑니다.**

⇒ 「잠깐 그런 것(TRANSIENT)」일 때는 **「아직 진행 중」으로 돌려 번호를 지킵니다.**
   연결이 풀린 것·틱톡이 거절한 것은 다시 눌러도 소용없으니 그대로 실패입니다.
   (접수 번호를 `try` **밖**으로 옮겼습니다 — 안에 있으면 오류 처리기가 그 번호를 못 봅니다.)

## 3. 권반장 걱정에 대한 답 — 「메모리에 통째로 올리지 마십시오」

**지키지 못했습니다. 이유를 적습니다.**

틱톡은 ①`init` 에 **`video_size` 를 먼저** 요구하고 ②PUT 에 **정확한 `Content-Length`·`Content-Range`**
를 요구합니다(세 헤더 전부 필수). 흘려보내면서 그 값을 정확히 맞추는 길이 이 런타임에는 없습니다 —
`lib/sns/youtube.ts` 가 이미 적어 둔 것처럼 **「`Content-Length` 는 fetch 가 조용히 무시하는 헤더」**이고,
「넣고서 넣었다고 믿는 것」이 제일 위험합니다.

**⇒ 대신 «크기로» 막았습니다.** 64MB 를 넘으면 **읽지도 않고** 되돌려보냅니다.
60초 영상은 보통 5~15MB 라(실측 4.69MB) 실제로 걸릴 일이 거의 없습니다.
⚠ 유튜브 어댑터도 **똑같이 통째로 읽습니다.** 두 곳이 같은 방식이라 나중에 바꿀 때도 한 번에 봅니다.

---

## 4. 🔴🔴 못 한 것 — **틱톡에 실제로 올려 보지 못했습니다**

**이것이 이 보고서에서 가장 중요한 줄입니다.**

| 무엇 | 확인했나 |
|---|---|
| 저장소에서 파일을 읽어 오는 것 | ✅ **실측** (4.69MB · 크기·형식까지) |
| 크기 재기 · 형식 판별 · `Content-Range` 문자열 | ✅ **실측** |
| 타입 검사 · 검사 260여 건 · 빌드 | ✅ 셋 다 0 |
| 🔴 **틱톡 `init` 이 `FILE_UPLOAD` 를 받아 주는지** | ❌ **못 해 봤습니다** |
| 🔴 **`upload_url` 에 PUT 이 통하는지** | ❌ **못 해 봤습니다** |

**왜 못 했나:** 틱톡에 올리는 것은 **사장님 계정에 진짜로 게시**하는 일입니다.
시험이라도 한 번 성공하면 **실제 영상이 올라갑니다.** 지시함의 「시킬 수 없는 것」에 걸립니다.
(「나만 보기」로 올리는 길이 있습니다만, 그것도 **실제 게시**입니다. 제가 혼자 정할 일이 아닙니다.)

🔴 **그래서 다음 한 걸음은 사람 손입니다:**
> 대표님이 **틱톡에 한 번만 더 올려 봐 주십시오.** 이번에는 `url_ownership_unverified` 가
> **안 나와야 정상**입니다. 다른 오류가 나오면 그 화면의 [자세한 이유 보기]를 그대로 주십시오 —
> 필드 이름 하나 차이일 가능성이 큽니다.

⚠ 그리고 권반장이 부반장에게 시키신 **(가) 도메인 인증도 그대로 해 두시는 편이 좋습니다.**
   제 (나)가 첫 시도에 안 통하면 **(가)가 바로 구해 줍니다.** 둘은 서로를 막지 않습니다.

---

## 5. 그 밖에

1. **인스타는 그대로 `PULL_FROM_URL` 입니다.** 인스타는 도메인 인증을 요구하지 않습니다 —
   건드릴 이유가 없어 **한 글자도 안 건드렸습니다.**
2. **옛 경고 주석을 지우지 않고 남겼습니다.** 「`PULL_FROM_URL` 은 인증된 도메인만 받는다」는
   그 경고가 **맞았는데 우리가 놓친 것**이라, 지우면 「왜 바꿨는지」가 사라집니다.
3. **틱톡의 심사 요건 셋은 그대로입니다** — `creator_info` 먼저 부르기 · 매번 사장님이 공개범위 고르기 ·
   올리기 직전 토큰 갱신. 한 글자도 안 건드렸습니다.
4. **배포는 안 했습니다.** `main` 커밋까지입니다.
