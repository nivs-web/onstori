## ⓪ 「여러 편을 걸었는데 한 편만 나온다」 — **원인이 짐작과 달랐습니다**

### 권반장님 진단

> 「`app/api/site/video/manage/route.ts:31` 의 action 이 `rename`·`move`·`delete`·`detach`
> 넷뿐입니다 — **「걸기(attach)」가 없습니다.**」

### 🔴 재 보니 — **거는 길은 «있었고», 실제로 일곱 편이 걸려 있었습니다**

거는 자리는 `manage` 가 아니라 **`app/api/site/video/route.ts`** 입니다(`video_out_key` 를 채웁니다).
DB 를 직접 세어 봤습니다:

```
sample-interior — 전체 17건 · 영상파일 있는 것 17 · 🔴 걸린 것 8 · 그중 안 지워진 것 7
```

**일곱 편이 멀쩡히 걸려 있는데 손님 화면에는 한 편만 나왔습니다.**

### 🔴🔴 진짜 범인 — **RLS 정책 한 줄**

```sql
create policy "stories_public_read" on story_entries for select
  using (visible and exists (...));     -- ← 「visible = true」 를 요구한다
```

그런데 **영상은 일부러 `visible` 을 안 켭니다.** 켜면 이야기 피드에 **내용이 텅 빈 항목**이 뜨고
완성도 점수가 저절로 올라가기 때문입니다(그 판단 자체는 옳습니다).

⇒ **걸린 영상은 전부 `visible = false` 라, 손님 권한으로는 «한 줄도» 안 읽힙니다.**

**실측 — 같은 사이트, 열쇠만 바꿔서:**

```
① 손님(anon) 이 story_entries 를 몇 줄 읽나 : 0
② 그중 «걸린 영상» 은 몇 줄               : 0
④ loadShorts(손님 열쇠)                   : 0 편
   loadShorts(운영자 열쇠)                : 7 편
🔴 걸렸는데 visible=false : 8건  ← RLS 가 손님에게 숨긴다
```

★ **불변 규칙 12 위반이었습니다** — 「걸렸다」를 판정하는 값(`video_out_key`)과
**읽을 수 있는 조건**(`visible`)이 **달랐습니다.** 사장님은 걸었다고 보고, 손님은 못 봅니다.
⚠ 운영자 미리보기(`/x/{상호}`)는 운영자 열쇠를 써서 **거기서는 일곱 편이 다 보였습니다.**
   그래서 더 늦게 발견됐습니다.

### 고친 방법 — **문을 넓히지 않았습니다**

| | |
|---|---|
| **「이 홈페이지를 보여도 되는가」** | 🔴 **여전히 손님 권한(RLS)이 정합니다.** `sites` 조회는 그대로 손님 열쇠입니다 — 만료·정지된 곳은 **거기서 이미 걸러집니다** |
| 그 문을 통과한 뒤 | 딸린 자료(영상·이야기)만 **운영자 열쇠**로 읽습니다 |
| 이야기 글 | **`visible = true` 를 코드로 그대로 겁니다** — RLS 가 하던 일과 **한 글자도 다르지 않습니다** |
| 영상 | 판정은 `video_out_key` 하나 — 그래야 **「걸었다」와 「보인다」가 같아집니다** |

### 실측 — 고치기 전 / 후

```
고치기 전 : /sample-interior 의 <video> 태그 수 = 1
고친 뒤   : /sample-interior 의 <video> 태그 수 = 7   ✅
            「N편 · 옆으로 넘겨 보세요. 소리는 영상을 누르면 켜집니다.」 문구도 나옴
```

**안 새는지도 확인했습니다:**

```
정지된 사이트(zz-gate-test-a) : 「…홈페이지는 지금은 볼 수 없어요」 · 영상 0편  ✅
숨긴 이야기 글                : 화면에 0건 (visible=true 인 글이 0건이라 정확)   ✅
```

### ⚠ 더 깨끗한 길이 있는데 **제가 못 합니다**

원래는 **DB 정책 한 줄**을 고치는 편이 낫습니다:

```sql
using ((visible or video_out_key is not null) and exists (...))
```

🔴 **DB 를 바꾸는 것은 「권반장이 시킬 수 없는 것」**이라 손대지 않았습니다.
**대표님이 허락하시면** 마이그레이션 한 장으로 더 깔끔해집니다. 지금 방식도 결과는 같습니다.
