## ⓪ 「여러 편을 걸었는데 한 편만 나온다」 — **원인이 짐작과 달랐습니다**

### 권반장님 진단

> 「`manage/route.ts` 의 action 이 넷뿐입니다 — **「걸기(attach)」가 없습니다.**」

### 🔴 재 보니 — 거는 길은 «있었고», **일곱 편이 걸려 있었습니다**

거는 자리는 `manage` 가 아니라 **`app/api/site/video/route.ts`** 입니다.

```
sample-interior — 전체 17건 · 영상파일 17 · 🔴 걸린 것 8 · 그중 안 지워진 것 7
```

### 🔴🔴 진짜 범인 — **RLS 정책 한 줄**

```sql
create policy "stories_public_read" on story_entries for select
  using (visible and exists (...));     -- ← 「visible = true」 를 요구한다
```

그런데 **영상은 일부러 `visible` 을 안 켭니다**(켜면 이야기 피드에 **내용이 텅 빈 항목**이 뜨고
완성도 점수가 저절로 올라갑니다 — 그 판단 자체는 옳습니다).

⇒ **걸린 영상은 전부 `visible = false` 라, 손님 권한으로는 «한 줄도» 안 읽힙니다.**

```
① 손님(anon) 이 story_entries 를 몇 줄 읽나 : 0
④ loadShorts(손님 열쇠)                    : 0 편
   loadShorts(운영자 열쇠)                 : 7 편
🔴 걸렸는데 visible=false : 8건
```

★ **불변 규칙 12 위반이었습니다** — 「걸렸다」를 판정하는 값(`video_out_key`)과
**읽을 수 있는 조건**(`visible`)이 **달랐습니다.**
⚠ 운영자 미리보기(`/x/{상호}`)는 운영자 열쇠라 **거기서는 일곱 편이 다 보였습니다.** 그래서 늦게 드러났습니다.

### 고친 방법 — **문을 넓히지 않았습니다**

| | |
|---|---|
| **「이 홈페이지를 보여도 되는가」** | 🔴 **여전히 손님 권한(RLS)이 정합니다.** 만료·정지는 거기서 걸러집니다 |
| 그 문을 통과한 뒤 | 딸린 자료만 **운영자 열쇠**로 읽습니다 |
| 이야기 글 | **`visible = true` 를 코드로 그대로** 겁니다 — RLS 와 한 글자도 다르지 않습니다 |

```
고치기 전 : /sample-interior 의 <video> 태그 = 1
고친 뒤   : /sample-interior 의 <video> 태그 = 7   ✅
정지된 사이트 : 「지금은 볼 수 없어요」 · 영상 0편 ✅ (안 샙니다)
```

⚠ **더 깨끗한 길은 DB 정책 한 줄**입니다 — `using ((visible or video_out_key is not null) and ...)`.
🔴 **DB 변경은 「권반장이 시킬 수 없는 것」**이라 손대지 않았습니다. **대표님 승인 사항**입니다.

## ① 숏폼 무대 — **화면이 다 까맣게 변합니다**

> 「히어로 섹션 아래로 내려가면 **화면이 다 까맣게 변하면서**, 스크롤을 히어로의 **2배 이상**
> 내리지 않으면 그 섹션에 머물게 못할까? … **모바일에선 틱톡·쇼츠·릴스처럼.**」

### 「가두는」 느낌의 정체 — **CSS 두 줄입니다. JS 가 스크롤을 «훔치지» 않습니다**

```
바깥 높이 = (편수 + 1) × 화면 한 개    →  그만큼 굴려야 이 구역을 벗어난다
안쪽은 화면에 «붙는다»(sticky)         →  굴리는 동안 화면에 머문다
```

⇒ 일곱 편이면 **8화면**입니다. 「히어로의 2배 이상」이 **저절로** 됩니다.
🔴 **스크롤 잭킹(JS 로 스크롤 가로채기)은 안 했습니다.** `docs/MOTION.md` 금지 목록이고,
무엇보다 **뒤로 가기·검색·스크롤바가 전부 망가집니다.** 스크롤은 손님 것입니다.

### 🔴 시키신 「반드시 지킬 것」 여섯 — 전부 실측했습니다

| # | 지시 | 실측 |
|---|---|---|
| 1 | **［건너뛰기 ↓］ 항상** | ✅ 누르니 **무대 밖으로 나감**(무대밖인가: true) |
| 2 | **음소거로 시작** | ✅ 전부 음소거 · 버튼 🔇 · 누르면 소리 |
| 3 | **움직임 줄이기 존중** | ✅ `static` · **7편이 목록으로** · **자동재생 안 함** · **재생바 줌** |
| 4 | **0편이면 섹션 자체를 없애라** | ✅ 부르는 쪽에서 막습니다 |
| 5 | **영상 없는 사이트에 JS 안 보냄** | ✅ `"use client"` 를 이 파일에만 둡니다 |
| 6 | **PC 에서도 9:16** | ✅ **506×900 = 0.563** (9/16 = 0.563) |

### 굴리기·스와이프 실측

```
굴리면 : 1/7 → 2/7 → 3/7 → 4/7 → 6/7
세로 스와이프 : 위로 쓸면 2/7 · 아래로 쓸면 1/7
살짝 흔들면(천천히 20px) : 1/7 그대로 — 안 넘어감 ✅
```

### 🔴 눌러 보고 잡은 것 셋 — **안 눌렀으면 다 나갔습니다**

| 무엇이 | 왜 |
|---|---|
| **편이 영원히 `1 / 7`** | 눈금을 지켜보는 «띠»의 **높이가 0** 이라 겹치는 넓이가 0 → 브라우저가 「안 겹쳤다」로 봤습니다. 띠에 두께를 주고 **직접 재서** 고르게 했습니다 |
| **［건너뛰기 ↓］가 안 보임** | 아래 **「문의하기」 고정바에 완전히 가려** 있었습니다. **탈출구가 안 보이면 「항상 띄운다」가 거짓말**입니다. 바 위로 올렸습니다 |
| **검은 화면 위 «흰 띠» 한 줄** | 위 상호 바가 `fixed` 라 무대 위에 떴습니다 — 「다 까맣게」가 깨졌습니다. 무대가 화면을 덮는 동안만 바를 까맣게 합니다 |

★ 마지막 것은 **`site-chrome.tsx` 를 한 줄도 안 건드리고** 했습니다 —
그 파일은 손님 사이트 **전부**가 쓰는 뼈대라, 무대 하나 때문에 조건을 심으면 다른 화면이 같이 흔들립니다.

### 같은 영상을 두 번 그리지 않습니다

무대가 서면 아래 「사장님 이야기」 영상 섹션은 **비킵니다**(실측: 페이지 전체 `<video>` **7개**).
⚠ 차림표의 「사장님 이야기」(`#video`)가 가리키던 자리를 **무대가 이어받았습니다** —
실측으로 **눌렀더니 무대로 갑니다**(불변 규칙 12).
★ **섹션 스키마를 늘리지 않았습니다**(불변 규칙 2) — 진실은 이미 DB 에 있습니다.

## ③ 디자인 개편 — **무엇을 왜 바꿨는지**

🔴 **손님이 보는 «글»은 한 글자도 안 바꿨습니다.** 「손님 글은 먼저 여쭙는다」 규칙 때문입니다.
바꾼 것은 **여백·배경·전환** 셋뿐입니다.

### ⓐ 🔴 「평범한 회사 홈페이지」로 보이던 가장 큰 이유 — **같은 바탕이 넷씩 이어졌습니다**

실측(고치기 전):

```
소개(흰) → 진행 과정(흰) → 시공 갤러리(흰) → 견적 문의(연) → 오시는 길(흰)
```

`docs/DESIGN.md` §7 이 못 박아 둔 「**같은 배경 연속 금지 — 경계가 사라져 한 덩어리로 보인다**」에
정면으로 어긋났습니다. **그 규칙이 고객 사이트에는 적용된 적이 없었습니다.**

고친 뒤:

```
무대(검정) → 소개(연) → 진행 과정(흰) → 시공 갤러리(연) → 견적 문의(연·가는 선) → 오시는 길(흰)
```

- 앞 칸과 **반드시 다른** 색을 고릅니다
- 다음 칸이 자기 색을 가졌고 겹치면 **뒤집어** 봅니다
- 앞뒤가 다 막히면 색은 같아도 **가는 선 한 줄**로 경계를 만듭니다(실제로 견적 문의 앞에서 그렇게 됐습니다)

🔴 **새 색을 하나도 안 만들었습니다.** 사장님 팔레트의 `--s-bg`·`--s-soft`·`--s-line` 셋뿐입니다.

### ⓑ 🔴 PC 에서 **폰과 똑같은 여백**을 쓰고 있었습니다

```
고치기 전 — 폰 64/20 · PC 64/20   ← 1440px 에서도 폰 여백
고친 뒤   — 폰 64/20 · PC 120/32  ← DESIGN.md §7 이 원래 정한 값
```

큰 화면에서 글이 가장자리에 붙고 섹션이 다닥다닥 붙어 **「폰 화면을 늘려 놓은 것」**처럼 보였습니다.
★ **새 값을 만든 게 아닙니다** — `--section-y-lg`·`--gutter-lg` 는 원래 있던 토큰인데
고객 사이트가 **안 쓰고** 있었습니다.
⚠ **본사 화면(랜딩·에디터·어드민)은 한 픽셀도 안 바뀝니다** — 실측으로 확인했습니다
(`.section` 여백 120px 그대로 · 본사에 `site-shell` 없음).

### ⓒ 「검게 들어갔다 다시 밝게 나온다」

| | 어떻게 |
|---|---|
| **들어갈 때** | 히어로의 **마지막 한 뼘이 검게 잠깁니다** |
| **나올 때** | 검정이 **다음 섹션 색으로 풀립니다**(150px) |

⚠ 처음에는 `box-shadow` 로 흉내 냈는데 경계에 **회색 얼룩**만 생겼습니다. 진짜 그라데이션으로 바꿨습니다.
⚠ 감싸개 배경을 `background`(줄임 표기)로 줬더니 **그것이 그라데이션까지 지웠습니다** —
`background-color` 로 바꿔 고쳤습니다. **실측으로 잡았습니다.**

### ⓓ 문서에 반영했습니다

`docs/DESIGN.md` 에 **§10 「고객 사이트 뼈대 규칙」**을 새로 썼습니다.
전에는 「고객 사이트는 **별개**다」 한 줄뿐이라 **여백·띠·전환에 규칙이 아예 없었습니다.**
그것이 이번 문제의 뿌리입니다.

## 🔴 못 한 것 · 걱정거리

### ① **진짜 폰에서는 못 만져 봤습니다**

전부 **PC 크롬에 폰 탈을 씌워** 잰 것입니다. 특히 이 셋은 **기계가 있어야** 압니다:

- 🔴 **아이폰 사파리**에서 `100svh` + `sticky` 가 주소창이 접힐 때 **덜컥거리지 않는지**
- 🔴 **영상 일곱 편이 든 무대를 실제 데이터로 굴릴 때** 폰이 뜨겁거나 끊기지 않는지
- 🔴 손가락으로 **빠르게 튕겼을 때**(플링) 두세 편이 한 번에 넘어가지 않는지

⇒ `docs/WAITING.md` 에 올렸습니다.

### ② **디자인 개편은 «여백·배경·전환»까지입니다**

권반장님이 적으신 「**카드 그림자·버튼**을 다시 잡으십시오」는 **안 했습니다.**
- 고객 사이트 카드는 지금 **테두리 + 은은한 면**으로만 구분합니다. 그림자를 넣을지는
  **정해진 바가 없고**, 잘못 넣으면 여덟 팔레트 중 어두운 쪽에서 지저분해집니다.
- 버튼 모양을 바꾸면 **［문의하기］의 생김새가 바뀝니다** — 그건 손님이 누르는 자리라
  **대표님 눈으로 한 번 보시는 게 맞다**고 봤습니다.
⇒ `DESIGN.md` §10-5 에 「아직 안 한 것」으로 적어 두었습니다.

### ③ **글자 크기는 PC 에서도 17px 그대로**입니다

큰 화면에서 조금 작아 보일 수 있습니다. 다만 **글자 크기는 읽는 경험을 직접 바꾸는 것**이라
여백처럼 조용히 바꾸지 않았습니다. 키울지 말씀해 주십시오.

### ④ 원래 있던 잔소리 2건은 **안 고쳤습니다**

`components/sections/shorts-feed.tsx:87` · `app/[slug]/edit/videos-panel.tsx:199`.
**제 변경 전부터 있던 것**이고(따로 확인했습니다), 지시 범위 밖이라 그대로 뒀습니다.
**이번에 새로 만든 파일은 잔소리 0건**입니다.

### ⑤ **`?src=home` 을 세지 않습니다**

무대에 들어온 손님이 몇 편까지 보고 나갔는지 **재지 않습니다.** 재려면 따로 붙여야 합니다.
