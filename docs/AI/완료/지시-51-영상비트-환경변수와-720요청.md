# [51] 영상 용량 — 「720 도화지에 1080 물감」을 걷었다 · 처리함 · 2026-09-18

지시: `반장-지시.md` [51] (근거: `handoff/2026-09-18-영상압축/01·02·03`)
🔴 **기본값은 «바꾸지 않았다».** 화질은 대표님이 폰으로 보시고 정하신다 — 이 지시는 **고를 수 있게 만드는 것**까지다.

## ① 무엇을 했나 — 셋

### ① 영상 초당 비트를 `config/recording.ts` 로 옮기고 **환경변수로 고를 수 있게** 했다

```
NEXT_PUBLIC_RECORDING_VIDEO_BPS   (비어 있으면 6,000,000 — 지금 값 그대로)
```

| 준 값 | 결과 | 확인 |
|---|---|---|
| (없음) | **6,000,000** | ✅ 실제로 돌려 확인 |
| `abc` | 6,000,000 | ✅ 조용히 기본값 |
| `99999999`(20M 초과) | 6,000,000 | ✅ 조용히 기본값 |
| `1500000` | **1,500,000** | ✅ 그대로 적용 |

⚠ 오타 하나로 녹화가 죽으면 안 되므로 **0.3M~20M 밖은 받지 않고 조용히 기본값**으로 간다.

### ② 카메라에 **처음부터 720×1280 을** 요청한다

```
전 : 카메라에 1080×1920 을 요청 → 캔버스가 720 으로 줄여서 녹화   ← 큰 그림을 열고 버렸다
후 : `RELAY_W`·`RELAY_H`(720×1280)를 «그대로» 요청                ← 숫자는 recording.ts 한 곳
```

### ③ 카메라가 **실제로 준 값**을 녹화 시작 로그에 남긴다

```json
{"evt":"rec_start","요청":"720x1280@30","카메라":"720x1280@30","캔버스중계":true,"비트":6000000}
```

⚠ 9/12~16 에 `2052×1154` 로 찍힌 적이 있는데 **왜 그랬는지 아직 아무도 모른다.**
  다시 나오면 **그 자리에서 보이게** 해 두는 것이 목적이다.

## ② 왜 이것이 「1/3~1/5」의 첫걸음인가 — 숫자를 날짜순으로 세우면 보인다

| 언제 | 화면 크기 | 영상 비트 | 60초 환산 |
|---|---|---|---|
| 9/10~11 | 720×1280 | 2.1~2.5Mbps | 15.6~21.0MB |
| 9/12~16 | 2052×1154(가로로 찍히던 때) | 6.0~7.45Mbps | 43.8~54.1MB |
| 🔴 9/17~(지금) | **720×1280** | **5.86Mbps** | **42.7MB** |

**화면이 2.6배 작아졌는데 파일은 그대로다.** [16] 이 크기는 고쳤는데 **비트가 1080 시절 값**이었다.

## ③ 무엇을 «못» 했나 — 반드시 읽어라

1. 🔴 **실제 폰으로 한 번도 안 찍어 봤다.** `/rec/{상호}` 는 **문자 서명 링크**로만 들어가는 곳이라
   제가 열 수 없다. ⇒ **①의 로그도, ②가 진짜 720 으로 열리는지도 «대표님 폰에서» 확인해야 한다.**
2. **비트를 낮췄을 때 몇 MB 가 되는지는 «계산값»이다.** 실제로 찍어 재야 확정된다.
   그래서 ①(고를 수 있게)이 먼저였다.
3. 🔴 **`videoBitsPerSecond` 는 «상한»이 아니라 «부탁»이다**(W3C 규격 "might be surpassed").
   실측으로 요청 6.0 → 7.45Mbps, 안드로이드는 +37% 까지 간다.
   ⇒ **낮춰도 그대로는 안 나온다.** 믿을 수 있는 손잡이는 **해상도**다.
4. **[52](틱톡 헛사본)은 손대지 않았다** — 「빼기 전에 실제 틱톡 발행 1회로 확인하라」는 조건이 붙어 있다.

## ④ 하지 않은 것 (지시서의 「하지 마십시오」 셋 그대로)

- 기본값을 1,500,000 으로 바꾸기 ❌
- HEVC·AV1 로 바꾸기 ❌ (윈도우 엣지·일부 크롬에서 손님이 재생을 못 한다)
- 브라우저 안에서 다시 인코딩 ❌ (폰에서 60초 영상에 2분 30초)

## ⑦ 대표님이 하실 것

1. **폰으로 한 번 찍어 주십시오** — 그러면 `rec_start` 로그로 **카메라가 실제로 준 크기**를 압니다.
2. 화질을 비교하시려면 Vercel → Settings → Environment Variables 에
   `NEXT_PUBLIC_RECORDING_VIDEO_BPS` 를 `3000000` → `1500000` 순으로 넣고 **Redeploy** 하신 뒤
   같은 자리에서 한 편씩 찍어 비교해 주십시오. **아니다 싶으면 값을 지우면 지금으로 돌아옵니다.**
